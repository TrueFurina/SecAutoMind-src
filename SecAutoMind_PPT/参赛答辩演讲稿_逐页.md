## 页 3｜项目背景与痛点（0:50–1:40）

**【口播稿】**
为什么做这件事？从政策层面看，国务院《关于深入实施"人工智能+"行动的意见》明确提出，要推动 AI 从"感知理解"向"自主决策"跃迁——这正是赛题的发令枪。

但在真实的安全运营中，我们遇到了**三个绕不开的痛点**：
第一，**告警洪峰与攻击路径复杂**——传统单一 AI 只能做分析，无法完成"分析—决策—执行"的闭环，安全运营难以真正落地；
第二，**安全工具割裂**——Nmap 在命令行、Burp 在图形界面、脚本各写各的，Agent 想把工具编排起来，却面对一座座孤岛；
第三，**自主操作风险难管控**——危险操作缺少审批与审计，谁也不敢把关键动作真正交给 AI，自主执行的信任问题无法解决。

这三点，决定了我们要做的不是"会聊天的 AI"，而是一个**能干活、敢放权、可追溯**的安全智能体。

## 页 4｜解决方案概述（1:40–2:40）

**【口播稿】**
针对痛点，我们的解决思路是——**用"规划、执行、审计、复盘"四类 Agent 协同，通过共享事实黑板，构建一个可离线运行的自主决策平台**。

具体来看：**规划层**负责把自然语言任务拆解成可执行行动计划；**执行层**调度九十余个 YAML 工具逐个完成子任务；**审计层**复核每一步结果、把经验复盘沉淀为知识。三层闭环之外，还有三个工程化承诺：
一是**全链路覆盖**——渗透、应急、Web、逆向等十三类攻防场景，统一调度 90 工具与 18 个角色化智能体协同对抗；
二是**可控可审计**——危险操作先经过人工审批（HITL）再执行，审计智能体复核偏差，全程留证可回放；
三是**离线可跑、全程可验证**——双击即用、首启向导设密码、三端 CI 发布、多模型零配置，演示现场不翻车、结果可复现。

底座是 Go 原生编译加本地数据库，前端资源全部内嵌——**一个文件，就是一个完整的安全作战平台**。

**【提示】**
- 本页是"总方案"，语速中等，重点讲清四类 Agent 的分工闭环
- "一个文件就是一个平台"是金句，配合指向"工程底座"区域

## 页 5｜四大核心功能（2:40–3:40）

**【口播稿】**
方案落地为四大核心功能：

**第一，自主决策编排。** 规划智能体拆解目标、生成计划、自动选型编排模式；执行智能体调用工具、完成子任务、动态校验——从一句自然语言到一串真实动作，全程无需人工逐步干预。

**第二，通用工具对抗。** 平台内置九十余个 YAML 工具配方，覆盖信息收集、渗透利用、Web 安全、应急响应等十三类场景。最关键的是——**新增一个工具，只需要新增一个 YAML 文件，无需改一行代码**。这是可持续进化的架构。

**第三，人机协同审计。** 命令执行、提权、数据删除、外联等敏感操作，一律先进入人工审批队列再执行；审计智能体复核偏差；配合 RBAC 多角色隔离，审计员写操作会被系统直接拒绝——实测返回 403。

**第四，离线可运行。** 数据全在本地，前端资源内嵌于二进制、无任何外部依赖；Windows 双击即用，Linux、macOS 单文件运行——一台学生笔记本，就是一个完整的演示环境。

**【口播稿】**
为了让这些能力"模块可换、层级可解、全程可审"，我们做了**五层解耦**的架构设计：

最上层是**交互控制台层**——仪表盘、对话、资产、漏洞、工作流、C2、审计回放，全部支持多用户 RBAC 权限隔离；

五层之间通过**事实黑板与审计总线**通信，做到：上层可解释、下层可替换、全链可审计。

## 页 7｜AI Agent 技术实现（4:25–5:25）

**【口播稿】**
智能体的智能，来自三个关键机制：

**第一，共享事实黑板。** 规划、执行、审计、复盘四类 Agent 不直接对话，而是统一读写"事实黑板"——上下文不丢失、多步决策可追溯、可回放。这解决了多 Agent 协作中最常见的"各说各话、记忆丢失"问题。

**第二，YAML 工具配方 + Schema 自动生成参数。** Agent 不需要知道底层命令细节——它按工具的 Schema 自动生成调用参数，工具层完成真实执行。九十多个工具的接入因此统一、规范、可扩展。

**第三，MCP 统一接入。** 注入型与独立型工具全部经 MCP 协议接入，架构上天然支持外部工具生态。

再看三个核心 Agent 的分工：
**规划 Agent**——计划生成 + 编排选型，把大任务切成有依赖关系的可执行步骤；
**执行 Agent**——工具调用 + 动态校验，每步执行都实时校验，一旦发现偏差，立即触发审计事件并重试；
**审计 Agent**——结果复核 + 知识沉淀，把成功经验与失败教训复盘入库，下次任务直接复用。

整个决策过程，全部留痕在审计日志里——**决策路径可追踪，每一步都有据可查**。

**【提示】**
- 本页信息密度最高，口播要挑"事实黑板 + 三个 Agent 分工"主线，YAML/MCP 点到即可
- "每一步都有据可查"呼应"可解释性"评分维度（页 10）

## 页 8｜系统演示（一）：首启向导 · 自主决策 · HITL 审批（5:25–6:25）

**【口播稿】**
空口无凭，直接看真机演示——这也是我们产品的第一次打开。

**第一步，首启向导。** 在全新的空目录里双击这个程序文件：没有命令行黑窗，浏览器自动打开。首次使用进入初始化向导——平台已经为管理员生成了一次性初始密码，我们复制过来，设置管理员自己的专属密码，即可进入控制台。这个设计回答了安全产品最基本的信任问题：**身份从第一秒就建立，初始密码一次性作废**。

**第二步，自主决策。** 我在对话里给它一个自然语言任务。看——规划智能体自主拆解任务、生成行动计划，执行智能体依次调度工具完成：扫描、识别、分析，全程无需我逐步操作。

**第三步，人机协同审批。** 当智能体准备执行命令执行、提权这类敏感操作时，审批请求出现了——带倒计时、必须由我确认。这里我点击批准，它继续执行；如果点击拒绝，它会调整策略。**AI 自主决策，但人类永远在关键节点上握着方向盘。**

整个过程的每一步，都在审计日志里留痕，可按操作者、时间、类别筛选回放。

# SecAutoMind MCP 工具分级注册方案（52 内置 + 90 YAML = 142 运行时）

> 2026-10-19 · 依据 REA 调研教训（全量注册 139 工具 → 上下文 5,000→11,000 tokens、消耗 ×2.5）制定
> 数字唯一真值源：`scripts/count_stats.py --json`（本次实测 HEAD=6567eab：tools_yaml=90, builtin_tools=52, runtime_tools=142）
> ⚠️ 口径漂移已发现：AGENTS.md 记「91 YAML + 52 内置 = 143」，count_stats 实测 90+52=142。以 count_stats 为准，AGENTS.md 待同步（见 §5）。

## 1. 问题定义

当前运行时向 agent 暴露 **142 个工具**（52 内置 Go 工具 + 90 个 tools/*.yaml 外部工具）。agent 每次会话的工具清单（名称+描述+参数 schema）全额进入上下文，造成：

1. **token 浪费**：REA 实测全量注册使上下文膨胀 2.2 倍；142 个工具的 schema 量级已超过该阈值
2. **选择抖动**：功能重叠工具（如 webshell_file_list vs manage_webshell_list）同时在场时，模型选错概率上升
3. **高危工具裸奔**：`webshell_exec`、`c2_payload`、`manage_webshell_delete` 等破坏性工具与只读查询同级暴露

## 2. 分级模型（T0/T1/T2）

| 层级 | 注册策略 | 选择判据 | 数量（本次盘点） |
|---|---|---|---|
| **T0 核心常驻** | 每次会话必注册 | ① 跨任务阶段通用 ② 只读或低风险 ③ 任务主干路径（记录-查询-检索） | ~22 |
| **T1 场景级** | 按 agent 角色/任务阶段注入 | ① 特定阶段才用（建站、扫描、利用）② 中风险 | ~45 |
| **T2 按需/高危** | 显式授权后才注册 | ① 破坏性/不可逆（delete/deprecate/exec）② 低频专家操作 | ~30 |

其余（90 YAML 外部工具）按同一判据归级，与内置工具共用一张注册表。

## 3. 落地机制（三步，不动现有注册逻辑）

1. **注册表层**：在 MCP server 初始化处增加 tier 过滤参数（`--tool-tier T0` / `T0,T1` / `all`），默认 `T0`；`GetAllBuiltinTools()` 旁增加 `GetBuiltinToolsByTier(tier)`（constants.go 同文件新增，纯增量）。
2. **遥测采集**：tool_call 日志落 `logs/`（工具名+阶段+耗时+成败），当前**无调用遥测**（2026-10-19 实测 logs/ 无 tool_call 记录）——分级初版基于任务阶段推导，遥测上线 2 周后用真实频率校准分级。
3. **prompt 侧声明**：agent system prompt 中明示当前可用工具集与「需要更多工具时显式申请」的升级路径，避免模型幻觉调用未注册工具。

## 7. 附录 A：Tier 迁移判据（2026-10-20 补，REA #11）

分级不是一次性的静态表。没有迁移判据，T0 只增不减，两年后又回到"全量驻留"。
**升降级只看行为，不看感觉**：

| 方向 | 判据（全部满足才可动） | 数据来源 | 最短观察期 |
|---|---|---|---|
| T1 → T0 | ① 出现在 ≥30% 的会话中；② 日均调用 ≥20 次；③ 无写库/网络副作用 或 副作用已由用户显式触发 | tool_call 遥测 | 连续 14 天 |
| T0 → T1 | ① 出现在 <5% 的会话中；② 可被其它 T0 工具组合替代（写明替代路径） | tool_call 遥测 | 连续 14 天 |
| T1 → T2 | ① 调用率 <1%；② 属破坏性/高权限操作（执行、写文件、连接管理） | tool_call 遥测 + 权限矩阵 | 连续 30 天 |
| T2 → T1 | ① 有 ≥3 个真实案例证明"必须频繁申请"；② 权限收窄方案已就位 | 工单/会话记录 | — |

**硬约束**：迁移必须成对提交（`constants.go` 的分级表 + 本文件表格 + 对应 schema 抽样），
单独改一处视为未完成——分级表与文档不一致时，以 `scripts/count_stats.py --json`
与 `audit_tool_contracts.py` 的实测为准，文档随后修正。

## 8. 附录 B：未验证项台账（REA #64：未验的计数器不当零）

本方案里所有"数字型承诺"必须能指出**谁在测、测了没有**。当前状态：

| 承诺 | 当前状态 | 为什么未验证 | 解除条件 |
|---|---|---|---|
| T0 常驻上下文占用下降 ≥40% | **未验证** | 无 schema token 估算脚本；无遥测基线，分母未知 | 先写 `--estimate-tokens` 估算器（读 52 个 InputSchema 计字符/近似 token），再与本表一起更新 |
| 遥测上线 2 周后校准分级 | **未验证** | 仓库内实测 `logs/` 无 tool_call 记录（2026-10-19） | MCP handler 落 tool_call 审计日志（工具名/阶段/耗时/成败），跑满 14 天 |
| 52 工具契约完备 | **部分验证** | `audit_tool_contracts.py` 静态扫到 47 个注册块 / T0 22 全命中；12 个 T0 工具仍在结果里拼 `err.Error()` | 见 `docs/工具契约与输出边界-2026-10-20.md` §一 |
| "分级后模型不会幻觉未注册工具" | **未验证** | 需对照实验（同任务、tier 全量 vs T0），未做 | 做一次 A/B，记录"调用不存在工具"的次数 |

**口径纪律**：上表任一项标"未验证"时，对外材料**不得**出现对应的量化收益表述
（"上下文降 40%"、"工具数减半"）。这与 README 的能力三档口径同源：
**未验证 ≠ 0，也 ≠ 已达成**。

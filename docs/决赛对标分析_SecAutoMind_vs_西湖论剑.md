## 一、两个项目的本质差异

| 维度 | 西湖论剑 CTF-Agent | SecAutoMind |
|------|-------------------|-------------|
| **定位** | 专用 CTF 解题 Agent（"CTF 夺旗赛选手"） | 通用网络安全智能体平台（"安全运营中心"） |
| **语言** | Python | Go（单二进制） |
| **核心能力** | 确定性求解 + LLM 兜底 | 多 Agent 协同编排 + 工具调度 |
| **解题方式** | presolve 确定性预解 → 58 skill 并行 → LLM 最后兜底 | Agent 规划 → 调用 90 YAML 工具 → 审计 |
| **平台对接** | DASCTF 完整 API 客户端（拉题/实例/提交/重置） | ❌ 无 CTF 平台对接 |
| **flag 提交** | fail-closed 提交 + 多候选迭代 + 墙钟止损 | ❌ 无 flag 提交机制 |
| **监督反思** | 轻量模型 + 确定性规则（0 token） | 审计 Agent（全量 LLM） |
| **诚实 KPI** | offline_verified=12（SHA256 验证） | 实测证据包 E1-E19 |
| **产品化** | CLI/脚本为主 | Web UI + 三端部署 + IM 机器人 |

**核心洞察：西湖论剑是"CTF 赛道专项选手"，SecAutoMind 是"通用安全平台"。决赛实战赛考的是 CTF 解题能力——这是西湖论剑的主场。**

## 二、逐模块能力差距矩阵

### 2.1 确定性求解能力（差距最大 🔴）

| 能力 | 西湖论剑 | SecAutoMind | 差距 |
|------|---------|-------------|------|
| **skill 总数** | 58 个 Python skill | 7 个 Go 求解器 | 🔴 58 vs 7 |
| **crypto 题型覆盖** | RSA(费马/小e/高指数/PKCS#1/共模/格) + AES/ECB/填充预言机 + 格基 + Legendre + 模逆 | RSA(费马/共模) + 凯撒 + 基础 base64 | 🔴 巨大 |
| **misc 题型覆盖** | 隐写(jpeg/png嵌入) + 流量分析 + 磁盘取证 + ZIP伪加密 + 网格重采样 + LFSR + Morse + 维吉尼亚 | base64多层 + XOR + 哈希 | 🔴 巨大 |
| **web 题型覆盖** | SQL注入 + SSRF + XXE + SSTI + JWT + 上传绕过 + 二次注入 + 竞态 + 源码审计 | ❌ 无专项 | 🔴 |
| **reverse 题型覆盖** | angr + ELF + Go/APK + JS + 混淆 + 路由器 + pyc反编译 | ❌ 无专项 | 🔴 |
| **pwn 题型覆盖** | exploit流程 + libc指纹 + 无GDB + ret2dlresolve + 沙箱逃逸 + tcache | ❌ 无专项 | 🔴 |
| **任务分析/路由** | `task_analyzer.py`：自动识别 RSA 子类型并路由到正确求解器 | ❌ 无自动题型识别 | 🔴 |
| **关键词模板匹配** | 40+ 关键词模板（caesar/b64/morse/hash/xor/栅栏/仿射/brainfuck/base58...）| ❌ 无 | 🔴 |

**结论：确定性求解是决赛 60% 的核心战场。SecAutoMind 目前只有 7 个基础求解器，而西湖论剑有 58 个覆盖全品类。差距不在 Agent 智能，在于"解题工具箱"的深度。**

### 2.2 确定性预解层 / presolve（差距大 🔴）

| 能力 | 西湖论剑 | SecAutoMind | 差距 |
|------|---------|-------------|------|
| **presolve 架构** | `core/presolve.py`：单入口统一预解，5 层尝试（flag扫描→crypto_auto→数学引擎→关键词模板→LLM兜底） | ❌ 无 presolve 层 | 🔴 |
| **去重机制** | 同一题只嗅探一次，避免重复消耗 | ❌ 无 | 🟠 |
| **多候选提取** | flag_extract_guard：flag{}/DASCTF{}/CTF{} + ROT13/ROT18 变体检查，候选透传到提交迭代 | 仅 ctf_flag_scan 正则 | 🟠 |
| **确定性优先纪律** | LLM 白名单 + token 预算 + 墙钟止损，presolve 命中则 0 token | 无强制"先确定性后 LLM"编排 | 🔴 |

### 2.3 CTF 平台对接（差距大 🔴）

| 能力 | 西湖论剑 | SecAutoMind | 差距 |
|------|---------|-------------|------|
| **平台 API 客户端** | `ctfplatform/dasctf.py`：完整生命周期（拉题→详情→实例→访问→下载附件→提交flag→重置→销毁） | ❌ 无 | 🔴 |
| **flag 提交机制** | fail-closed 提交 + 多候选迭代 + 错误分类（请求失败 vs flag 错误） | ❌ 无 | 🔴 |
| **轮询/首血** | `_race_start.py --compete`：首血扫描→稳定轮询→终报 | ❌ 无 | 🔴 |
| **e2e 预检** | `_e2e_verify.py`：平台实际提供题目数据的验证 | ❌ 无 | 🔴 |

**决赛场景适配：决赛第一环节是"人机协同实战赛"，3 名队员 + AI Agent 在受控环境现场解题。这意味着：①平台会提供题目（需 API 拉题）②需要提交 flag（需提交机制）③需要监控进度（需轮询）。SecAutoMind 目前完全没有这条链路。**

### 2.4 监督/纠错机制（各有优势 🟡）

| 能力 | 西湖论剑 | SecAutoMind |
|------|---------|-------------|
| **监督模型** | 轻量模型 + 确定性规则（0 token） | 审计 Agent（全量 LLM，更重） |
| **裁决类型** | continue/redirect/switch_strategy/upgrade_model/give_up | approve/reject（HITL） |
| **错误分类** | 7 类精细分类（stuck_loop/wrong_direction/hallucination/tool_failure/env_failure/extract_fail/wallclock_timeout） | 403 拒绝路径 |
| **墙钟止损** | 300s 硬止损，单题超时强制放弃 | ❌ 无单题级止损 |
| **步骤预算** | 每 2-3 步 / 连续失败 2 次强制咨询监督 | ❌ 无步骤级约束 |

**SecAutoMind 的 HITL 审批是"人机协同"优势（赛题明确要求），但缺少"自动纠错/止损"机制——决赛限时场景下，单题烧 10 分钟没有止损 = 丢分。**

### 2.5 Agent 协同架构（SecAutoMind 优势 🟢）

| 能力 | 西湖论剑 | SecAutoMind |
|------|---------|-------------|
| **Agent 类型** | 2 类（主 Agent + 监督 Agent） | 4 类（规划/执行/审计/复盘） |
| **编排模式** | 单一 Plan-Act-Observe 循环 | 3 种（Deep/Plan-Execute/Supervisor）自动选型 |
| **共享上下文** | 无（单 Agent 直接推理） | 事实黑板（多 Agent 跨步共享） |
| **可解释性** | 步骤记录 + 置信度 | 审计日志 + HITL 裁决链 |
| **人机协同** | ❌ 无人工干预点 | ✅ HITL 审批（赛题核心要求） |

**SecAutoMind 的"四类 Agent + HITL"架构更贴合赛题要求——但目前只用于通用安全运营，没有针对 CTF 解题场景优化。**

## 四、SecAutoMind 的独特优势（西湖论剑没有的）

| 优势 | 决赛价值 |
|------|---------|
| **HITL 审批门** | 赛题明确要求"人机协同"——3 名队员可通过审批界面实时干预 Agent 决策，这是纯自动化 Agent 做不到的 |
| **多编排模式自动选型** | 简单题用 Deep 快解，复杂题用 Plan-Execute 规划，多任务用 Supervisor 协调——比单一循环更灵活 |
| **审计回放** | 答辩环节 40%：完整决策链可回放，评委可看到"为什么这样做" |
| **单二进制部署** | 受控环境部署最快，3 分钟搞定 |
| **8 通道 IM 机器人** | 3 名队员可通过飞书/钉钉实时与 Agent 对话（不只是 Web UI） |
| **RBAC 权限隔离** | 队长/队员/审计员分工明确 |
| **Go 高性能** | 并发工具调用比 Python 单线程快 |

## 六、关键结论

1. **SecAutoMind 的核心竞争力不是"解题比西湖论剑快"，而是"人机协同 + 可解释 + 产品化"**——赛题明确要求"人机协同"，这是西湖论剑做不到的。

2. **但"不能对接平台 + 不能提交 flag = 不能参赛"**——P0 #1-#3 是生死线，没有平台对接一切白搭。

3. **确定性求解器是"省钱省时"的关键**——西湖论剑的经验：presolve 命中则 0 token，58 个 skill 覆盖 92 道真题中的 12 道。SecAutoMind 的 7 个求解器只能覆盖最基础的题型，需要大幅扩展。

4. **Go 语言是性能优势**——并发工具调用、单二进制部署、内存效率都优于 Python。决赛受控环境部署 Go 版本更快更稳。

5. **决赛 120h 仿真平台是机会**——如果能提前拿到平台 API 文档，做好平台对接和解题工作台，SecAutoMind 的"人机协同"优势会在长时间对抗中充分体现。

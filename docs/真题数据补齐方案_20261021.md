# 真题基准数据补齐方案（2026-10-21 调查结论）

> 目的：把「静态真题 16/55 = 29.1%」背后的数据缺失调查固化成可执行方案，供后续决策。
> **本文只做方案，不改任何对外数字**。执行数据补齐 = 会改竞赛 headline，须主理人拍板。

## 一、结论先行

29.1% 是**数据缺口**，不是能力缺口。55 题中：
- **命中 20 题**（有数据，题面即密文/参数，可解）；
- **未命中 35 题**：`description` 只有 12–28 字符的**提示语**（如"RSA e=3小指数攻击"），**无实际题目数据**、无附件——任何求解器都无法解。

**有数据的 20 题里，真求解器命中 16 = 80%**（另 4 道是"题面即答案"伪解，不计能力）。

## 三、为什么补数据会持久化（不是白补）

`data/ctf_benchmark/real_benchmark.json` 经 `git ls-files` 确认**是 tracked（已入库）**，不是 gitignore。补进去的题面/参数会随提交持久化、进 CI。

## 四、补齐可行性分级

| 分类 | 缺什么 | 补了静态分能提吗 |
|---|---|---|
| **crypto（4）** | 缺 n/e/c 等精确参数 | **可能**——若参数写进题面，`rsa_small_e` / `crc` 等求解器可解。需从 writeup 抠精确参数（flag 是 sha256 校验，参数必须完全对得上） |
| **misc（10）** | 缺文件（pcap/图片/二进制） | **基本不能**——静态求解器"仅 description 输入"，没有文件等于没题 |
| **web（21）** | 缺文件/靶机 | **不能**——需要真实靶机，属于"执行层/Web 层"基准，不是静态基准 |

**净收益估算**：最多 4 道 crypto → 16/55 → 20/55 = 36.4%。

## 五、若决定补齐（选项 C/A）的完整链

补 crypto 数据会改 headline，必须同步整条数字链（缺一步门禁就红）：

1. 从 writeup 抠出 4 道 crypto 的精确参数，写进 `real_benchmark.json` 的 `description`；
2. 重跑覆盖率报告，确认命中数变化（`data/ctf_benchmark/real_coverage_report.json`）；
3. 改 `scripts/check_quant_effect.py` 的期望值（16/55 → 20/55）；
4. 抬 `docs/benchmark_baseline.json` 的 `min_hit`（20 → 24，地板只许抬）；
5. 改材料（`quant_effect.md` / `cross_bench_report.md` / PPT 生成器）的 29.1% → 36.4%；
6. 重跑 PPT 生成器 → `check_artifact_numbers` → `check_final_artifacts_freeze --update` → `build_championship_evidence`；
7. 全门禁复验（9 个）+ 服务器全量测试。

## 六、建议

- **维持现状（B）**：29.1% 是数据口径真实值，且已诚实标注"35 道无数据、有数据的 20 道 80%"。风险最低。
- **只补数据不改 headline（C）**：补 `real_benchmark.json` 但不重跑覆盖率/不改材料——**会造成"数据变了但报告没变"的不一致**，不推荐。
- **完整补齐（A）**：仅当主理人愿意把 headline 从 29.1% 改成 36.4% 并承担整链重跑时执行。

**当前 HEAD 的诚实口径已能把能力讲清楚；是否用"补齐数据"换一个更高的 headline，是竞赛叙事决策，需主理人定。**

# SecAutoMind 产品优化规划（2026-10-18）

> **文档定位**：`规划-移植与优化总纲.md`（9-15）解决的是「工程完备」——平台接线、抗打击、诚信铁律、证据包、冻结纪律，这些**已全部机验闭环**。本文件解决的是它的下一层：**「工程完备」不等于「评委信服」**，产品优化的缺口在叙事、体验、可信三个层面，而非再补一个门禁。
>
> **数字口径**：本文件所有规模数字一律以 `scripts/count_stats.py` 实时输出为准（单一真值源），不手写、不凭记忆。

---

## 一、核心判断

SecAutoMind 的工程治理已做到参赛项目天花板（24 job CI、六道交付红线、证据包可复现、反注水法令、数字漂移清零），这是真正的护城河。但「产品优化」的缺口不在工程完备，而在**从「工程完备」到「评委说服力」的最后一跃**：

1. **叙事层**：对外材料仍在用「技术清单」讲「我有什么」（4 类 Agent × 91 YAML 工具 × 143 运行时工具 × 13 角色），而不是「为什么非我不可」。
2. **可信层**：最大的护城河「诚实治理 / 可复现证据」几乎只存在于内部纪律，对外材料零提及。
3. **体验层**：决赛现场「一句自然语言 → 端到端结果」的 wow moment 需要确定性演示，而非现场运气。
4. **一致性**：同一页官网里「顶部 143 运行时 vs 创新二 143」「顶部旧 140 vs 真值 143」这类漂移，正是评委最容易抓到的「数字不自洽」。

1. **官网叙事一致性**：§04「测试包通过」「Go 版本」「实测日期」三处陈旧值 + 顶部 stats「运行时安全工具」旧值，共五处口径对齐真值（测试包数 37、运行时工具 143、Go 1.25）。

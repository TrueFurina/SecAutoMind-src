# 决策可解释性证据包（T2 · docs/evidence-20260905）

> 对应赛题维度③「决策逻辑与可解释性」17-20 档要求：*"具备完善的决策可解释性设计，行为依据明确，逻辑可追溯、可复现，能有效应对干扰。"*
> 实测时间：2026-09-05 03:13-03:30 · 沙盒实例 · deepseek 通道 · plan_execute 编排

## 一、端到端决策链实测（一次真实任务全量留痕）

**任务**：*"请列出当前工作目录 data/ 目录下的文件清单，并用一句话总结本平台的数据存储结构。"*

**实测结果**：任务完成，产出正确结果（data/ 目录表格 + 存储结构总结）。全过程留痕 **63 个过程事件**：

| 事件类型 | 次数 | 含义（答辩口径） |
|---|---|---|
| `planning` | 7 | 规划 Agent 生成/修正计划——"计划即证据" |
| `reasoning_chain` | 6 | 推理链显式记录——行为依据明确 |
| `tool_calls_detected` / `tool_call` | 6 / 9 | 每次工具调用（参数+调用 ID）逐一入档 |
| `tool_result` | 8 | 每个结果回传黑板，可复核 |
| `iteration` | 8 | 执行-校验循环轮次——动态调整可数 |
| **`hitl_audit_agent_started` / `hitl_audit_agent`** | 2 / 2 | **审计 Agent 自动启动复核** |
| **`hitl_rejected`** | **2** | **审批先于执行：2 次危险调用被拒**（见下） |

**工具执行明细**（10 次，全部 completed）：`exec → ls → glob → ls → ls → execute → glob → ls → ls → ls`

## 二、意外收获：HITL"拒绝路径"天然实证（回答赛题"能有效应对干扰"）

决策链显示：Agent 首选 `exec`/`execute`（命令执行，属 HITL 敏感操作）→ **被 HITL 审批层自动拒绝 2 次** → Agent **未重试危险路径、未产生幻觉结论**，自动降级改用只读工具 `ls`/`glob` 完成任务。

这一条链同时证明了三件事（答辩可直接讲）：
1. **审批先于执行**——不是"执行完才报告"，危险调用在执行前被拦截；
2. **拒绝后行为可控**——降级到安全路径而非硬重试，验证"运行鲁棒性"；
3. **拒绝事件全程留痕**——`hitl_rejected` 事件 + 审计日志双记录，可回放。

## 三、可解释性设计说明（一页版，答辩可讲）

```
用户任务 ──► 规划 Agent（planning ×7：拆解目标生成计划，计划即证据）
                │
                ▼
        执行 Agent（iteration ×8 循环）
                │  每轮：reasoning_chain（为什么这么做）
                │        → tool_call（调用什么、参数是什么）
                │        → [HITL 审批门：危险操作？→ 审计 Agent 复核 → 放行/拒绝]
                │        → tool_result（结果回传事实黑板）
                ▼
        审计 Agent（hitl_audit_agent：复核偏差，hitl_rejected 即审计事件）
                │
                ▼
        复盘沉淀（决策链全量入档，API 可回放）
```

**三个"可"的落地**：
- **可追溯**：`GET /api/messages/:id/process-details` 返回全量事件流（本次实测 63 事件 / 10 次工具执行，原始 JSON 见 `raw/decision_chain_process_details_*.json`）
- **可审计**：并行审计日志独立留存（见 evidence_index.md E-09/E-10），含 access_denied/hitl_rejected 事件
- **可复现**：同一任务可重复执行，事件流结构一致；批量任务队列支持 cron 重跑

## 四、通道切换实测（鲁棒性副证）

- qwen-max 通道：阿里云欠费 → 400 "Access denied"（如实记录，不掩饰）
- deepseek 通道：自动接管，1.7s 响应"在线"，随后完成 plan_execute 全任务
- **口径**：这验证了"多通道 + 失败切换"的设计在真实故障下有效；但"自动轮询切换"是代码内建行为，本次为手动指定通道，**全自动 failover 的端到端断言留给 A 线 E4 抗干扰实验**（诚实边界）。

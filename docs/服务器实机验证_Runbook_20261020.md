# 服务器实机全量验证 Runbook（2026-10-20 实测）

> 用途：决赛前在**真实 Linux 环境**跑全量测试，与本地 Windows 结果形成"双环境互证"。
> 凭据：SSH 访问见 `E:\Program\实验服务器与全局配置.md`（`user@172.16.222.99`，ed25519 免密已授权）。
> 本文只记流程与坑，**不写任何口令**。

## 0. 前置

- 服务器：主机名 `ubantu`，Go 1.25.4 在 `~/go1.25.4`，python 在 `/usr/bin/python3`。
- 本机连通性：`ssh -o BatchMode=yes -o ConnectTimeout=8 user@172.16.222.99 "echo ok"` → 输出 `ok` 即通。

## 1. 同步当前 HEAD 到服务器

用 `git bundle`（含完整历史、可克隆、**不含并行会话 WIP**）——服务器原 `~/SecAutoMind` 是旧快照且无 `.git`，不能直接测当前代码。

```bash
# 本机
git bundle create /tmp/sam.bundle HEAD
scp /tmp/sam.bundle user@172.16.222.99:~/sam.bundle

# 服务器
cd ~ && rm -rf SecAutoMind_verify
git clone ~/sam.bundle SecAutoMind_verify
cd ~/SecAutoMind_verify && git log --oneline -1   # 确认 HEAD 与本地一致
```

## 2. 环境准备

```bash
export GOROOT=$HOME/go1.25.4
export PATH=$GOROOT/bin:$HOME/bin:$PATH
export GOPATH=$HOME/gopath
export GOPROXY=https://goproxy.cn,direct
export GOFLAGS=-mod=mod
# ctfplatform 拉起靶场需 `python`，服务器只有 python3
ln -sf $(command -v python3) $HOME/bin/python
```

## 3. 补齐不被 git 跟踪的测试夹具（关键坑）

`exec_git_repo` / `git_cred_repo` 是带 `.git` 的夹具，**不被 git 跟踪**，bundle/clone 不会带。
不补的话 `TestExecSolversAgainstBenchmark` 会 13/15（两个 git-history 用例失败），**这是环境缺件，不是代码 bug**。

```bash
cp -r ~/SecAutoMind/data/ctf_benchmark/execution/exec_git_repo \
      ~/SecAutoMind/data/ctf_benchmark/execution/git_cred_repo \
      ~/SecAutoMind_verify/data/ctf_benchmark/execution/
```

## 4. 全量测试

```bash
cd ~/SecAutoMind_verify

go build ./...

# 37 包（排除 ctfplatform，快）
PKGS=$(go list ./internal/... | grep -v ctfplatform)
go test -p 1 -count=1 $PKGS

# ctfplatform 整包（慢：SSRF 靶场各 ~60s；无 LLM key 时 TestLLMAutoSolve 自动跳过）
env -u DEEPSEEK_API_KEY go test -p 1 -count=1 -timeout 900s ./internal/ctfplatform/
```

判成败一律落盘后看 RC：`cmd > /tmp/x.log 2>&1; echo "RC=$?"; grep '^FAIL' /tmp/x.log`。

## 7. 已知坑（与部署文档 §8.4 同源）

1. **`python` 软链**：ctfplatform 靶场需 `python`，服务器只有 `python3`。
2. **`.git` 夹具不随 bundle**：`exec_git_repo`/`git_cred_repo` 需单独拷入。
3. **`DEEPSEEK_API_KEY`**：若服务器上被设，`TestLLMAutoSolve` 会真跑 LLM（慢且费 token），跑全量时用 `env -u` 去掉。
4. **GOPROXY 必须设**：`https://goproxy.cn,direct`，否则首次构建拉不到依赖。

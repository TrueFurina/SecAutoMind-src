# 非 flag 靶场「打穿证据」探测：设计与训练记录

> 建立日期：2026-10-21 · 主理人已批准（"点头了"）
> 目的：让本仓能够对**不发 flag 的真实靶场**判定"是否真的被打穿"，同时**不改动**基准判分口径。
> 关键约束：**旁路能力，不进 flag 判分路径，对基准分数零影响。**

---

## 1. 为什么需要它

基准题库（`data/ctf_benchmark/real_benchmark.json`）的判分口径是 **sha256(flag)**，
而真实靶场（如 LAMPSecurity CTF4）是 **root 导向、全程不发 flag**。

此前用生产链路函数打 CTF4，结果恒为 **0 命中**。根因有两条（已核实）：

1. `internal/ctfplatform/web_hints.go:241` — `if len(eps) == 0 { return }`：
   题目描述不给端点线索时，SQLi/SSTI/LFI/cmdi/SSRF 定向阶段**一次都不跑**。
2. 所有探测结果经 `passiveScan` 过滤（`web_hints.go:212-221`），**只保留 flag 形态字符串**。
   靶机返回的是 `/etc/passwd`、`.htpasswd` 明文，不含 flag → 不产生 `WebFinding`。

**结论：这是判分口径差异，不是能力缺失。** 因此不修改 flag 路径，而是新增一条旁路。

## 2. 设计

### 2.1 隔离原则

| 项 | flag 判分路径（原有） | 旁路证据（本次新增） |
|---|---|---|
| 入口 | `ExploitURLsInText` / `ExploitWebTargetWithHints` | `ProbeSensitiveFileRead` |
| 返回 | `[]WebFinding`（含 `Flag`） | `[]WebEvidence`（**无 Flag 字段**） |
| 判分 | 参与 sha256(flag) 校验 | **完全不参与** |
| 对基准数字影响 | — | **零** |

两者**不共享返回值**，也不互相调用，因此不可能出现"伪造 flag 污染分数"。

### 2.2 新增 API（`internal/ctfplatform/web_evidence.go`）

```go
type WebEvidence struct {
    Kind    string // lfi_sensitive_file
    URL     string // 命中的完整请求
    Param   string // 被注入的参数名
    Payload string // 生效的载荷
    Signal  string // etc_passwd / etc_shadow / htpasswd_hash
    Detail  string // 打码摘要（绝不落原文口令哈希）
}

func ProbeSensitiveFileRead(ctx, baseURL string, hints WebHints) []WebEvidence
func DiscoverWebParams(ctx, baseURL string) (endpoints, params []string)
```

`DiscoverWebParams` 补的正是 §1 第 1 条盲区：抓入口页的 `href`/`action`，
自己找出 `?page=` 这类参数，**不依赖题目描述给线索**。

### 2.3 检测信号（强特征，避免误报）

| 信号 | 正则要点 | 说明 |
|---|---|---|
| `etc_passwd` | `^root:[^:]{0,64}:0:0:` | root 行是"文件被读出"最硬的证据 |
| `etc_shadow` | `^root:[^:]{1,160}:\d+:\d+:\d+:` | 需 root 权限，通常拿不到（负向对照） |
| `htpasswd_hash` | `^user:(\$apr1\$…\|\$2[aby]\$…\|[A-Za-z0-9./]{13})$` | 同时识别 DES-crypt / apr1-md5 / bcrypt |

普通页面（含 "root" 单词）不会命中——`TestClassifySensitive` 有专门的反向用例。

### 2.4 载荷策略

按命中概率排序，**载荷优先于参数扩展**（保证最可能的参数先被穷举）：

1. 题目线索给出的载荷（含 `..`/`passwd`/`htpasswd` 时）
2. `/etc/passwd` 多级深度 ×1..6，每级带 `%00` 变体（对抗 `include($page.".php")` 后缀拼接）
3. 敏感文件字典：`restricted/.htpasswd`、`.htpasswd`、`htpasswd`、`conf/.htpasswd`、`etc/hosts`、`etc/shadow`（深度 1..4，均带 `%00`）
4. 过滤绕过：`....//` 归一化形态
5. 编码回读：`php://filter/convert.base64-encode/resource=…`（命中后自动 base64 解码再分类）

**关键实现细节**：`%00` 必须保持字面量。`url.QueryEscape` 会把它变成 `%2500` 而失效，
因此 `buildProbeURL` 用裸串拼接（`TestBuildProbeURL_KeepsNullByteLiteral` 锁死这条）。

请求预算上限 180 次，命中 4 条即提前返回，避免组合爆炸。

## 3. 训练记录（对真实靶机）

靶机：LAMPSecurity CTF4（见 `docs/真实靶场_LAMPSecurity_CTF4_可用性验证_20261021.md`）
地址：`http://127.0.0.1:8080/`，由 `scripts/ctf4_lab.sh start` 拉起。

| 轮次 | 变更 | 证据数 | 命中信号 | 耗时 |
|---|---|---|---|---|
| 0（基线） | 生产 flag 链路 | **0** | — | 1.52s |
| 1 | 新增旁路探测 + 参数自动发现 | **1** | `etc_passwd` | 1.54s |
| 2 | 扩展敏感文件字典（`.htpasswd` 等） | **2** | `etc_passwd`, `htpasswd_hash` | 1.41s |

第 2 轮的实际输出：

```
[discover] endpoints=[/index.html /usage] params=[title page]
[probe] elapsed=1.41s evidence=2
  #1 signal=etc_passwd    param=page payload=../../../../etc/passwd%00
     detail=命中 /etc/passwd 的 root 行，账户行数≈48
  #2 signal=htpasswd_hash param=page payload=../restricted/.htpasswd%00
     detail=命中 Apache 口令文件，条目数=4，算法=DES-crypt（哈希已打码）
```

**注意第 1 条**：`page` 参数和 4 级深度都是**自动发现**的，没有任何人工线索——
这正是 CTF4 说明书 Step 8/9 要人手工试出来的东西。

## 5. 训练回路（可重复）

```bash
bash scripts/ctf4_lab.sh start     # 拉起靶机（首次自动建 VM）
bash scripts/lab_train.sh          # 跑一轮
bash scripts/lab_train.sh -n 5     # 连跑 5 轮，看稳定性
```

脚本会：拉起靶机 → 等 HTTP 200 → 跑活靶机用例 → 把结果追加到

退出码：0=至少 1 条证据，1=0 条，2=环境未就绪。

## 6. 边界（必须说清）

- **不改基准数字**：`ProbeSensitiveFileRead` 不参与任何打分，`real_benchmark` 的
  16/55、20/55 等口径**一个都没动**。
- **不是"能力提升"的对外材料**：它是**真实靶机对照能力**，不能拿来替代基准成绩，
  计入对外能力数字即属注水（AGENTS.md 第一条 1.5）。
- **未做的事**：DES-crypt 口令破解、SSH 登录、本地提权链。这三步需要外部工具或
  交互式会话，当前不在本仓的自动化范围内。
- **靶机仅限本机 NAT**，2009 年的 CentOS 时代系统，不得暴露公网。

## 7. 下一步（若继续训练）

1. **SQLi 登录绕过**：CTF4 的后台登录（说明书 Step 6）——可复用现有 `AttackSQLi`，
   但需要先发现登录表单（`DiscoverWebParams` 已能抓 `action`）。
2. **口令破解**：DES-crypt 需要 `hashcat`/`john` 或自带 crypt 实现，属外部依赖。
3. **提权链**：需要交互式 shell，超出当前 HTTP-only 链路。

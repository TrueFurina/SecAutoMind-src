## 二、Writeup：第 1024 行（Web, 100pts）

**靶面**：Flask 单文件应用 OpsDesk（~1100 行），评审组留话「问题就在第 1024 行」；flag 在 `/flag`。

**1. 静态定位**：附件 `app.py` 直读 1024 行附近——`resume_state_object()` 的 legacy 分支对
用户可控 `state` 做 **`pickle.load`**（`POST /api/v1/session/resume`），前置条件
`CONFIG["legacy_compat_mode"]` 为 True 才可达。源码里其他「看起来危险」的段落均为诱饵。

**2. 确认开关**：`GET /api/v1/meta` 返回 `"legacy_compat_mode": true`（version 2.4.1-demo）——
不用猜，应用自己承认脆弱路径启用。

**3. 反射型 payload**：漏洞点的回显链是
`jsonify({"resumed": True, "state": safe_json_loads(json.dumps(obj, default=str), obj)})`——
`default=str` 会对 pickle 还原出的任意对象调 `__str__`。构造：

```python
class P:
    def __reduce__(self):
        return (builtins.eval, ("open('/flag').read().strip()",))
```

`eval` 是内建可按引用 pickle；`__reduce__` 执行后返回 flag 字符串本体，经 `default=str`
原样回显在响应里——零外带信道、一发命中。注意 payload 首字节不得为 `{`（否则走 JSON 分支绕开
pickle），pickle 流天然满足。

**4. 发射与提交**：`POST /api/v1/session/resume`（body 走文件避免 shell 吞引号）→
响应直接给出 `DASCTF{461603ee-07a4-44b4-9ad4-f74c937f4a5a}` → 平台 API 提交返回
`ALREADY_SOLVED`（swarm 几乎同时独立打通同一漏洞，双向确认）。

**可复用经验**：①`__reduce__ + eval + 回显函数的 default=str` 三件套适用于一切
「pickle 落地后对象被序列化/字符串化输出」的题目；②解题时先看应用自曝的配置位（meta/debug
路由）再猜环境；③平台 API（challenge 列表/environment/scoreboard）是地面真值。

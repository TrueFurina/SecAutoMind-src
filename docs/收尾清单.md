# 收尾清单（P-10 · 八项打钩 + 取证边界）

> **这是打钩用的，不是参考用的。** 每次涉及代码/文档的任务收尾，逐项过一遍；过不了的写"未通过"，不许写"基本通过"。
> 前六项管本次改动，后两项管下一次会话——后两项不会让当前功能变好，但它们是唯一能让同类错误不复发的两栏。

---

## 一、八项打钩

### 1. 接口（HTTP / MCP / 内部 API）
- [ ] 新增或修改的接口，**调用方**已同步（前端 `internal/app/web/`、`cmd/`、`mcp-servers/`）。
- [ ] 有对应的测试；没有测试的，在"取证边界"里写明"无测试覆盖"。
- 判据：`go build ./...` rc=0 且能指出至少一个真实调用点（不是只存在于定义里）。

### 2. 事件 / 回调 / 订阅
- [ ] 新增的订阅方已登记在发布方能看到的地方；**回调里的异常有兜底**（未捕获异常会让订阅永久死亡且不报错）。
- 判据：能回答"谁发、谁收、收不到时有没有日志"。

### 3. 数据库迁移
- [ ] 迁移文件**已登记进执行清单**（放进目录 ≠ 会执行）。
- [ ] 有默认值的新列，默认值方向与代码判据一致。
- 判据：能指出登记位置；无迁移则本项打 `N/A` 并说明。

### 4. 新子系统 / 新包
- [ ] 已注册到启动序列（`cmd/server/main.go` / `internal/app/`）。
- [ ] `docs/AGENT_ROUTES.md` **同轮更新**（加代码不改表 = 下一个人踩空）。
- 判据：`ls internal/<新包>` 存在，且路由表能查到它。

### 5. 隔离与权限
- [ ] 涉及按用户/租户/角色取数的查询，**显式带条件**，不依赖上层兜底。
- [ ] 高危动作（删除/部署/批量改）走 HITL 档位，不自动执行。
- 判据：能指出条件写在哪一行；无此类改动则打 `N/A`。

### 6. 新模式 / 新门禁
- [ ] 新写的门禁脚本：① 自身有回归测试；② 关键门禁有**变异验证**（注入错误必须变红）；③ 已接进 `ci.yml`。
- 判据：`ci.yml` 里能 grep 到该 job；`<script>_test.py` 存在且实跑 rc=0。

### 7. 行号漂移（管下一次会话）
- [ ] 本轮在文档里引用的行号/路径，**已重新核对**（`grep -n` 现查，不信旧记录）。
- 判据：每个引用都能当场复现。

### 8. 避坑经验（管下一次会话）
- [ ] 本轮踩到的新坑，已落到 `AGENTS.md`（纪律类）或 `docs/AGENT_ROUTES.md`（定位类）。
- 判据：能指出落在哪个文件哪一条；**只写在对话里等于没写**。

---

## 二、取证边界声明（必须写，不许空）

> 空着 = 默认"全查过了"，这是假话。照实写三行：

- **没查的**：
- **查了但没覆盖的**：
- **仍未知 / 仍待用户拍板的**：

---

## 三、收尾三条硬判据

1. **"已完成"必须有证据**：给出命令 + 退出码 + 关键输出行。没有输出的"已修复"一律不算。
2. **失败就是失败**：非 0 退出码不许描述成"基本通过"；不许用管道过滤掩盖 FAIL。
3. **部分完成就说部分完成**：不许用"收官/全部搞定"概括未完成项。

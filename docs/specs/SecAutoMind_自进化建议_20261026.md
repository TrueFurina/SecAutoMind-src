# SecAutoMind 项目自进化建议（2026-10-26）

> 前置：基于《SecAutoMind_认知报告_20261026.md》同日同基线（head=5462133）。
> 「自进化」定义：**系统不依赖人肉警觉，自己抓自己的错误、把失败/成功自动变成下一轮资产**。
> 本文只提建议不动代码；每条标注现状证据与验收判据。

---

## 一、已有的进化机制盘点（先承认家底）

本仓已经是同类项目里反馈环最密的：LessonsLearned（红一次登记一条）、weekly_audit 周审（九项，立尺）、AGENTS.md 事故驱动更新、KPI_WATERMARK + KPI_BASELINE 棘轮（fail-closed，不允许自动重建）、变异验证纪律、session_registry 占位、`.workbuddy-ai` 每日记忆 + 会话总结提炼、skill-exec-gate（堵 skill 写了不被调用）。

**核心判断：不缺机制，缺的是「环的闭合」——若干环节仍靠人肉自觉，一旦没人盯就静默失效。** 自进化的杠杆点是把断掉的环接上，而不是新增治理文档（AGENTS.md 本身警告两者不许膨胀）。

---

## 二、P0 · 先修正在「自蚀」的环（不修则一切进化建在被削弱的门禁上）

### 1. secret_guard 假阳性白名单（最高优先）
- **现状**：21 处已知假阳性（`CTF-Agent_融合/` PyCryptodome 测试向量 + 合成样本）→ **每次提交都 `--no-verify`**。这是全仓唯一「常态性绕过门禁」的通道，真 key 若混进下次绕过的提交里，门禁已习惯性闭眼。
- **建议**：白名单按「文件 + 行锚 + 指纹」三元组登记（不可只按文件，防文件内容被替换后白名单继续放行）；白名单自身进 CI 校验条目仍存在；修完先做变异验证（注入真 key 形态必须仍红）。
- **验收**：连续一个提交周期零 `--no-verify`。

### 2. LessonsLearned 登记自动化
- **现状**：登记纪律「CI 每红一次登记一条」写在 AGENTS.md，但靠人自觉；当前 4 条登记里已有 1 条是「归因错了再改」（说明人肉登记还慢一拍）。
- **建议**：CI 失败 job 的 post-step 自动 append 一行待登记骨架（日期/job/空原因列）到 LessonsLearned「待归因」区；人只填归因，不负责「想起来登记」。空骨架停留超 7 天 → agent-docs-gate 转 WARN。
- **验收**：下次非预期红灯后，表里自动出现骨架行。

### 3. 文档新鲜度机检（这次会话就撞上的坑）
- **现状**：`QUICKSTART_NEXT_AGENT.md` 停在 10-20 仍在声称「以 HANDOFF_2026-10-18 为准」，而战略 10-25 已转向——**入口卡本身成了过期信息源**，且无门禁拦截。
- **建议**：所有 INDEX 标「当前权威」的文档头部强制 `as_of: YYYY-MM-DD` 戳；超 14 天未刷新 → agent-docs-gate WARN（不 BLOCK，防止为刷而刷）；QUICKSTART 这类入口卡超期即升红。
- **验收**：把 QUICKSTART 的 as_of 改老 30 天，门禁必须变红（变异验证）。

## 三、P1 · 让失败自动变成「下一刀」（破晓线的进化引擎）

### 4. rejected_candidates 聚合器
- **现状**：C 线刚落地（5462133）——`extract_fail` 的被拒候选值已进结构化字段并贯穿 BenchmarkResult，但**消费方还是人肉 grep**。
- **建议**：weekly_audit 新增检查项：聚合最近跑批的 `rejected_candidates` → 按拒绝原因分桶出「失败步直方图」（哪一步死得最多：附件未读/候选错/超时/幻觉）→ 自动产出「下一刀候选清单」给破晓/听风。这正是 A 库十轮锐评「81.9% 失败集中在主 Agent 步」的方法论复刻，但目前靠人重跑分析。
- **验收**：跑批后周审 JSON 里出现 `failure_histogram` 字段且与手数一致。

### 5. 监督消费率统计落盘
- **现状**：听风的 KPI（被采纳的 ABANDON/SWITCH 次数 ÷ 总反思次数）**没有统计产物**；supervision.go 的 ReflectSupervision 甚至还没接进生产循环（第八条缺口审计同型：定义齐全 ≠ 接线）。
- **建议**：接线时同步落 `supervision_decisions.jsonl`；周审第 10 项消费它。**接线与统计必须同 commit**，否则又是「先接线后补数」的注水温床。
- **验收**：一个跑批周期后消费率可数。

### 6. 资产断链全量对账自动化
- **现状**：周审第 4 项已升级 active/known_lost 双语义（好设计），但范围仅数据资产；这次就发现 33 道附件缺失是靠人跑过滤脚本才量化。
- **建议**：对 heldout MANIFEST 全量 `Path.exists` 周审化：**新断链即红、已登记 known_lost 不重报**（防噪音红，A 库「护栏被注释掉」血教训）。找回附件后池子从 1→N 的变化自动可数。
- **验收**：删掉任一 active 附件，周审该项变红。

## 四、P2 · 让成功也自动沉淀（防「解了就忘」）

### 7. 解出题 → writeup/skill 骨架自动生成
- **现状**：writeups 目录纪律很好（赛中实证/赛后复现/未留痕三级），但产出靠人写；1024 快闪赛就留下「2 题未留痕」。
- **建议**：跑批 solved=True 时自动落 `writeups/_auto_<题名>_<日期>.md` 骨架（含轨迹、耗时、token、命令复现段），人只补叙述。skill-exec-gate 已保证沉淀的 skill 必被调用——生成与消费两端都已就位，只差中间的自动生成。
- **验收**：下次真实解出，骨架自动出现且被 INDEX 规则收编。

### 8. 变异验证覆盖率棘轮
- **现状**：29 个 CI job 中 **12 个标「无」**（无变异验证）——「能跑」≠「能红」。这本身就是 GATES.md 已登记盲区。
- **建议**：仿 KPI_BASELINE 棘轮：`mutation_covered / total_jobs` 只许升不许降，写入周审；每次给一个「无」job 补变异测试即 +1。不必一次补完（P2 节奏），但方向锁死。
- **验收**：周审 JSON 出现该比率，人为回退即红。

### 9. 口径漂移 PR 级检查
- **现状**：caliber-gate 全树扫，慢且红得频繁（并行写代码时一天红三次），于是立了「只在发布节点刷」的纪律——**纪律本身正确，但意味着平时漂移无人看**。
- **建议**：保留发布节点全量扫；另加轻量 PR 级检查：只扫本 PR 改动的文档里的数字 vs 真值。把「漂移发现时点」从「交付前」提前到「提交时」，成本近零。
- **验收**：PR 里写死旧求解器数，轻量检查当场红。

## 五、P3 · 组织层进化

### 10. 观澜台账数字化
- **现状**：六角色分工纪律 + session_registry 占位已存在，但「在飞收口率」（观澜 KPI）**不可数**——117 项在途改动收口状态不明就是证据。
- **建议**：session_registry 扩展 `--status`：列活跃会话 × 其声明文件边界 × 实际 `git status` 落在该边界的改动数；**边界外改动即「裸奔」告警**。现有 claim/release 数据已够，只差一个对账视图。
- **验收**：跑一次即可指出当前哪些未跟踪文件不属于任何活跃会话的声明边界。

### 11. 记忆分层自动提炼
- **现状**：`.workbuddy-ai` 日志单日可达 1071 行/46 节，靠会话总结人工提炼；QwenWork awareness MEMORY 已有体积预算（当前 ~58%）。
- **建议**：周审时自动把本周日志中「判据类」段落（标题含判据/教训/裁定）抽出成候选提炼稿，人只做删减不做摘写。与建议 2 同构：**机器负责不遗漏，人负责归因**。

## 六、反建议（自进化的边界，照 AGENTS.md 方法论红线）

1. **不加治理文档**：以上建议全部是「脚本/门禁/字段」，没有一条是新增 .md 制度——文档进化的尽头是没人读。
2. **进化机制自身要有变异验证**：每个新环落地前先证明它能红（第 4 条纪律），否则是第二层「失效门禁比没有门禁更危险」。
3. **不自动改代码**：所有「自动产出」（骨架/清单/提炼稿）都是**给人审的草稿**，不是直接落库的变更——永不在 bypass 模式下让 agent 持写权限自改（Five Never-Dos #1/#5）。
4. **优先级跟着战略走**：P1 全部服务破晓线（当前唯一 KPI）；刀锋侧不再新增求解器进化投入（线已冻结）。

# flag 泄露专项分析：为什么修了 19 个脚本还在漏（2026-10-31）

> 触发：用户指出「flag 相关问题太多，需要单独深入研究，比如训练时答案泄露、明文入库」。
> 本文只做两件事：**用实测数据说清现状**，**指出结构性根因**。不含"加强意识"这类空话。

## 0. 一句话结论

**项目一直把 flag 泄露当成"检测问题"（文件里有没有敏感串），但它本质是"数据流动问题"** ——
同一份答案从题库出发，被复制到 benchmark、生成器源码、测试夹具、文档、会话记忆、交付包共 6 个面。
每新增一个面就复发一次；检测做得再准，也只是追着面的增长跑。

## 1. 实测存量（2026-10-31 实跑，命令附后）

### 1.1 已入库（进了 git，不可逆）

`python scripts/audit_flag_provenance.py` → **已入库明文命中 1638 条**，按 sha256 命中真值分档：

| 分档 | 条数 | 含义 |
|---|---|---|
| **铁实锤真题答案** | **291**（157 道不同题） | sha256 命中题库真值 —— 是真答案，不是夹具 |
| 品牌像真但无实锤 | 69 | 需人看（下线题/新题/夹具） |
| 占位符模板 | 167 | 非答案 |
| 通用前缀自产构造 | 1111 | 自造样例 |

291 条真答案的**分布**（Top）：`data/ctf_benchmark/benchmark.json` 15、`gen_exec_artifacts_v2.py` 11、
`test_anti_hallucination.py` 10、`live_target/web_range.py` 10、`gen_forensics_artifacts.py` 10、
`heldout附件可用性审计_20261026.md` 9 …

**这五类文件的性质完全不同**，但都在泄露：
- benchmark json → 自测需要答案，但应该只存 sha256
- **生成器源码** → flag 被内联进 `gen_*.py`，所以才有 `externalize_generator_flags.py`
- **测试夹具** → 用真题答案当断言样本 ← **这就是"训练时答案泄露"的入口**
- 审计/复盘文档 → 分析时引用原文
- writeup → 解题记录

### 1.2 未入库但在磁盘上（一旦 `git add` 立刻变泄露）

`python scripts/secret_guard.py --dir .` → **未跟踪明文 flag 2005 条**，其中：

| 位置 | 条数 | 性质 |
|---|---|---|
| `.workbuddy-ai/memory/*.md` | 116（84 条实质内容） | **agent 会话记忆** |
| `CTF-Agent_融合/**` | 若干 | 融合树测试夹具 |
| `STEPFUN_CONCURRENT_PLAYBOOK.md` | 2 | 作战手册 |

更严重的是记忆里还有**真凭证**（`secret_guard --dir .workbuddy-ai/memory` 报"真实凭证命中 10"）：
`2026-10-13.md` 有一把千问 `sk-ws-…` 真 key、`2026-10-25.md` 有 PEM 私钥。
即 **agent 把自己看到的凭证原样写进了记忆**。

### 1.3 基准集的半迁移状态

`data/ctf_benchmark/*.json` 共 41 个：33 个已有 `_sha256` 字段，**7 个仍含明文 flag 形态**，9 个两者并存。
→ sha256 迁移**做了一半**，没有完成态。

## 3. 五类失效模式（同一个结构的五个出口）

| # | 模式 | 机制 | 代表证据 |
|---|---|---|---|
| 1 | **明文入库** | 生成器内联 flag、文档引用原文 | 291 条真答案已 commit |
| 2 | **训练污染** | 测试夹具/benchmark 用真题答案 → agent 练习时读到 → 评估集与学习集重叠 | `test_anti_hallucination.py` 10 处真答案 |
| 3 | **记忆外溢** | agent 把解题过程（含 flag、凭证）写进 `.workbuddy-ai/memory/` | 116 条 flag + 10 条真凭证 |
| 4 | **交付面泄露** | 打包时把上面这些一并带走 | 10-26 交付包被 1791 条 flag 拦下 |
| 5 | **判据失效** | 形态正则漏非 flag 答案（`1`/`cisco123`）、豁免腐化、真值集覆盖不足 | 事故 #9；`SELF_EXEMPT` 曾整体豁免测试文件 |

## 4. 根因：三个结构性错配

### 4.1 「题面」与「答案」同源同文件

题库（西湖论剑归档、`data/questions_*`）里答案和题面在同一个 json。任何"整体摄入"的流水线
（迁移、备份、融合、打包）都会连答案一起带走。**只要没有物理隔离，"记得排除答案"就是靠人。**

### 4.2 「需要答案」与「不能有答案」是同一个文件的两个消费者

自测/评测要答案，交付/入库不能有答案。于是同一个文件被迫同时满足两个矛盾需求 →
只能靠"跑完再改"（redact）→ 改之前的那一版已经进了 git 历史。

### 4.3 「形态判据」打不过「内容判据」

品牌正则（`DASCTF{...}`）可被改名洗白；只有 **sha256 命中真值**是硬判据。但它的覆盖率取决于
真值集大小（当前 473 个 sha256 / 270 个 benchmark json），且**新题一进来就没覆盖**。

## 5. 现有防线与盲区

| 面 | 现有防线 | 盲区 |
|---|---|---|
| 入库 | `secret_guard` 三卡口（tracked/real_brand/known_answer）+ CI | 基线"只许减不许增"，新增面不受约束 |
| 生成器 | `externalize_generator_flags.py` | 只覆盖被它列举的生成器，新写的生成器默认内联 |
| benchmark | `check_benchmark_plaintext_answer` / `migrate_*_to_sha256` | 迁移做了一半（7 个文件仍有明文） |
| 记忆 | **无** | agent 写入即落盘，事后才扫 |
| 历史 | **无** | redact 只改工作树，历史仍在 |
| 交付 | `make_delivery_package` 红线 | 靠 staging 扫描，不阻止源头产生 |

**最大盲区是"记忆面"和"历史面"** —— 前者每天都在长，后者不可逆。

---

## 6. 建议：从「检测」转向「不产生」

按性价比排序，前三项是治本，后两项是兜底。

### P0 记忆层写入前脱敏（成本最低、收益最高）
`.workbuddy-ai/memory/` 是当前**唯一每天都在增长**的泄露面。做法：写记忆的 hook 里先跑一遍
`redact_plaintext_flags.py --stdin`，命中即替换为 `flag{sha256:前8位}`。
理由：事后扫描永远晚一步，而记忆是"写完就不会再有人看"的文件。

### P0 测试夹具改用合成答案（直接掐断训练污染）
测试里用真题答案毫无必要 —— 断言"能提取出 flag"用 `flag{TEST_a1b2c3}` 就够。
把 `test_*.py` 里的 291 条真答案批量替换为合成值（可用 `redact_plaintext_flags.py` 扩展）。
**这是"训练时答案泄露"的根**：夹具里有真答案，agent 练习时就会读到。

### P1 完成 sha256 迁移（把"需要答案"的需求与"不能有答案"的约束解耦）
把剩余 7 个含明文的 benchmark 文件迁到 `*_sha256`；明文只留在 gitignore 的 vault
（`data/truth_vault/`）。这样 benchmark 可以随包分发，而答案不进仓库。

### P1 生成器强制外置（堵住"新生成器默认内联"）
在 `check_artifact_numbers.py --generators-only` 里加一条：生成器源码中出现 flag 形态字面量即红
（除非从 vault 读取）。现有 `externalize_generator_flags.py` 是"事后搬"，应改成"事前禁"。

### P2 历史重写（需你拍板，成本高）
若要彻底消除"291 条真答案在 git 历史里"，需要 `git filter-repo` 重写历史 + 强推。
代价：所有并行会话的分支失效、需要重新 clone。**除非要公开仓库，否则不建议做。**

---

## 7. 需要拍板的三件事

1. **记忆层脱敏**：是否接受"记忆里的 flag 一律替换成哈希前缀"（会损失一点可读性，但可查证）。
2. **测试夹具替换**：是否同意把 `test_*.py` 里的真题答案换成合成值（断言语义不变）。
3. **历史重写**：做 / 不做。不做的话，"291 条真答案在历史里"要作为**已知残留**登记在案。

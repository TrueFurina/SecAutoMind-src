## 0. 一句话结论

**项目一直把 flag 泄露当成"检测问题"（文件里有没有敏感串），但它本质是"数据流动问题"** ——
同一份答案从题库出发，被复制到 benchmark、生成器源码、测试夹具、文档、会话记忆、交付包共 6 个面。
每新增一个面就复发一次；检测做得再准，也只是追着面的增长跑。

## 4. 根因：三个结构性错配

### 4.1 「题面」与「答案」同源同文件

题库（西湖论剑归档、`data/questions_*`）里答案和题面在同一个 json。任何"整体摄入"的流水线
（迁移、备份、融合、打包）都会连答案一起带走。**只要没有物理隔离，"记得排除答案"就是靠人。**

### 4.2 「需要答案」与「不能有答案」是同一个文件的两个消费者

自测/评测要答案，交付/入库不能有答案。于是同一个文件被迫同时满足两个矛盾需求 →
只能靠"跑完再改"（redact）→ 改之前的那一版已经进了 git 历史。

### 4.3 「形态判据」打不过「内容判据」

品牌正则（`DASCTF{...}`）可被改名洗白；只有 **sha256 命中真值**是硬判据。但它的覆盖率取决于
真值集大小（当前 473 个 sha256 / 270 个 benchmark json），且**新题一进来就没覆盖**。

## 5. 现有防线与盲区

| 面 | 现有防线 | 盲区 |
|---|---|---|
| 入库 | `secret_guard` 三卡口（tracked/real_brand/known_answer）+ CI | 基线"只许减不许增"，新增面不受约束 |
| 生成器 | `externalize_generator_flags.py` | 只覆盖被它列举的生成器，新写的生成器默认内联 |
| benchmark | `check_benchmark_plaintext_answer` / `migrate_*_to_sha256` | 迁移做了一半（7 个文件仍有明文） |
| 记忆 | **无** | agent 写入即落盘，事后才扫 |
| 历史 | **无** | redact 只改工作树，历史仍在 |
| 交付 | `make_delivery_package` 红线 | 靠 staging 扫描，不阻止源头产生 |

**最大盲区是"记忆面"和"历史面"** —— 前者每天都在长，后者不可逆。

## 6. 建议（2026-10-31 第二次修订：按「真实危害」而非「安全最佳实践」排序）

### 先撤掉两条我编出来的优先级

| 我之前的说法 | 为什么站不住 |
|---|---|
| 「评委观感风险」 | **凭空假设了一个评审场景**。当前没有比赛，也没人看这个仓。拿它当优先级依据是错的。 |
| 「P0 重写历史」 | 历史里的 flag 是**已结束赛事**的答案，这类答案本来就是公开知识（各队 writeup 满网都是）。花大代价重写历史，换不来实际收益，还要让所有并行分支失效。**不做。** |

### 重新定义问题：这不是「泄露」，是「评测可信度」

没有外部读者时，明文 flag 的唯一实际危害不是"被别人看到"，而是：
**agent 在评测时能看到答案 → 你以为求解器很强，其实它在抄。**
也就是你点名的"训练时答案泄露"——它是**内部测量失真**，不是外部泄露。

### 修订后的排序

| 优先级 | 动作 | 依据 |
|---|---|---|
| **P0（唯一真 P0）** | **轮换两把在产 key**（千问 `sk-ws-` + 飞书 `app_secret`） | 与比赛无关。10-13 泄露，10-15 仍记「连续三天未轮换」，此后无轮换记录。明文就在 `.workbuddy-ai/memory/2026-10-13.md`。 |
| **P1** | **评测隔离**：跑 eval 时 agent 不可见答案文件（真值只在仲裁侧，不进 agent 上下文） | 这才是"训练时答案泄露"的真实入口 |
| **P2** | 测试夹具改合成答案 / 生成器禁内联 | 降低污染面，但属卫生项 |
| **P2** | 哈希升级为 HMAC+仓库外密钥 | 只有"要对外分发 benchmark"时才需要 |
| **不做** | 历史重写 | 收益≈0，代价=所有分支失效 |

### 附：一处事实更正
第一版把 `.workbuddy-ai/memory/2026-10-25.md` 里那段 RSA 私钥头报成"真私钥"。
实测该行上下文是 **PyCryptodome 自带的标准测试向量**（正文以 `MIIfake` 开头），是假阳性。
真正需要处理的是那把 `sk-ws-` 在产 key，不是这份测试向量。

> 顺带一个现场教训：本文件第一次提交时，因为上面这句话**照抄了 PEM 头部的字面量**，
> 被 pre-commit 的 secret_guard 判成"PEM 私钥"并**拦下提交**。
> 一份讨论"怎么不泄露"的文档，自己泄露了一个（假的）密钥头 —— 这说明**形态判据不区分真假**，
> 也说明"文档里引用密钥片段"这个动作本身就是泄露面的来源。故此处改为描述而非照抄。

## 7. 需要拍板的事（第二次修订后）

1. **两把在产 key 什么时候轮换**：这是唯一与比赛无关、且现在就有实际危害的事项。
   你在控制台换，我负责把 `.workbuddy-ai/memory/`、`config.yaml.bak-*` 等处的明文清干净。
2. **评测隔离怎么做**：跑 eval 时把答案文件从 agent 可见范围移走（换目录 / 换挂载点 / 只给仲裁侧）。
   这条决定"你的评测结果可不可信"。
3. 其余（夹具合成答案、哈希升级、历史重写）都不是当务之急，按需再做。

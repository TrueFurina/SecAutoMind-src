# 三创赛答辩 Q&A 预案（v0.1 · 2026-10-25）

> 用法：答辩前的弹药库。每条答案按"30 秒口播版"写，后面挂证据文件——
> 评委追问任何数字，30 秒内给出处。原则与项目文化一致：**不编、不绕、不吹**。

## A. 技术类

**Q1：这和"让 ChatGPT 帮我写脚本"有什么区别？**
A：三个区别。① 它有 194 个确定性求解器——常见题型（编码、RSA、古典密码）是算出来的，
不是"想"出来的，零 token 成本、毫秒级、结果可复现；② 它是多智能体协同——4 个模型并行
攻一题，中间发现实时共享，有失败退避和止损，不是一次对话硬刚；③ 它有证据门禁——
每一步可审计，结论可复算。ChatGPT 给你答案，我们给你**可验证的答案生产过程**。
【证据：一页纸四层架构表】

**Q2：大模型不是号称很强吗，为什么还要"确定性求解器"？**
A：因为我们实测过。主链路 LLM 自主推理在我们的 heldout 基准上是 0/17——14 道 external
全失败。这不是模型不行，是"裸模型+长上下文"这个形态不行。所以我们的架构是：
确定性能力做矛（能算的绝不让模型算），模型做它擅长的（难题探索、模式识别）。
【证据：2027决赛作战规划 §2；注意只引用修正后的 5/41 口径，9/17 已证伪永不再引】

**Q3：多智能体之间怎么协作？会不会互相干扰？**
A：协作靠消息总线：solver 的中间发现写成 findings，同题的其他模型下轮自动注入；
调度上静态题并行、容器题串行（平台同时只给 1 个环境槽）。干扰确实发生过——快闪赛时
多个会话各自启动引擎，新实例把别人的容器当孤儿删了。这个事故当晚就变成了
**跨会话租约机制**：一场比赛只有一个引擎，心跳 60 秒过期自动接管。
【证据：backend/runner_lease.py + 测试 7 用例】

**Q4：反注水是什么意思？**
A：防"自己考自己作弊"。早期我们的判分函数有个 bug：flag 字段匹配时没穷举所有形态，
导致 `flag{program}` 这种占位词被当成"解出"——9 道"解出"里 7 道是假的。我们发现后
明文规定"9/17 永不再引用"，只认 sha256 真值闭环。现在 26 个基准集每个都带反注水断言，
标准库打不通的解法不许算对。**主动拆自己的台，是这个系统最硬的功能。**
【证据：evidence/presolve_9of17_pollution_20261008.md】

**Q5：你们本地模型为什么跑不动？是不是技术不行？**
A：对，就是不行，而且我们花了 4 个模型逐个实测封了档：qwen3.5:9b 跑到第 2 轮把工具
调用写成 XML 文本、llama3.1:8b 产不出结构化输出、deepseek-r1 不支持工具、
qwen2.5-coder 全程文本伪命令。16G 显存封顶 14B 模型，驱动不了这套完整栈。
我们把这份失败报告原样存档——**知道边界比假装全能可信**。
【证据：P0_HANDOFF.md §6.1】

**Q6：系统现在最薄弱的环节是什么？**
A：两个。① 长链路推理题（Pwn 的复杂利用链）仍依赖前沿闭源模型，本地无替代；
② 练习场（无比赛期间的刷题通道）平台只给了 MCP 接口，引擎还没接——
这是我们自己发现的、排在下一版的真实缺口。
【证据：memory 2026-10-25 练习场探坑记录】

## B. 商业/价值类

**Q7：商业模式是什么？谁付钱？**
A：三条路，按优先级：① 赛事服务——给企业/高校做"AI 战队"参赛与培训（已有真实战绩背书）；
② 安全能力评估——把确定性求解器阵列用作漏洞模式检测的规则引擎（194 个求解器本质是
可执行的漏洞知识库）；③ 教学内容——CTF 培训市场的智能化教具。当前阶段我们不虚构收入，
用比赛名次和可复现证据说话。
【证据：一页纸路线图；注意：本条为方向性表述，财务预测不做无依据展开】

**Q8：这和商业漏洞扫描器有什么区别？**
A：定位不同。扫描器回答"你的系统有没有已知漏洞"——资产维度、合规维度；
我们回答"面对一个新构造的难题，AI 能不能独立解出来"——能力维度、攻防维度。
CTF 题是安全能力的纯粹试金石：没有"讲故事"空间，机器判分，行就行不行就不行。
【证据：一页纸"问题"节】

**Q9：为什么打 CTF 而不是做真实渗透测试？**
A：CTF 是能力度量的标准化考场，也是合规的风险隔离带——我们在合法靶场里把能力练到极致，
再向真实场景迁移（求解器的漏洞模式识别就是迁移路径）。另外坦白说：真实渗透的授权与
合规成本，不是当前团队能承担的，我们不装这个能。
【证据：Runbook 的合规表述；诚实人设】

## C. 竞赛/证据类

**Q10：1049 分、47 名，是不是不高？**
A：看口径。那是 AI Agent 赛道，9 题全解是完成度满分；分数排名靠起跑速度——
前 8 名同样 9/9，分差只有 25 分，等于晚解 7~10 分钟。我们那晚前 30 分钟还在修引擎
启动问题。真正说明问题的是：**全场只有我们把自己的失败（25 次提交、两次猝死）
逐条变成了当晚入库的纪律和代码**。
【证据：1024快闪赛复盘；名次口径以平台为准】

**Q11：羊城杯听说你们 0 分？**
A：是，交了最贵的学费：6 个答案第 3 分钟就基本到手，但连续 25 次提交失败——
原因是 flag 带了外壳，平台只认裸内容。这个教训当天就变成了三样东西：
提交格式注册表（每平台实测登记）、"通道先于解题"铁律、以及赛前预检脚本的凭证维度
（以前的预检在没令牌时也打印 GO，这个 bug 也修了）。**0 分那场教会我们的，
比 1049 分那场更多。**
【证据：URGENT_提交格式_裸内容.md；preflight_ctf.py】

**Q12：你们和开源项目 ctf-agent 什么关系？是拿来的还是自研？**
A：双轨，说清楚：SecAutoMind 主仓是我们自研的体系（194 求解器 + 26 基准集 + 25 项
门禁，羊城杯用它打的）；快闪赛我们接入开源标杆 verialabs/ctf-agent 打了一个对照——
结论是"直接用最强开源标杆"的决策被实战验证（它拿到了 9/9）。我们对它的定位是
**外部引擎资产、生态融合**，不是冒充自研。主侧自研的教训（羊城杯 0 分）和外部引擎的
战绩（快闪赛 1049）我们都如实归档。
【证据：1024快闪赛复盘 §一；融合副本 MIGRATION 文档】

## D. 团队/执行类

**Q13：一夜两次系统被杀，说明什么？**
A：说明我们的战场是真实 Windows 开发机——16G 内存被 5 个 IDE 分食到只剩 887M，
4 模型 swarm 直接把提交内存压爆，Windows 静默击杀（零日志）。当晚的产物是内存韧性
守卫：起飞前检测，<1G 拒绝启动、<2G 自动压模型。**能在这种环境下活下来的系统，
比 Demo 环境里的值得信。**
【证据：backend/memguard.py + 5 档测试】

**Q14：团队怎么分工？**
A：（按实际填写——此处预留。建议表述：算法/求解器、引擎/基础设施、证据与门禁文化
三个角色，互相用门禁卡对方——我们的 commit 要过六道检查，包括"诚实口径"检查。）

**Q15：比赛结束了，你们现在在干什么？**
A：回放验证——把赛时没解的题重新喂给引擎，用胜利验证改进、用失败定位环境账。
首批 3 题（10-25 实跑）：12082 就是坑了我们 25 次提交那道题，**agent 独立解出全部
六问**，包括人工卡住的 PAT 令牌重组；另 2 题受阻，归因诚实：图片题需要视觉模型、
ML 题沙箱缺 torch——都是环境账，不是接线账。而且网关缓存命中后单题成本近零，
这个"比赛→复盘→回放→加固"的循环可以一直转到决赛。
【证据：ctf-agent/benchmarks/ycb2026_replay/results.md】

## 使用注意

- 每条答案的"30 秒口播版"是骨架，别背稿；证据文件路径要能在 30 秒内调出。

## 1. 现状基线（本机实测，2026-10-23）

### 1.1 求解器体系
```
$ grep -rh "RegisterSolver(SolverEntry{" internal/ctfplatform/ | wc -l
189
按分类：Misc 56 / Crypto 51 / Web 26 / Rev 18 / Pwn 14 / All 3
```
- 证据包口径「130 真求解器」与注册表 189 的差 = **提示器/检测器**（关键词命中返回 hint，不返回 flag）。
- 已实测确认的提示器（读码实证，非猜测）：`lattice`、`lattice_lll`、`lattice_keywords`、
  `polynomial_discrete_log`、`crypto_algorithm_detect`、`advanced_crypto`——
  函数体是关键词表循环，返回 `格基攻击: <hint>` 字符串（`presolve_crypto.go:539-580`）。
- **真求解器**覆盖的经典模式：RSA（small e / Wiener / 共模 / Håstad 广播 / oracle）、
  ECDSA nonce 复用、Pohlig-Hellman、LFSR/LCG/mt19937 预测、CRC32 伪造、padding oracle、
  hash length extension、DES/AES-ECB、经典密码 + 编码族（base16/32/45/58/62/64/85/91、morse、braille…）。

### 1.2 诚实能力口径（既有结论，勿再注水）
| 尺子 | 数字 | 性质 |
|---|---|---|
| 静态真题 55 题 | **真求解器 16/55 = 29.1%**（保分母剔 4 伪解） | 已饱和，只作回归 |
| 外部尺 Google CTF 2021–2025 | **0/40**（crypto 26 + misc 14） | 真实差距：LWE/格/ECC/mceliece/zkpok 级 |
| LLM 自主解题 13 web 靶机 | **4–6/13**，构造类 ≈0 | prompt 工程已证伪（10-05 定格） |
| 自研 72 题集 | 真求解器 55/72 = 76.4% | 开卷，不作能力证据 |

### 1.3 架构现状（与外部标杆对照的面）
- presolve 扇出（0 token）→ 命中即短路（`integrator.go:84 SkipAgent`）→ 未命中进 Agent。
- Agent 工具面：MCP 注册（ctf_* 确定性工具族 + read_file/grep/nmap/hydra/nuclei + **exec/execute shell**）。
- eino ADK 多 agent 框架就绪（`internal/multiagent/`，40+ 文件）。
- flag 验证：`internal/flagverify` 存在（sha256/形态校验）。

## 4. 深化计划（P0–P3）

### P0 — 不动架构、冻结窗前必须完成（预期收益最大）

> 排序依据（外部实证收敛）：**确定性求解器覆盖 > Agent 编排花活**。
> NYU-CTF 200 题中 rev/crypto/misc/forensics 共 142 题是静态结构化题型，
> 而 2026-05 CRAKEN 榜首也只解出 rev 14/51、crypto 8/52——**头部空间最大的就是这 142 题**。

**P0-1 代码执行沙箱桥（CTF 治理化）**
- 做什么：给 Agent 的 exec/execute 加 CTF 场景系统提示段——「先用现成工具/模板，禁止从零推数学；
  禁网；每个脚本必须 print 候选 flag 并过校验」；附依赖探测清单（python3/sage/pwntools/gmpy2）。
- 为什么：外部实证最一致增益源（ChatGPT Agent +58pp、EnIGMA ×3、Kali 52% vs Ubuntu 42.5%）。
- 形态：prompt/配置级，**不动 internal/ 架构** → 不触发冻结门禁、不触发证据包漂移。
- 附带：**模型分流**（KryptoPilot 实证：常规子任务中档模型、仅 L3–L5 难题调强模型，省 35% 成本）
  + **预算熔断**（防 ⑩ 难度悬崖：单题 token/步数上限，超了换题不空烧）。
- 验收：13 题评测里 1–2 道构造类从 0→1（同通道可比）；沙箱缺 Sage 时优雅降级不崩。

**P0-2 密码攻击模板库（Python/Sage，含参数提取说明）**
Coppersmith 小根 / HNP-ECDSA 格恢复 / 截断 LFSR（Berlekamp-Massey+格）/ Boneh-Durfee /
BSGS+Pohlig-Hellman DLP / Håstad 广播统一入口。后续按 CRAKEN 差距补 rev/misc/forensics 静态类。
- 为什么：AICrypto 实测 LLM 单独 lattice 8.3–25%，Sage 模板可覆盖；KryptoPilot 证明
  「治理化调用 Sage」是正解；我们 Go 侧重写 LLL 是重复造轮子。
- 红线：模板用**合成参数**，禁止任何真 flag 入库（PUBLIC 仓铁律）。
- 验收：模板自测（合成题各解出 1 次）+ 变异用例（参数不满足前提时须报"不适用"而非瞎跑）。

**P0-3 MCP 硬约束层**
- 做什么：CTF 工具调用过 schema 强校验 + 环境事实源（文件/进程/连接状态以工具返回为准，
  禁止 LLM 声称"已读取/已连接"而无对应工具记录）。
- 为什么：STRIATUM-CTF 实证这套组合拿下真实多队 CTF **第一**；D-CIPHER VI-B 日志显示
  **幻觉文件/函数/服务端是工程失败主因**（失败模式 ⑨⑪）；我们 MCP 面已就绪，只缺硬约束。
- 验收：变异测试——LLM 输出引用不存在的文件路径时，编排层必须打回而非放行。

**P0-4 LLM 通道 failover**
- 做什么：多 provider 配置（官方/AMD/OpenRouter 类）+ 启动预检探针（发最小请求探活）+
  失败自动切换 + 开赛前 preflight 列出通道健康表。
- 为什么：10-05 实测全通道 402/403/404 是决赛级风险；跨通道数字不可比（DeepSeek 官方 38% vs OpenRouter 15%）。
- 验收：模拟主通道 402，预检报 NO-GO 且切备用通道跑通 1 轮。

### P1 — 架构小改（收益大，须排在冻结窗外）

**P1-1 攻击向量编排层**：hint 求解器 → 结构化「攻击假设」对象（attack_type + preconditions +
所需参数 + 验证方式），随题面注入 LLM。治失败模式①②（两路调研共同头号失败模式）。
**P1-2 交互会话状态**：exec/execute 从一次性命令升级为**有状态会话**（cwd/变量/连接跨步保持），
EnIGMA 实证 ~3×（11%→36%）、STRIATUM-CTF 治独白与上下文漂移（失败模式 ⑨⑪）。
**P1-3 交互 oracle 链路化**：padding_oracle 单点 → oracle 编排客户端（LSB/MSB 自适应 + 明文恢复），
治「把 oracle 当静态解」。
**P1-4 确定性验证后置**：确认 LLM 路径的候选 flag 一律过 `flagverify` 才提交（治失败模式⑤）。

### P2 — 策略层（不动求解器）
**P2-1 pass@k 提交策略**：一题多路（确定性 → Sage 模板 → LLM）。前提：**先确认平台提交规则**
（扣分制则不可；羊城杯/西湖论剑规则需赛方确认）。InterCode-CTF 实证 +13pp。
**P2-2 难度路由**：静态/编码类全自动；构造/pwn/高级 crypto 走深度模式（Cybench 分层实证）。
**P2-3 本地程序化基准**：Random-Crypto 模式（程序合成题库做回归）——静态 55 题已饱和，
新能力没有尺子量 = 盲飞。

### P3 — 重投入（赛后/冠军赛周期）
RL/蒸馏训练（Random-Crypto 0.35→0.88 实证有效，算力门槛高）；多 agent 深度分工（边际 5–8pp，最低优先）。

## 6. 决策点（must-confirm-before-acting）

1. **P0 是否现在启动？** 全部为非 internal/ 形态，不触冻结门禁；但模板库要入 git（PUBLIC 仓，需过 secret 扫描）。
2. **Sage/Python 依赖策略**：软探测（有则用，推荐）vs 交付包打包依赖（破坏单文件分发红线）。
3. **LLM 通道预算**：AMD 免费通道是否仍可用（10-05 时可用）；是否值得为 pass@k 买多通道。
4. **pass@k 的平台规则**：需向赛方确认提交是否扣分——不问清就实现 = 可能反向送分。

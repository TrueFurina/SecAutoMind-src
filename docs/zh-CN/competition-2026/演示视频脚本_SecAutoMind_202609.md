## 2. 分镜明细

### S1 开场（0:00–0:30）
- **画面**：深色标题卡，logo 出现。大字："SecAutoMind —— 具备自主决策能力的通用网络安全智能体平台"。
- **旁白**："我们提交的作品，是一套把任务理解、多智能体决策、工具协同与安全管控串成完整闭环的网络安全智能体平台。它不止能打点，还能复盘、能审批、能讲清楚每一步为什么这么做。"
- **字幕要点**：赛题编号 XH-202609；"通用 · 自主决策 · 可解释 · 合规可控"。

### S2 架构快闪（0:30–1:10）
- **画面**：架构分层图逐层点亮：接入层（Web/机器人/API）→ 编排层（单代理/Deep/Plan-Execute/Supervisor）→ 执行层（143 运行时工具/外部 MCP/Skills）→ 横切层（HITL/Monitor/Audit）→ 数据层（SQLite）。
- **旁白**："三层接入、四种编排、四层插件化工具池，外加 HITL 审批、监控与审计两条横切链——这是我们架构的核心。"

### S3 启动与安全默认（1:10–2:00）
- **画面**：双击 `secautomind-ai.exe`（或 `start.bat`）；控制台打印引导管理员密码一次；浏览器开 `http://127.0.0.1:8080`。
- **旁白**："150MB 单文件、零外部依赖启动。默认只监听本机回环地址；管理员密码随机生成、仅打印一次、不落盘——安全默认内置，而不是靠配置自觉。"
- **字幕**：`server.host: 127.0.0.1`；`config.yaml` 不入库、密钥走环境变量。

### S4 任务理解：自然语言下任务（2:00–3:00）
- **画面**：聊天窗输入（示例任务）："对 10.0.0.0/24 做攻击面枚举，找到对外开放的 Web 服务并评估风险，输出报告"。Agent 先展示拆解后的执行计划（thinking/planning），再逐步执行。
- **旁白**："我们验证的正是赛题核心——自主决策：模型先拆解、再选工具、循环执行，并实时把推理链推给你看。"
- **证据点**：时间线出现 planning 结构 + recon 工具事件。

### S5 工具协同（3:00–4:10）
- **画面**：放大多工具串联片段：nmap 扫描 → 服务识别 → 指纹/漏扫 → 证据汇总；每个工具卡片带状态、耗时、结果摘要。
- **旁白**："90 个 YAML 内置工具按攻击面组织，工具结果自动摘要压缩回填上下文，长任务不爆上下文；不够用时还能接任意外部 MCP 系统。"
- **证据点**：前端时间线 tool 事件流连续、无人工干预。

### S6 HITL 人机协同（4:10–5:10）
- **画面**：Agent 请求调用高危工具 → 弹出审批卡片（参数/风险说明）→ **先点拒绝**，Agent 换思路 → **再触发一次审批并放行** → 展示审计页该条审批与执行记录。
- **旁白**："终审是队员与 AI 协同解题。我们的 HITL 让每一步高危动作都过人工这一关——批准、拒绝或编辑参数，全程留痕。这既是安全边界，也是'人机协同'的产品化。"
- **字幕**：approval / review_edit；audit 记录。

### S7 多智能体编排（5:10–6:20）
- **画面**（二选一，录已跑通者）：
  - A：Supervisor——"派一个子代理去查这个域名的历史漏洞情报，另一个去评估 Web 暴露面"→ 观察 supervisor 把任务转派给不同专家子代理并汇总结论；
  - B：Plan-Execute——目标明确的多步任务，展示 规划→执行→重规划 闭环。
- **旁白**："三种多代理编排——Deep 拆解协作、Plan-Execute 规划闭环、Supervisor 专家路由，全部走同一条可观测链路；子代理用 Markdown 定义，Web 界面即改即用。"

### S8 通用场景：应急响应（6:20–7:10）
- **画面**：切换到 incident-response 子代理，演示一个应急场景（如"收到告警：某 Web 服务疑似被植入 WebShell"）：分析告警 → 定位 → 取证 → 处置建议 → 加固，最后调用 reporting 输出报告。
- **旁白**："'通用'不是口号：从攻击面枚举、渗透、到应急响应、防护加固与报告整改，18 个角色化子代理覆盖攻防两侧的同一平台。"

### S9 扩展性 30 秒（7:10–7:50）
- **画面**：现场新建 `tools/my-ffuf-rate.yaml`（或任意简单命令工具）→ 无需重启 → 下一轮对话 Agent 即能调用。
- **旁白**："加工具 = 加一个 YAML 文件；加子代理 = 加一个 Markdown；接系统 = 配一个外部 MCP。扩展门槛被压到最低。"

### S10 可解释回看（7:50–8:30）
- **画面**：Audit/Monitor 页面按会话回放整条决策链：请求、思考、工具事件、HITL 决定、最终答复、模型用量。
- **旁白**："赛后复盘、评委核验，都能回到每一条决策的时间线。"

### S11 （可选）钉钉给智能体下任务（8:30–9:10，条件分支）
- **画面**：手机钉钉企业应用内给机器人发消息（文字/图片）→ 平台执行 → 钉钉回执结果。
- **前置条件**：**已取得真实钉钉开放平台应用 `DING_APP_KEY` / `DING_APP_SECRET` 并配置成功**（走 Stream 长连接，无公网回调）。
- **备选画面（无真实凭证时）**：不拍摄该场景；改为 10 秒画面展示 `config.example.yaml` 中钉钉占位配置 + 启动日志中"凭据缺失→通道软禁用→主服务正常"的降级行为，旁白说明："机器人通道凭据走环境变量注入，凭据不全时优雅降级、不影响主服务——演示现场可随时配置接入。"
- **判断标准**：录制前 3 天仍无可用凭证 → 采用备选画面，避免现场翻车。

### S12 结尾（8:30–9:10 或 9:10–9:50）
- **画面**：工程证据卡：`go vet` exit 0 / 36 包测试全绿 / 三平台构建；对照实验结论（若有）；感谢页。
- **旁白**（模板，数据须替换为实测）：
  - 工程面："静态检查零告警、26 个 Go 包全部测试通过、三平台原生构建，工程质量可复现。"
  - 效果面（**如已跑出受控靶场对照实验则播报真实数字**，如"在 N 个靶场任务上，supervisor 编排较单代理成功率 X%→Y%"；否则只说工程结论，不报数字）。
- **结尾字幕**："SecAutoMind · 让每一次安全决策可见、可控、可追溯。"

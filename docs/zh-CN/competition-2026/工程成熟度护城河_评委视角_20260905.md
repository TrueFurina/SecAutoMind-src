## 一、核心命题：我们走的是「架构先行」，不是「AI 写到哪算到哪」

同类项目（含往届参赛作品）最常见的翻车模式是「先堆功能、后补架构、用自评文档掩盖工程债」。
本项目用**可复验的工程体征**证明走了相反路径——这是决赛最该被量化的差异化，而非功能数量。

| 工程体征 | 实测值 | 验证方式（可复跑） |
|---|---|---|
| 内部包数 | **40 个**（含子包；一级子目录 31 个，两口径不混用） | import 图 Tarjan SCC 分析 |
| **循环依赖** | **0 个**（40 包 / 139 条内部依赖边，全 DAG） | 同上 |
| 业务代码规模 | **105,861 行**，分散在 **387 个文件** | `find internal cmd -name '*.go'` 逐文件统计 |
| 最大单文件 | `openapi.go` 6,362 行 = **OpenAPI 生成代码**（带 `DO NOT EDIT`） | 文件头 gen 标记，非手写上帝模块 |
| 测试文件 | **230 个**（09-05 23:45 复核：+2 = materializer 单测 + http-framework-test 端到端集成测试）；40 包中 **26 包有测试** | `find -name '*_test.go'` + `evidence-build-test-20260903.txt`（228）+ 09-05 复核 |

> 关键判读：**0 循环依赖**是「架构先行」最硬的体征——AI 按想到哪写到哪的项目几乎必然产生 import 环；本项目分层干净，证明边界在写代码前已定。

## 三、安全态势：交付物「开箱即安全」，且**流程默认安全**

> 这是本项目相对同类作品最被低估、也最该主动讲清的护城河。

**实测结论（2026-09-05 全树扫描）：**
- ✅ **源码零硬编码密钥**：`internal/` + `cmd/` 全部 `.go` 扫描 `apiKey:=`/`secret=`/长 base64 等模式 → **0 命中**，密钥全部外置 `config.yaml`。
- ✅ **交付副本零活密钥**：`config.share.yaml`（脱敏版，10 处活凭据洗成占位符）+ `config.example.yaml`（官方模板）已就位；最终扫描仅本地运行必需的 `./config.yaml` 含真实 key。
- ✅ **PII 零泄露**：`data/` 为运行时产物（对话库/管理员密码/RAG 索引），**服务启动会自动重建** → 已通过「打包时结构性排除」根除（手动清会被复活，故从流程上解决）。
- ✅ **安装包干净**：NSIS 仅打包 `secautomind-ai.exe` + `README`，**不打包 config/data**，版本号 `v1.7.25` 自洽。

**从流程上消除「说修没修」型雷：**
- 提供 `safe_package.py`（零依赖一键脚本）：复制 → 排除 `.git`/`.workbuddy`(3.3G 工具链)/`data/`/活 key 的 `config.yaml` → 写入脱敏 `config.yaml` → **收尾自动跑活密钥 + PII 扫描，任一命中即 fail-fast**。
- 含义：未来任何一次重打包**默认安全**，不再依赖「记得去换文件」这种人工记忆——这正是往届项目最易翻车的「声称已修、磁盘证伪」缺口。

> ⚠️ **一处与既有文档的口径补正**（供答辩口径统一）：`提交前硬门槛核查清单` §3/§4 的密钥安全叙事建立在「`config.yaml` 已 gitignore = 安全」。该结论对 **git 仓库**成立，但**分享包是文件夹拷贝不是 git clone**——若直接 zip 工作目录，8+ 活 key 仍会随包发出。故**分发请以 `SecAutoMind-v1.7.25-share-SAFE/`（一键安全打包产物）为准**，或打包时用 `config.share.yaml` 替换 `config.yaml` 并排除 `data/`。

### 1.1 执行层真实能力（Agent 真跑工具 + 真打靶机）★ 本会话新增，冠军差异点

> 西湖论剑类关键词求解器的天花板即「静态集」：文本里没有密文/附件就解不出。
> SecAutoMind 额外验证了 **Agent 真的能跑工具、真的能打靶机**——这是确定性之外的能力维度。

| 执行求解器（Go 等价实现） | 等价真实工具 | 基准集题 | 验证 |
|------|------|------|------|
| `exec_strings` | `strings` + flag 扫描 | exec_strings（flag 藏二进制可打印串） | Go 6/6 + Py 8/8 |
| `exec_git_history` | `git log -p --all` | exec_git（历史泄露 flag） | 同上 |
| `exec_web_source_audit` | 查看网页源码→base64 解码 | exec_base64_source | 同上 |
| `exec_cookie_decode` | 解码 Cookie base64 | exec_cookie | 同上 |
| `exec_endian_swap` | 大小端反转 | exec_endian | 同上 |
| `exec_pcap_http` | `tshark` 抽 HTTP POST 体 | exec_pcap | 同上 |
| `exec_rsa_small_e` | RSA e 次根开根（牛顿法） | breizhctf2022_rsa / nahamcon2024_rsa（小指数） | 同上 |
| **live_sqli** | 真实发 `admin' OR '1'='1` | 本地脆弱靶机登录绕过 | Go `TestLiveExploitation` 真打 |
| **live_ssti** | 真实发 `{{flag()}}` | 本地脆弱靶机模板注入 | Go `TestLiveExploitation` 真打 |

- **双语言机验**：Go 侧（`presolve_execution.go` 7 求解器 + `TestExecSolversAgainstBenchmark` 文件型 6/6 + `TestLiveExploitation` 实时 2/2）与 Python 侧（`judge_exec.py` 8/8）算法一一对应，任一侧漂移立即暴露。
- **诚实边界**：8 道执行题的 flag 由「真实工具执行结果」派生并经 SHA-256 校验，非关键词猜中。
- **接线状态（诚实声明，2026-09-07 更新）**：
  - ✅ **已接线**：7 个 `exec_*` 求解器已加进生产 `Presolve` 硬编码并行扇出（`presolve_misc.go`，commit `80bd795`），`integrator.go:73` 实际调用路径现在会跑它们。其中 `exec_rsa_small_e`（RSA 小指数开根）在**仅 description** 场景即实打实算出 `breizhctf2022_rsa` / `nahamcon2024_rsa` 两道真 flag，把生产路径覆盖率从 17/55(30.9%) 抬到 18/55(32.7%)；随后 `tryB64AlphabetCaesar`（Case64ar 型，commit `4ce58ef`）实打实解出 `sdctf2021_case64ar`，抬到 **19/55(34.5%)**。
  - ✅ **Tier 2 已激活（commit `e66f361`，不再休眠）**：生产 handler `agent.go:900` 虽仍传 `nil` 附件，但聊天上传链路会把附件绝对路径以 `[用户上传的文件]\n- 文件名: 绝对路径` 形式拼进消息文本。新增 `presolve_attachment.go` 在 `Presolve` 入口识别并读回这些真实文件、灌进 `attachments`，**6 个需附件的 `exec_*`（strings/git 历史/网页源码/Cookie/大小端/pcap）现已能吃到底层二进制/文本并解题**。全程未改任何函数签名、未动 handler（零并行会话冲突）。
    - 安全约束：路径强制落在 `cwd/chat_uploads` 之下（`EvalSymlinks` + 前缀校验防穿越），单文件 4 MiB 上限、最多 10 个，越界/过大静默跳过。
    - 端到端机验（`presolve_attachment_test.go`，全部复刻生产 `nil` 附件调用方式）：① 上传含 flag 的二进制 → 生产 `Presolve` 直接解出 `flag{upl04d_4tt4chm3nt_r34l}`；② 上传 pcap → `exec_pcap_http` 专项从上传附件还原 `flag{upl04ded_pc4p_r34l}`；③ 越界路径（系统临时目录）→ 拒绝读取，无路径穿越。
  - ℹ️ **剩余口径说明**：description-only 基准集（55 道真题，无上传文件）下这些附件型求解器仍不触发，故静态覆盖率 19/55 不受影响——它们由「真实上传附件」场景的独立端到端测试证明。
  - ⚠️ **注册表路径缺陷仍存**：`PresolveWithRegistry`「首个非空即返回」缺陷未修（诊断提示会被当命中，实测 55 题仅 21.8% < 硬编码 34.5%）；当前生产走硬编码 `Presolve`，该缺陷不影响交付。

### 1.2 Web 目标自动利用（Agent 真攻 Web 站点）★ 冠军差异点

静态基准集 55 道里**未命中的 36 道中有 20 道是 Web 题**——它们的 flag 只存在于靶机响应里，
任何"读描述猜答案"的关键词求解器（西湖论剑类）结构性拿不到。本能力把这条断层补上。

**实现**：`internal/ctfplatform/web_exploit.go` —— `ExploitWebTarget(ctx, baseURL)` 对任意 URL 跑完整渗透链：

| 阶段 | 能力 | 对应真题题型 |
|------|------|------------|
| 1 资产发现 | 首页 + 13 个常见路径探测 | pico2024_intro_to_web / findme / not_my_fault |
| 2 被动收集 | HTML 注释 / 隐藏域 / base64 段落 / Set-Cookie 解码 | pico2024_webdecode / cookie / pico2025_cookie_monster |
| 3 SQLi | 7 种登录绕过载荷（POST+GET 双形态） | pico2024_irishname / matchfix / buuctf_sqli_basic |
| 4 SSTI | `{{7*7}}→49` 确认模板执行后再上 `{{flag()}}` 提权 | pico2025_echo_valley / ssti_tpl_inject |
| 5 LFI | 5 类路径遍历载荷 × 5 个参数名 | buuctf_lfi_basic |
| 6 SSRF | 回打内网 `/admin` 端点 | buuctf_ssrf_basic |
| 7 命令注入 | `;cat /flag` 等 4 类分隔符 | buuctf_rce_basic |
| 8 NoSQL | `$ne`/`$gt`/空对象运算符注入 | pico2024_no_sql_injection |
| 9 未授权 API | 直接请求敏感端点 | pico2025_handoff |

**机验结果（双语言一致）**：

| 验证维度 | 结果 |
|---------|------|
| Go `TestWebExploitAgainstRange`（对靶场实打） | **10/10 = 100%**（SHA-256 逐题校验） |
| Python `judge_web.py`（纯 stdlib 独立复刻） | **10/10 = 100%** |
| Go `TestPresolveAutoExploitsWebTarget`（生产路径） | ✅ 题目文本给出靶机 URL → 生产 `Presolve` 自动渗透交出 flag，`engine=web_exploit` |
| Go `TestWebExploitNoFalsePositiveOnCleanSite`（反例门禁） | ✅ 无漏洞干净站点 **0 命中**，无误报 |

**生产接线**：`Presolve` 新增 `web_exploit` 求解器（`ExploitURLsInText`）——题目文本里识别出靶机 URL 即自动渗透，
优先级置顶（`-1`，高于所有静态推导，因为 flag 由靶机真实返回而非推导）。
安全约束：单次最多 3 个 URL、每 URL 独立 25s 超时、仅 http/https、不做端口扫描，
可用环境变量 `SECAUTOMIND_WEB_EXPLOIT=0` 全局关闭（与执行器同为"授权安全测试工具、能力设计内"口径）。

**诚实边界**：靶场 `live_target/web_range.py` 是我方为机验复刻的本地脆弱站点（10 个场景逐一标注对应真题），
**不是**真实赛事靶机；它证明的是"渗透链对这 10 类漏洞形态有效且无误报"，不代表任意真实站点的通过率。

## 4. 线上战绩（诚实声明）

> **SecAutoMind 尚未参加任何正式 CTF 赛事线上对抗。**
> 本报告所有"解出/覆盖率"数据均指**本地离线测试**，不代表线上赛事得分。
> 137 个求解器中，大部分为**关键词模式匹配**（识别"这个文本提到了 RSA"），而非从密文数据实际解出 flag。
> 确定性算法求解器（base64 解码/凯撒爆破/XOR 爆破/RSA 费马/共模等约 15 个）可真实解题，但尚未经过正式赛事验证。

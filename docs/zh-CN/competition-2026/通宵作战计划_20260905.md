## 一、A 线：材料实测（02:40 → 05:30，冲初审 100 分）

### 1.1 实测环境：Docker 坏了，改用自建可复现靶场

**故障实况**：`docker info` → `npipe:////./pipe/dockerDesktopLinuxEngine` 管道不存在，Docker Desktop Linux 引擎未运行。

**替代方案（更优）**：自建**本地多场景靶场**，理由三条：
1. 报告第四章原本就用的 `127.0.0.1:8000` "本地授权演示靶场"——**口径天然一致，不是降级**
2. 在线靶场存在授权合规与不可复现风险；自建靶场 = 完全授权 + 脚本化一键重建 + 任意次重复，恰恰命中赛题"**可复现**"要求
3. 这本身可以写成加分项：*自建可复现评测靶场用于系统性验证*

**靶场设计（Python 单文件，零依赖）**：
- `S1 Web 综合靶场`：登录弱口令 + SQL 注入 + 反射型 XSS + 目录遍历 + 敏感文件泄露 + 目录枚举面
- `S2 API/云场景靶场`：未授权接口 + JWT 弱密钥 + 目录遍历 + 信息泄露响应头
- `S3 主机/服务场景靶场`：多端口服务指纹（SSH/FTP/Redis 未授权模拟）+ Banner 泄露 + 配置错误

每个靶场自带**真值清单（ground truth）**，供自动判分：预期漏洞数、预期可识别指纹、预期工具链路径。
→ 这让"环境识别准确率""漏洞发现率"从主观描述变成**可自动计算的客观数字**。

### 1.2 六组实验（每组直接对齐一个评分维度的 17-20 档要求）

| # | 实验 | 对齐维度与档位要求 | 采集指标 | 样本量 |
|---|---|---|---|---|
| E1 | **多场景识别准确率** | 维度①"多策略/深度理解"、维度③ | 环境类型/技术栈/指纹识别准确率 vs ground truth | 3 场景 × 5 轮 = 15 |
| E2 | **端到端推演成功率与耗时** | 维度①、维度③ | 成功率、端到端耗时、工具调用数、迭代轮次 | 每场景 ≥5 轮 |
| E3 | **可复现性**：同任务重复 3 次 | 维度③"逻辑可追溯、**可复现**" | 结果一致性（Jaccard）、耗时方差、结论偏差率 | 3 组 × 3 次 |
| E4 | **抗干扰/鲁棒性**：断网 / 模型通道故障 / 工具超时 / 目标不可达 | 维度③"**能有效应对干扰**" | 降级行为是否正确、是否静默失败、是否产生幻觉结论、恢复耗时 | 4 类 × 2 次 |
| E5 | **多策略对照**：Deep vs Plan-Execute vs Supervisor 同任务 | 维度①"**多策略选择和动态规划**"、维度⑤"验证创新" | 三模式成功率/耗时/token/工具数对比 → 证明"自动选型"优于"固定单策略" | 3 模式 × 3 任务 |
| E6 | **跨工具链协同**：多工具串联（≥3 跳，跨类别） | 维度④"**强大的跨工具链自动化编排与协同**" | 串联链长度、上下文传递是否无需人工搬运、成功率 | ≥5 条链 |

**E4 与 E5 是今晚最值钱的两组**：
- E4 直接命中维度③ 17-20 档唯一的硬门槛"能有效应对干扰"——目前**零证据**
- E5 是唯一能证明"按复杂度自动选型"这个创新点**真的有用**的实验——目前只有设计、没有对照

## 二、B 线：网关 + 3 人协同（05:30 → 08:00，备战 11 月 60%）

### 2.1 安恒 AI 安全网关适配器（H1）

**目标**：从"文档里说改 base_url 即可"→"代码里真有适配器 + 自检 + 降级"。

交付内容：
1. **网关配置段落地** `config.yaml`：
   ```yaml
   ai:
     gateway:
       enabled: true
       mode: henang_compatible      # 主办方网关（OpenAI 兼容）
       base_url: "${AI_GATEWAY_BASE_URL}"
       api_key: "${AI_GATEWAY_API_KEY}"
       model_map: { qwen-max: "<网关注册名>" }
       fallback_channel: qwen-max   # 网关不可达时的逃生通道
       verify_on_startup: true
   ```
2. **启动自检** `internal/config/gateway_preflight.go`：启动时打印生效配置快照（网关地址/通道/key 状态/逃生通道），网关不可达时**醒目告警 + 自动切逃生通道**，不静默失败。
   > 直接复用西湖论剑 08-22 的两件产物：`print_effective_config_snapshot()` 与 `CTF_AGENT_ESCAPE_PROVIDER` 逃生开关——那次初赛"30 分钟全灭"的根因就是单点环境变量 + fail-closed 无降级档，这个坑不能在一个比赛里踩两次。
3. **降级策略固化**：网关 5xx/超时 → 切备案直连通道 → 仍失败 → 进入只读模式并告警（**绝不静默重试、绝不返回幻觉结论**）。
4. **验收清单自动化** `scripts/verify_gateway.sh`：把 `ai-gateway-compliance.md` 第 62-67 行那 4 条人工勾选项，变成可自动执行的检查。

### 2.2 3 人 + Agent 协同作战模式（H2 前半）

赛题原文："要求各团队以'3 名队员 + 自研 AI Agent'形式现场协同解题""设置超出纯人工处理能力范围的赛题量"。

**这意味着现场真正的瓶颈不是"Agent 会不会解题"，而是"3 个人和 1 个 Agent 怎么分配超出人工能力的题量"。**

交付内容：
1. **作战席位模型**：3 个队员席位 + N 个 Agent 工作台，每席位可独立下发任务、共享同一事实黑板
2. **任务池与原子领取**：题量超出人工 → 任务入池 → Agent 与队员原子领取（防重复领取，西湖论剑踩过并发互踩：7410 次 stuck_loop）
3. **并行进度总览**：一屏看清每个任务的负责人（人/Agent）、状态、耗时、卡点
4. **冲突与降级**：并发上限、单任务墙钟硬限、卡死自动放弃并把任务退回池子
5. **协同全程入审计**：谁（人或 Agent）在何时领了什么题、做了什么、结论是什么 → 命中维度③"可追溯"

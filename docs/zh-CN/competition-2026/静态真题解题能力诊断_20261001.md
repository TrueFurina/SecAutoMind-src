# 静态真题解题能力诊断报告（2026-10-01 磁盘实测）

> 数据源：`data/ctf_benchmark/real_coverage_report.json` + `benchmark.json` + `all_benchmarks_summary.json`。
> 只诊断、不改代码。口径对齐 `count_stats.py` 单一真值源。

## 一句话结论

静态 55 真题命中 19/55 = 34.5%，但 **36 个 miss 里 0 个是「引擎存在但解错」，100% 是「缺载荷 / 没接引擎」**。
换句话说：所有已实现的求解器没有一个是坏的，34.5% 不是质量缺陷，是「题目清单里这些题要么没输入文件、要么没把引擎路由接上」。

## 36 个 miss 的三分类

| 分类 | 数量 | 含义 | 能否提分 |
|---|---|---|---|
| A. 自带密文、有现成真引擎 | 3 | 密文就在 description 里，引擎已存在，但判分时 `presolve_engine=null`（路由没接上） | ✅ 能真提分，非注水 |
| B. 只有一句文字描述、无真实输入 | 多数 | 如 `minirsa` 只有「RSA e=3」几个字、无 n/e/c；`stringsit` 只有「用 strings 提取」、无二进制 | ⚠️ 需先补真载荷才能解 |
| C. 引擎标 `flag_scan`（扫 flag 兜底） | 约 15 | 不是解题能力，反注水门禁会拦 | ❌ 不算真解出，禁注水 |

## A 类明细（原判「3 题可立刻接引擎」，已实测证伪，见下方更正）

> ⚠️ **更正（2026-10-01 实测）**：原判「3 题自带密文可接引擎」是**双重误判**：
> 1. 实际只有 `wolvctf2024_xor` 这 1 题 description 真带密文；`public_morse_image` 只有一句「图片隐写提取 Morse」（无图片文件）、`pico2024_webdecode` 只有一句「查看源码找 base64」（无源码/base64 串）——后两题属 **B 类缺载荷**。
> 2. `wolvctf2024_xor` 也不是简单单字节/重复密钥 XOR：实测反推 key = `"A string of text can be encr"`（28 字节，与密文**等长**），是**一次性 XOR（英语句子 key）**。现有 `tryXOR` 只做 hex 单字节、`tryVigenereAutoKey` 只做字母表维吉尼亚（模 26），都接不住字节级等长 key。要真解需**恢复完整英文句子 key（NLP/频率分析级）**，超出「接现成引擎」量级。

**结论修正：A 类「可直接接引擎真提分」的题实际为 0。** 34.5% 的 36 个 miss 全部要么缺载荷、要么是困难题（等长 key XOR / 隐写 / 内存取证等），没有「接个引擎就能 +1」的低垂果实。

## B 类补载荷的典型缺口（举例）

- `pico2024_minirsa`（rsa_small_e）：需补 n/e/c 三个大整数才能跑 `trySmallExponent`（引擎已存在）
- `pico2024_stringsit`（strings）：需补真实二进制文件
- `forensics_mem_volatility` / `forensics_pcap_http` / `forensics_disk_image`：需补真实内存镜像/pcap/磁盘镜像文件
- `pico2024_commitment` / `pico2024_gitcred`（git）：需补 .git 目录
- 大量 web 族（sqli/xss/ssti/upload/xxe/ssrf/lfi/rce/nosql/cookie/api）：这些**求解器文件都已存在**（`*_attack.go`），但静态集里缺对应靶机/请求上下文，无法离线判分

## 为什么不能简单「把 skill 字段从 auto 改成引擎名」提分

1. 真实基准题里 `presolve_skill` 大多写 `"auto"`，判分拿不到引擎 → 但这不代表改字段就能解：**题没有真实输入，引擎拿到空数据也解不出真 flag**。
2. 把「flag_scan 命中」算作「解出」= 注水，会被 `verify_evidence.py` 反注水门禁拦（记忆：`flag_scan_only=4` 已单独标注不算真解出）。
3. 真提升唯一路径 = **补真实载荷 + 接真引擎**，且每题 flag 必须 SHA-256 校验（`flag_sha256`），伪造会被抓。

## 建议的下一步（需你拍板，非我擅动）

1. ~~最小真提分（接 A 类 3 题）~~ → **已证伪**：A 类实际为 0，见上方更正。
2. **中等**：给 B 类里「能从公开 writeup 拿到真实密文/文件」的题补载荷（minirsa 的 n/e/c、strings 的二进制等），再接已有引擎——这是唯一真实的提分路径，但每题都要有真实来源、SHA-256 校验。
3. **不推荐**：为 flag_scan 或纯描述题强行造「可解」假象——违背项目反注水底线。
4. **若想啃 wolvctf_xor 这类「等长 key XOR」**：需新写一个「英语句子 key 恢复」求解器（已知明文前缀 + 英文单词频率分析），这是真能力扩展但工作量大、且属较冷门题型，投入产出需你权衡。

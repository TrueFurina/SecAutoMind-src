# 羊城杯 2026 · 双系统上膛启动卡（ycb2026.dasctf.com）

> 生成 2026-10-22。目标赛事：羊城杯 2026 初赛，平台 `https://ycb2026.dasctf.com`（DASCTF 家族，官方 AI Agent API 前缀 `/slab-match/api/v1/agent/`）。
> SecAutoMind 与西湖论剑的 API 契约完全一致，都可打这场。本卡只写**怎么上膛**；令牌与门户口令**不写入本文件**。

## 0. 两个前提（缺一不可，都得你侧解决）

1. **Agent 令牌**：两系统都只认请求头 `X-Agent-AccessKey` 的 `ak_` 令牌（走环境变量）。
   **网页门户的手机号+密码喂不进去**——不是同一套鉴权。去 `ycb2026.dasctf.com` 门户开通/生成 AI Agent 的 AccessKey（可能要短信验证码）。
2. **够得着平台的机器**：live 拉题/提交必须在能正常访问平台的机器上跑。
   （本会话沙箱无外网；服务器 `172.16.222.99` 探该域名被 WAF 挡回 **418**——出口 IP 被挡，非代码/证书问题。）

## 1. 共同环境变量（两系统通用）

```bash
export DASCTF_BASE_URL="https://ycb2026.dasctf.com"   # 只填 host，别带 /slab-match——驱动自己拼
export DASCTF_TOKEN="ak_xxxx"                          # 或 CTF_AGENT_PLATFORM_TOKEN，二选一即可
```

- SecAutoMind：`internal/ctfplatform/dasctf.go` 读 `DASCTF_BASE_URL` + `DASCTF_TOKEN`（回退 `CTF_AGENT_PLATFORM_TOKEN`）。
- 西湖论剑：`ctf_agent/config.py` 读同样三个变量（Windows 另支持 setx 注册表回退）。
- 两者请求都带浏览器 UA 降低 WAF 拦截；SecAutoMind 另有 403 WAF 冷却（`antiBlock`）。

## 2. SecAutoMind 上膛

```bash
cd /e/Program/SecAutoMind
export DASCTF_BASE_URL="https://ycb2026.dasctf.com"
export CTF_AGENT_PLATFORM_TOKEN="ak_xxxx"        # 或 DASCTF_TOKEN
source scripts/finals_arm.sh                      # 🔴 必须 source：设自动化开关 + 打印确认表 + 跑 finals_preflight.py 给 GO/NO-GO
```

- `finals_arm.sh` 现设 **7 个开关**（`CTF_POLL_ENABLED` / `CTF_AUTOSOLVE_SUBMIT` / `CTF_AUTO_BUILD_ENV` / `CTF_AUTO_FETCH_DETAIL` / `CTF_AUTO_FETCH_ATTACHMENT` / `CTF_AUTO_RELEASE_ENV` / `CTF_ROBOT_AUTO_PREPARE`，均默认 true，已设过不覆盖）。runbook 写的「6 个」是旧快照。
- ⚠️ 脚本的地址白名单只认 `pro.dasctf.com` 为「官方」；填 `ycb2026.dasctf.com` 会显示「⚠ 非官方域名，请与赛事通知核对」——**这是提示不是阻断**，核对赛事通知后继续即可。
- 预检 **NO-GO 就不要开赛**（阻塞项见脚本输出 / runbook §4 降级清单）。
- 设好 env + 预检 GO 后，按 `docs/zh-CN/competition-2026/决赛当天runbook_20260917.md` 起服务/poller（入口 `cmd/server`）。启动后 5 分钟内核对 runbook §1 的四个健康信号。

## 3. 西湖论剑上膛

```bash
cd /e/Program/西湖论剑/ctf_agent
export DASCTF_BASE_URL="https://ycb2026.dasctf.com"
export DASCTF_TOKEN="ak_xxxx"
export CTF_AGENT_LLM_PROVIDER="<provider>"        # 如 qwen / deepseek / baidu …
export <PROVIDER>_API_KEY="<key>"                 # 对应 provider 的 key（如 DASHSCOPE_API_KEY / DEEPSEEK_API_KEY …）
python run.py --mode platform --once              # 先单轮冒烟：拉题→解题→提交 一轮，看 accepted
# 稳定后去掉 --once 定时轮询：
python run.py --mode platform --interval 30
```

- `--once` = 单轮（冒烟用）；去掉即每 30s 轮询。
- `config.py` 导入即打印 provider/端点/模型/key 快照 + 清空代理变量；**先看快照确认 provider/key 没打错端点**，再开跑。
- provider 默认值是**静态的，不保证当前可用**（`config.py` 自带此纪律注释）；可用性以现场探测为准，显式指定更稳。
- 正确性以平台 `submit` 的 accepted 回流为准（本地题库答案会误伤 `DASCTF{}` 平台 flag）。

## 4. 建议顺序（别直接定时轮询开跑）

1. 两系统都先 `--once` / 冒烟，确认能拉到题、能提交、accepted 回流正常。
2. 无误后再去掉 `--once` 定时轮询。
3. SecAutoMind 盯 runbook §1 四健康信号；西湖论剑盯 `run.py` 的「平台对战汇总」。

### 0.1 Agent API 契约（2026-10-24 05:40 真机确认，不再是推测）

站点整体是 SPA（任意路径回同一 `index.html`，691 B 壳），但 **Agent API 前缀确实存在**，用两条对照即可分辨：

| 探测 | 响应 | 含义 |
|---|---|---|
| `GET /slab-match/api/v1/agent/match/notice/match-info` | `200` + `Content-Type: application/json` + `{"code":"40001","message":"方法参数传递不正确","data":[]}` | **接口存在**，只是缺参数/凭证 |
| `GET /this-path-does-not-exist-xyz` | `200` + `text/html` + 691 B 壳 | SPA 兜底，不是接口 |

**鉴权头已确认**（同一 URL，只换头）：

| 请求头 | 响应 |
|---|---|
| 不带任何头 | `40001 方法参数传递不正确` |
| `X-Agent-AccessKey: ak_xxx` | **`{"code":"40403","message":"无权操作"}`** ← 头被识别、令牌被校验 |
| `Authorization: Bearer xxx` | `40001`（未识别） |
| `X-Token: xxx` | `40001`（未识别） |

⇒ **前缀 `/slab-match/api/v1/agent/` + 头 `X-Agent-AccessKey` 均已证实**，与 SecAutoMind `internal/ctfplatform/dasctf.go` 的实现一致。
错误码速查：`40001` 参数不全 / `40403` 无权操作（令牌无效或过期）。

## 1. 唯一还缺的东西：`ak_` Agent 令牌

- 两系统都只认请求头 `X-Agent-AccessKey`，值来自环境变量，形如 `ak_` 开头、约 40 位。
- **门户的手机号 + 密码喂不进驱动**——那是网页登录，不是 Agent API 鉴权。需在门户开通/生成 AI Agent 的 AccessKey（可能要短信验证码，我方无法代收）。
- 拿到令牌后，**最快的自检**（不拉题、不提交，只验鉴权）：
  ```bash
  curl -s -H "X-Agent-AccessKey: $DASCTF_TOKEN" \
    "https://ycb-bk.dasctf.com/slab-match/api/v1/agent/match/notice/match-info"
  ```
  返回 `40403 无权操作` = 令牌无效/过期；返回 `40001` = 令牌已通过鉴权（只是缺参数）；返回 `data` 有内容 = 完全就绪。
- **更省事的一条命令**（2026-10-24 新增，已实测）：
  ```bash
  python scripts/finals_preflight.py --phase pre --check-auth
  ```
  它会在跑完五道门禁后**真的发一次只读请求**验令牌：令牌废了就直接 `NO-GO` 并点名
  「令牌鉴权失败：40403 无权操作」。**注意：不加 `--check-auth` 时它只判"凭证存在"，
  判不了"可用"** —— 实测本机环境里那把 `ak_` 令牌对 `pro` 与 `ycb-bk` 都返回 40403，
  不加这个开关预检会照样显示 `[SET]`。
- ⚠️ 另注意 `DASCTF_BASE_URL` 的默认值是 `https://pro.dasctf.com`（通用平台），
  **不显式覆盖就会打错平台**；本场必须 `export DASCTF_BASE_URL="https://ycb-bk.dasctf.com"`。

## 2. 共同环境变量（两系统通用）

```bash
export DASCTF_BASE_URL="https://ycb-bk.dasctf.com"   # 只填 host，别带 /slab-match——驱动自己拼
export DASCTF_TOKEN="ak_xxxx"                         # 或 CTF_AGENT_PLATFORM_TOKEN，二选一
```

- SecAutoMind：`internal/ctfplatform/dasctf.go` 读 `DASCTF_BASE_URL` + `DASCTF_TOKEN`（回退 `CTF_AGENT_PLATFORM_TOKEN`），URL = BaseURL + 路径。
- 西湖论剑：`ctf_agent/config.py` 读同样三个变量（Windows 另支持 setx 注册表回退）。
- 两者都带浏览器 UA 降 WAF；SecAutoMind 另有 403 WAF 冷却（`antiBlock`）。

## 4. 西湖论剑上膛

```bash
cd "E:/Program/西湖论剑/ctf_agent"
export DASCTF_BASE_URL="https://ycb-bk.dasctf.com"
export DASCTF_TOKEN="ak_xxxx"
export CTF_AGENT_LLM_PROVIDER="<provider>"        # 如 qwen / deepseek / baidu …
export <PROVIDER>_API_KEY="<key>"                 # 对应 provider 的 key
python run.py --mode platform --once              # 先单轮冒烟：拉题→解题→提交，看 accepted
python run.py --mode platform --interval 30       # 稳定后再定时轮询
```

- `--once` = 单轮（冒烟用）；去掉即每 30s 轮询。
- `config.py` 导入即打印 provider/端点/模型/key 快照 + 清空代理变量；**先看快照确认没打错端点**，再开跑。
- provider 默认值**静态、不保证当前可用**（`config.py` 自带此纪律注释）；可用性以现场探测为准。
- 正确性以平台 `submit` 的 accepted 回流为准（本地题库答案会误伤 `DASCTF{}` 平台 flag）。

## 5. 建议顺序（别直接定时轮询开跑）

1. 两系统都先 `--once` / 冒烟，确认能拉到题、能提交、accepted 回流正常。
2. 无误后再去掉 `--once` 定时轮询。
3. SecAutoMind 盯 runbook §1 四健康信号；西湖论剑盯 `run.py` 的「平台对战汇总」。

## 6. 红线

- 令牌 / 门户口令**只走环境变量**：不落盘、不入版本库、不进交付包、不贴进聊天记录。

- 平台侧异常（418 / 证书 / 5xx）先按第 0 节表格判断「是不是主机名错了」，再谈平台故障。
- 开赛前用官方 API 文档核对附件端点等（见 SecAutoMind runbook「附件链现状」）。

## 三、关键发现：靶场必须先启动（否则全 FAIL）

- **现象**：直接跑 `verify_range.py` → **0/19 全 FAIL**，报文如
  `S3-02 Redis 未授权 … ERR:[WinError 10061] 目标计算机积极拒绝`。
- **原因**：靶场是**独立服务进程**，必须**先启动** `scripts/experiments/target_range.py`。
- **验证**：启动后重跑 → **19/19 PASS**，尾部输出
  `✅ 靶场全部可复现，可以开始实验`（ground truth 预期漏洞 14 项）。
- 🔑 **录制前务必先起靶场**，并把它列进 OBS 录制前的固定动作；脚本里 S4/S8 的「Web 打点/应急」画面依赖它。

## 五、建议的录制顺序（按依赖排序）

1. 启动靶场：`python scripts/experiments/target_range.py`（后台）
2. 启动主服务（exe 或 `go run ./cmd/server`），确认 18086 端口 HTTP 200
3. `python scripts/experiments/verify_range.py` → **必须 19/19** 再开录（1 分钟）
4. 录制 S1–S3（开场 / 架构 / 启动与安全默认）——**不耗 LLM**
5. 录制 S4/S6/S7/S8 ——**需 LLM 授权**
6. S5/S9/S10（工具协同 / 扩展性 / 可解释回看）

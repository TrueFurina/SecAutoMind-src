# 企业微信（wecom）接通清单（2026-10-01）

> 状态：wecom 通道**代码已端到端完整实现**，本清单是「配置对接」步骤，零写码。
> 本次另补了一个真实缺口：`WECOM_AGENT_ID` 环境变量覆盖（主动推送必需字段），已测试通过。

## 一、前提（必须满足，否则进不了后台）

- 操作者**属于某企业且能创建自建应用**（管理员或自建应用权限）。
- 个人微信可**免费自注册企业**（work.weixin.qq.com 选团队/企业类型，无需营业执照）即自动成为管理员。

## 二、后台要取的 5 样凭证

| 后台位置 | 字段 | 对应 config / env |
|---|---|---|
| 「我的企业」页 | 企业 ID（CorpID） | `robots.wecom.corp_id` / `WECOM_CORP_ID` |
| 应用详情页 | AgentId | `robots.wecom.agent_id` / `WECOM_AGENT_ID` |
| 应用详情页 | Secret | `robots.wecom.secret` / `WECOM_SECRET` |
| 应用详情页 → 接收消息 | Token（自定字符串） | `robots.wecom.token` / `WECOM_TOKEN` |
| 应用详情页 → 接收消息 | EncodingAESKey（随机生成 43 位） | `robots.wecom.encoding_aes_key` / `WECOM_ENCODING_AES_KEY` |

## 三、后台「接收消息」配置

1. **回调 URL**：`http://<你的服务器IP>:18086/api/robot/wecom`
   - 注意路由是 `/api/robot/wecom`（代码写死，别写错）。
   - 官方支持 HTTP 或 HTTPS（非强制 HTTPS）。
2. **Token**：填一个自定字符串，**必须与 config/env 里完全一致**。
3. **EncodingAESKey**：点「随机获取」自动生成，复制出来。
4. **保存时的硬前置**：企微会**立刻向回调 URL 发真实 GET 验签请求**。
   → 所以保存前必须：服务实例**在跑** + `IP:18086` **公网可达**（安全组放行）。服务没起 = 保存报「验证失败」，不是代码问题。

## 四、填进程序配置（二选一）

### 方式 A：直接改 config.yaml
```yaml
robots:
  wecom:
    enabled: true
    corp_id: "企业ID"
    secret: "应用Secret"
    agent_id: 1000002        # 数字，别加引号
    token: "后台填的Token"
    encoding_aes_key: "43位AESKey"
```

### 方式 B：环境变量（线上部署推荐，不落明文）
```
WECOM_ENABLED=true
WECOM_CORP_ID=...
WECOM_SECRET=...
WECOM_TOKEN=...
WECOM_ENCODING_AES_KEY=...
WECOM_AGENT_ID=1000002      # ← 本次补的，之前漏了，走 env 必须带这个
```

## 五、两条硬校验（代码里已设）

1. `enabled=true` 时 **Token 必填**，留空直接启动报错（`ValidateWecomConfig` 拦截）。
2. `enabled=true` 但凭证不完整 → 通道会被禁用并告警，不影响主系统启动（`EnabledButIncompleteRobots`）。

## 六、验证

- 保存回调后，企微应用里给机器人发条消息，应收到被动回复（内置命令）。
- AI 消息走异步处理 + 主动 API 推送（`sendWecomMessageViaAPI`，依赖 AgentID + Secret 拿 access_token）。
- 出站告警走 `sendWecomProactive`。

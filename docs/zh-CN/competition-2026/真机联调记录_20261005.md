## 三、结论（区分已验证 / 未验证）

### ✅ 已验证（本次实测证明）

1. **网络可达**：`pro.dasctf.com` 正常响应，RTT 3.49s。
2. **端点路径正确**：3 个端点均返回平台业务 JSON 而非 404/超时 → `/slab-match/api/v1/agent/` 前缀与各路径正确。
3. **鉴权方式正确**：`internal/ctfplatform/testdata/request_golden.json`（真源 Python 真实
   打平台录下的 6 条报文）显示 header 只有 `content-type` / `user-agent` / `x-agent-accesskey`
   三个，**无额外身份头** → 本项目代码的请求头与真源一致。
4. **Token 被平台成功解析身份**：带 Token 得 `40403 无权操作`、不带 Token 得 `40001 参数不正确`
   —— 两个不同错误码证明平台读到了身份并进入了权限判定。
   → **排除了"Token 是伪造/格式错"与"代码契约写错"这两个最坏可能。**

### ❌ 未通过

5. **该 Token 当前无权限**：所有 agent 接口 `40403`。

### ⚠️ 未能验证（不编造）

6. **成功响应的真实结构**未验证——无权限就拿不到成功响应，因此
   `code=="00000"` 且 `data.isCorrect==true` 的成功判据、题目列表的嵌套展平结构、
   `challenge_detail.endpoints[].exposeIps[0]` 靶机地址格式，**在真机上仍是未验证状态**。
   这些目前只有仿真平台（`TestRehearsal`）与真源 golden 两条证据支撑。

### 40403 的成因未判定（不猜）

以下四种可能，本次实测**无法区分**：
1. Agent 接入 Key 需在平台后台/由赛事方开通后才生效；
2. agent 接口仅在**比赛窗口期**开放，非赛期调用一律 40403；
3. Token 属于其他队伍或其他场次；
4. Token 已过期。

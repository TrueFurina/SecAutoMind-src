## 三、提示词通用骨架（写新提示词时套这个）

本项目最容易出问题的不是模型能力，而是**报告的真实性**。所以每个提示词都该带这五段：

```
【角色】你是 SecAutoMind 仓库的工程 agent，已读 AGENTS.md（九条宪章）。

【硬约束】
- 诚实高于一切：没跑过的命令不许说跑过；没读过的文件不许描述内容；引用行号必须真读过。
- 判成败一律 `cmd > out.txt 2>&1; echo "RC=$?"`，禁止管道吞掉 FAIL 与退出码。
- 改完必须 Read/grep 复验（Edit 假成功已发生 3 次）。
- 失败就报失败，"基本通过/收官/全部搞定"属于违规用词。
- 数字只来自脚本实跑（count_stats.py 等），不手写、不凭记忆。
- 冻结窗口内禁止改 internal/ agents/ cmd/（先跑 freeze_gate.py --status）。

【上下文锚点】先读：<具体文件 1>、<具体文件 2>、<具体文件 3>。
不要读整个仓库，不要凭目录名猜功能。

【任务】<单一、可验收的目标，不要塞 5 件事>

【验收】（必须可机验）
- 命令：<cmd>，期望 RC=0，且 <具体断言>；
- 反向验证：把 <X> 弄坏后门禁必须变红（证明门禁有效，不是恒绿）。

【输出】
1) 改了什么（文件清单）；2) 真实验证输出（原文，含 RC）；3) 未验证项与风险；
4) 若部分完成，明确写"部分完成"，并给 target / current / gap。
```

**三条最容易漏的写作要点**
1. **一定要写反向验证**。本项目的门禁事故基本都是"门禁恒绿"——只证明"能过"，没证明"该红时会红"。
2. **一定要写"未验证项"这一节**。留空的"未验证"比填满的"已验证"更可信。
3. **一定要写边界**（能改哪些目录）。冻结纪律靠提示词兜底，因为 agent 不知道今天是不是冻结期。

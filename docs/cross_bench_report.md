🔴 **10-14 修正记录（为什么从 1/12 改为 0/12）**：10-13 版的"剔除口径 1/12"命中的

🟢 **10-15 立尺驱动修订记录（0/12 → 3/12 → 4/12，两轮，均为真攻击而非口径放水）**：

- **第一轮（PR #26，新增三个确定性求解器，0 token）**：
  - `rsa_phi_pinv`（ExcitingInverse）：已知 phi+pinv/qinv 而 n 未给出——两式消 pq 得
    kj=pinv·qinv−1，代入 phi 得关于 k 的二次方程，判别式完全平方即恢复 p,q；
  - `legendre_bit_phi`（SimpleLegendre）：Jacobi 符号 (c/N) 对两个比特值同值为 +1，
    必须先用泄露的 phi 分解 N 再逐位算 (c|p)——本轮先受制于截断（见下），第三轮才命中；
  - `lfsr_correlation`（FilterRandom）：LFSR 演化对 init 完全线性 → 基向量展开得系数矩阵，
    GF(2) 高斯-约当解前缀、ISD 信息集解码恢复 init1（0.9^64 全清概率，期望 ~850 次）；
  - 同时修复两个**挤压真解**的缺陷：题面占位符（`DASCTF{init1-init2}`、printf 模板
    `b'DASCTF{%d-%d}'`）被 flag_scan 刮成同分假 flag 以 priority 10 压掉正确解；
    Håstad 裸数字格式的指数候选漏掉 ezRSA 真实 e=17（`e.Sign()<3` 误用，Sign 只返回 −1/0/1）。
- **第二轮（PR #27，立尺口径修订 + 生产缺陷修复）**：
  - harness 附件截断上限 **4KB/文件、16KB/题 → 512KB/1MB**：旧注释理由「数值型大 output
    对正则扫描是纯成本」对逐位加密题恰好相反——**数字本身就是题目数据**。simplelegendre
    的 163KB output（phi+N+264 密文，恢复 264 比特 flag 需全量）被截到个位数密文，
    求解器数据不完整而不可解，此前被误记为「能力缺口」。人类选手拿全量 output，
    截断属**测量管道缺陷**。答案文件排除逻辑不受影响；
  - Håstad 裸数字回退按 12 数字（6 对）封顶：全量文本下 264 密文全进 CRT 会使模数涨到
    ~545k bit，整数 k 次开根是二分（~B/k 次 Exp），全范围 3..99 sweep 最坏代价按
    ~B³/k² 爆炸到小时级——不封顶会拖死 CI（600s 预算）；
  - URL 渗透链九件套按题目类别门控：crypto 题 specialcurve2 附件注释里的 writeup 链接
    令九件套对无关主机干等满超时（单题 60s），且从第三方页面刮回伪 flag 污染 solved 判定。

四个必须同时陈述的边界：

1. **答案文件的入仓红线**：4 个含 flag 明文/内嵌答案的附件（两个 `flag.txt`、
   `index.php`、`helloupx11`）**只保留在本机**，经 `attachments/.gitignore` 排除出
   PUBLIC 仓库（交付红线：禁止 flag 明文入 commit），并在 `cross_bench.json` 逐文件登记
   `git_excluded` + 原因。后果：**CI 检出不含这些文件，「含答案口径」在 CI 上自动降级
   为剔除口径**——这是预期行为，不是故障；本地跑分不受影响。
   测试对"非排除文件缺失"fail-closed 报红（清单与实物脱节），对"git 排除文件缺失"
   只记账不问责。
2. **真实赛制下附件直给答案也计入**：`smallsword3` 的题型就是"攻击者下载的 flag"，
   附件当场给答案是赛场事实；但它**不是解题能力**，故必须单列剔除口径——两口径互不冒充。
3. **截断边界（2026-10-15 第三版修订）**：附件内容按 **512KB/文件、1MB/题** 截断

   喂原始字节只虚增耗时）。求解器侧最坏耗时由 Håstad 裸数字回退的配对数封顶单独约束。
4. **耗时波动与 CI 形态（2026-10-15 第三版归因）**：旧实测 29.6s~242s 大幅波动的根因
   **已定位并消除**——URL 渗透链九件套对题目文本中提取的 URL（含 crypto 题附件注释里的
   writeup 链接）发起真实 HTTP 请求并干等满超时（逐 solver 计时 jwt 40s / upload 29.8s /
   web_exploit 25s）。按题目类别门控后子集测试稳定在 ~27s 且**零网络依赖**。
   独立 job `cross-bench-subset`（`-timeout 600s`，不 -race）保留；命中率只报告不断言。

### 判据必须机验：一次差点发生的误判

初扫时 `crc32` / `lcg` / `ecdsa` / `execution` 四集的题面也有 flag 明文，
**一度被判为注水——实测是错的**：那些题的 flag 是**已知输入**
（CRC32 伪造、LCG 参数恢复本就是"给定原文求碰撞"），sha256 与 `flag_sha256` 不相等。

题面提取出的 flag 串，其 `sha256 == flag_sha256` ⇒ 答案就写在题面上；不等 ⇒ 只是输入，合法。
**"看着像答案"不能作为判据**——这与 4.5 节"归因必须逐题穷举，不许按类别推断"同源。

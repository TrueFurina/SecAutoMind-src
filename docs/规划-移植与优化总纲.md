## 0. 总决策重申（不合并，定向移植）

**全量融入 = 🔴 No-Go；定向移植 = 🟢 Go。** 迁移范围从「A 的全部资产」收缩到 **15–20%**，且**代码迁移量 ≈ 0**（A 的求解器 B 已显式移植；A 的 Python 逻辑不重写、不引入 Python 运行时）。

三条否决硬约束（任一成立即不可合并）：
1. **License 冲突**：A 是 MIT 开源；B 是 source-available、SHARE_README 明示"未经书面许可不得再分发"。互融任一侧都违规。
2. **技术栈不可并**：Python vs Go，构建/依赖/运行模型全不同。
3. **生命周期错位**：A 已收口开源；B 是 7 周后（11 月）决赛的在赛交付物，有"单二进制部署"硬要求。

**已发生大半的事实**：B 已显式移植 A 的主力求解器（`tryLegendrePhi` / `tryModInvFactor` / `tryPKCS1Hint` / `tryZIPFakeEncryption` / `tryWebSourceAudit` / `tryHastadBoard`）。今天决策的是"补长尾 + 补治理层"，不是"从零融"。

## 2. P0 移植清单（参赛资格线，W1–W2 必须完成）

### 2.1 🔴 平台对接层接线（最高优先级，当前最大未闭环项）

- **现状（9-12 复验确认）**：`app.go:403` → `NewPresolveAgentIntegrator(ctfPresolve, ctfAnalyzer, nil, log.Logger)` 第 3 参数**显式传 `nil`**；`NewDasCTFPlatform` / `NewPoller` 全库仅定义无调用；`cmd/` 下 6 个 main 包无一引用；无 dasctf/poller/analyzer/integrator 测试，全库无 e2e。**拉题 / 起靶机 / 提交 flag 这条链路写了却从未被调用、从未被测过一次** → 参赛资格不成立。
- **动作**：
  1. `app.go:403` 第 3 参数由 `nil` 改为真实 `DasCTFPlatform` 实例（`NewDasCTFPlatform(cfg, log)`）。
  2. 在接线**同一 PR** 内同步注入 A 的 **7 项抗打击机制**（见 2.4），一次性做完别分两次。
  3. 补 e2e：`internal/ctfplatform/` 新增 `TestPlatformE2E_Lifecycle`：模拟"拉题列表 → 选靶机 → 提交 flag → 校验 accepted"，用 A 的 `dasctf.py` 真源做 golden 对照。
- **验收（可机验）**：`go test ./internal/ctfplatform/... -run E2E -v` 全绿；CI 新增 e2e job；官方仿真平台联调一次（不能用单测代替）。

### 2.2 🔴 cross-bench 立尺（92 道真题进 B）

- **动作**：将 A 的 `data/questions_real/`（92/92 已 git 入库）搬运为 B 的 `data/questions_real_bench/`，**仅作尺，不混入 B 题库刷数字**。
- **同题对照表**：跑 A、B 两库对 92 题的同卷解算，产出 `cross_bench_report.md`：
  - 列：qid / 分类 / A 结果 / B 结果 / 一致 / 差集（B 未解而 A 解）。
- **阈值决策机制（先定阈再跑数，防恐慌性全量迁移复发）**：
  - B 在 92 题命中率 **≥ 13%** → **不迁题型**；
  - **< 13%** → 仅迁 **misc 差集**（A 46 道 vs B 真命中 2/13，负收益最小、收益最高）；
  - crypto / web 明确不迁（B 72% vs A 22 道；web 静态测不了靶机）。
- **成本**：≈ 0.5 人天。收益：W1 立尺从"周级"降为"小时级" + 协同演练题库 + 回归集三合一。

### 2.3 🔴 诚信铁律继承（B 当前正在犯的错误）

- **铁律**：无外部 `flag_sha256` 真值不计入 KPI（A 的 10732/10735 即因此不入 KPI）。
- **动作**：B 的 `data/ctf_benchmark/` 一批"100%"来自 `gen_*.py` 自产题，自产自解无信息量。一律**标注「自产题」或剔除**，不得作为能力证据对外。
- **验收**：`verify_evidence.py` 增加"自产题占比"字段；所有对外 100% 标注来源。

### 2.4 🟠 7 项抗打击机制（A 唯一被真实赛时验证的遗产，随 2.1 同步注入）

A 初赛被 **37 次 429** 打爆后的修复成果，B 的 `dasctf.go` 对以下 7 项**零命中**（`backoff` / `Retry-After` / 连续 429 计数 / 列表 TTL / `waf_blocked_until` / `last_list_ok` / AsyncClient 复用）：

| # | 机制 | A 真源位置 | B 注入点 |
|---|------|-----------|---------|
| 1 | 指数退避 + 抖动 | `dasctf.py: _backoff()` | `dasctf.go` 请求重试器 |
| 2 | `Retry-After` 头尊重 | `dasctf.py` | 429 分支解析 |
| 3 | 连续 429 计数熔断 | `_consec_429` | 平台客户端状态机 |
| 4 | 列表 TTL 缓存 | `list_ttl` | poller 缓存 |
| 5 | WAF 冻结窗口 | `waf_blocked_until` | 请求拦截层 |
| 6 | 列表成功标记 | `last_list_ok` | poller 状态 |
| 7 | 连接复用 | `AsyncClient` | `http.Client` 复用 |

- **约束**：全部 **config 开关化、默认开、一键回退**；**必须在仿真平台验，不接受只过单测**（9-12 风险预案同款）。

## 4. P2 更多规划优化点（超越 9-12 文档，W5–W7 + 常态化）

### 4.1 🟢 机器可验证据包标准化（championship evidence package）

- **动机**：9-13 复检已证明"能力可测、证据可复现"，但证据散落于 `evidence-championship-*.md` 与多份 txt。需把"答辩即用的证据"固化成**单一可机验包**。
- **动作**：扩展 `verify_evidence.py` 为 `build_championship_evidence.py`，输出一份 `evidence-package.json`（含规模真值、构建/测试退出码、四基准数字、双语言 golden 结果、密钥门禁三件套 RC、交付包三红线），附 SHA-256 清单。评委/巡检可一键 `python verify_evidence.py --package` 复现。
- **验收**：`evidence-package.json` 每次构建自动重生；CI 门禁比对活值与包内值，漂移即 BLOCK。

### 4.2 🟢 HITL 失效边界实证专项（副 RQ-B，发表优先）

- **动机**：HITL 是赛题"决策逻辑与可解释性"评分维的直接回应，也是 9-12 标记"唯一真正可随机化的子研究"。当前仅 `default_mode: approval` 已修，但**失效边界未实证**。
- **动作**：设计 HITL 失效模式矩阵（false-approve / false-block / 超时挂死 / 人工覆盖冲突 / 多 agent 共识分裂），用 ≥8 名外部导师（跨校招募）做 randomized 评测，产出"失效边界报告"。**这同时是挑战杯之外的学术论文产出。**
- **验收**：`hitl_failure_boundary.md` + 可复现实验脚本；阈值：false-approve 率 < X%、false-block 率 < Y%（阈值由 MPU-2 定）。

### 4.3 🟢 决赛冻结纪律 + 变更闸门（<14 天不动架构）

- **动机**：9-12 三条停工边界之③"距决赛 < 14 天 → 不动架构，只做冻结与演练"需落到工具上。
- **动作**：新增 `freeze_gate.py`：决赛前 14 天起，除 `docs/`、`config.share.yaml`、证据包外，任何 `internal/` / `agents/` / `cmd/` 改动被 pre-commit BLOCK（显式 `--freeze-override` 逃生阀仅限安全官/主理人）。冻结期只跑"构建 + 全测 + 交付包自检 + 演练"。
- **验收**：冻结开关由 `config.share.yaml: freeze_mode` 驱动；CI 在 freeze 窗口内拒绝架构 PR。
- ✅ **2026-09-16 已实现**：`scripts/freeze_gate.py`（查暂存区 / `--worktree` / `--base <sha>` / `--status` / `--json`）
  + `scripts/freeze_gate_test.py`（16 项用例，含"protected_paths 置空后同文件必须放行"的**因果验证**）
  + CI job `freeze-gate`（自测 + status + PR 区间拦截）。
  实测：含 `internal/` 改动的真实区间 **RC=1（BLOCK）**，仅材料改动 **RC=0**。
  - **与原始设计的偏差（如实记录）**：验收里写的单一 `freeze_mode` 布尔**表达力不足**——没有决赛日期就无法
    自动进入/退出窗口。故改为 `freeze.enabled` + `freeze.final_date` + `freeze.freeze_days`（默认 14）组合：
    置 `enabled=true` 并填日期即自动生效，日期过后自动解除；`enabled=true` 但日期缺失/非法则 **fail-closed**。
  - 逃生阀：`--freeze-override "<≥20 字理由>"` **且** `FREEZE_OVERRIDE_ACK=1`，缺一不可，触发后追加审计到
    `docs/freeze-override-log.md`。

### 4.4 🟢 官网 / 对外材料同步自动化（根治 P1-3）

- **动机**：9-13 P1-3 官网数字滞后一个数量级（官网自述约 1.8 万行 vs 活值 127,192 行）且无门禁覆盖（官网被 `.gitignore` 排除）。

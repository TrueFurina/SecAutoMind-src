## 维护纪律（同主库）
新增事故模式必须带「出处 + 机器化或人工检查动作」，不许写无出处的教训。
本文件为 runbook 附录（活文档），新事故模式按主库同款格式追加。

| # | 事故模式 | 根因 | 机器化检查 / 动作（本项目语境） |
|---|---|---|---|
| A1 | **Bash 管道破坏 `git show 远端:path` → 误判文件不在 main → 开冗余 PR** | 管道中冒号/斜杠被 shell 转义 → `git show` 静默失败 → grep 空 → 误判「文件不在远端」。10-25 实证：误判 skill-exec-gate 不在 main，白开 PR #67 又关（逐字节 diff=0 才证伪）。 | 核远端文件一律 `git cat-file -e <远端>:<path>`（无管道，返回码即真值）；结论反直觉时先用「无管道最小命令」复测再下结论。 |
| A2 | **共享暂存区预载 → commit 卷入并行会话 WIP** | 多会话共享同一 worktree 暂存区；某会话 `git add` 前未查，把另一会话 stage 的删除/新增连带提交，污染 commit。 | `git add` 前必 `git diff --cached --name-only` 查预载；commit 用**显式路径**（禁 `git add -A` / `git commit -a`）；提交后 `git show --stat HEAD` 复核仅含预期文件。 |
| A3 | **并行半成品（未跟踪 broken .go）堵死整包编译** | 并行会话把含编译错误的未跟踪 `.go` 留在工作树 → 整包 `go build`/`go test` 失败，误判自己改动引入回归。10-25 实证：`presolve_emoji_binary.go`（`ebRank` 返回 3 值调用处接 1 个）堵死 ctfplatform 整包，worktree 隔离后才证伪。 | 主树 build 失败时先 `git ls-files -o --exclude-standard \| grep '\.go$'` 找未跟踪 broken 文件；隔离验证用 `git worktree add --detach <dir> <mycommit>` 在干净基上跑测试，绝不改并行 WIP。 |
| A4 | **`\| head`/`\| tail` 吞管道退出码 → 误判测试/编译通过** | `cmd \| head` 后 `$?` 是 head 的退出码而非 cmd 的；本项目已踩 ≥4 次，曾掩盖编译器 OOM（errno 1455）。 | 判 RC 一律 `cmd > out.txt 2>&1; echo RC=$?` 落盘取值；CI / 手动判绿只读落盘文件，不靠管道末段 `$?`。 |

# 决赛日 Runbook（v0.1 · 2026-10-25 固化）

> 用途：下一场目标赛事（2027-03-01 决赛及之前任何一场）开赛前后的**执行清单**。
> 来源：羊城杯（25 次提交教训）+ CTF² 快闪赛（9/9 但两起事故）+ 两晚工程善后的全部实证。
> 铁律：**拿分是唯一目标**；每 15 分钟自问"这一步直接产生分吗"，答否就停。

## T-24h（赛前一天，工程冻结前）

- [ ] 跑赛前预检：`python ctf-agent\scripts\preflight_ctf.py`（GO 才上场；NO-GO 逐项修，
      确属误报才 `-SkipPreflight` 并在复盘留痕）
- [ ] 确认模型通道：默认模型（claude-sdk/codex 订阅制）可用；网关模型（azure/*）作备胎
      ——**赛前用一次最小调用验证每条通道**，别开赛才发现密钥过期
- [ ] Docker 在跑、`ctf-sandbox:latest` 镜像在；磁盘 >10G
- [ ] 提交格式注册表（`backend/flag_formats.py`）已核对目标平台；**表里没有的平台，
      赛前用已知正确串裸/带壳各试一次**（拿练习场试，不消耗正式题次数）
- [ ] runner 起飞内存预检（memguard）阈值合理；`--per-task-timeout` 保持引擎默认
- [ ] 本机腾内存：关掉非必要 IDE/Agent 进程，留 >4G（今晚两次静默击杀的根因）

## T-30min（开赛前）

- [ ] 令牌探测：`GET /api/open/v1/user/agent/me/` 返回 agent active ✓
- [ ] 比赛 entered=true（没有就 enter，别等开赛才发现没进场）
- [ ] 拉题目列表，按三色分类：**已解（跳过）/ 附件源码题（最优先，确定性分析）/
      容器交互题（排后，平台同时只给 1 个环境槽）**
- [ ] **提交通道打通**：用一个已知正确串（练习场的）走完整提交链路，确认返回码形态
      ——"解题不需要令牌，提交才需要"；开赛第一件事是提交，第二件才是解题

## T-0（开赛）

- [ ] 启动顺序：预检 GO → 确保 entered → 拉起 runner（**一场比赛只允许一个会话拥有引擎**；
      启动前 `Get-CimInstance Win32_Process` 查已有 runner 进程，有则接管不新起）
- [ ]  runner 参数：`--poll 5 --max-concurrent 4`（匹配平台 max_targets）；
      容器题串行由引擎自控；`--per-task-timeout` 用默认（600），不手贱覆盖
- [ ] 选题排序引擎自处理（静态优先→附件题最前→容器题排后）；**人工只补"初步方向"列**
- [ ] 前 30 分钟盯三件事：首轮 poll 是否拉到题、前几次提交的 HTTP 状态与 flag 格式、
       solver 是否真在动（看 stderr 时间戳 + 容器 + CPU，**别只看 stdout**——假卡死误判杀容器的事故）

## 赛中（每 15 分钟一个节拍）

- [ ] 自问：这一步直接产生分吗？（读日志/看板/调格式都不直接产分——设时限）
- [ ] 提交失败：**先疑格式/通道，不疑答案**。连续 3 次同形态失败 → 停下来做通道对照
      （裸/带壳各发一次），不要在内容上继续枚举（羊城杯 25 次的教训）
- [ ] runner 猝死（零日志）：先查内存（任务管理器/`free`），再查是否被并行会话误杀；
      重启前先腾内存或减模型（memguard 会替你决定）
- [ ] 单题卡住 >超时值：引擎自动退避换题——**别人工抱着难题啃**，分值要让位给能拿的分
- [ ] 环境槽位 409：退出时交还机制应已处理；若仍在，`close_environment` 手动释放再重试

## 赛后（30 分钟内）

- [ ] 平台 entry 页截图（战绩数字只认平台：score/rank/solve_count，**自算合计会错——
      快闪赛标分 974 vs 平台 1049**）
- [ ] 归档：trace/作战板/提交记录/成本汇总（`logs/cost_*.json`）→ 复盘文档
- [ ] 复盘三问：哪一步直接产生了分？哪一步是代理指标（看着在推进其实不产分）？
      哪个事故能变成明天的纪律/代码？（今晚：内存守卫、格式注册表、租约，都这么来的）
- [ ]  Runner 收尾：容器交还、进程清理（`taskkill /PID /T /F`，Windows 下 Kill 不杀子树）

## 事故决策树（速查）

| 症状 | 第一怀疑 | 动作 |
|---|---|---|
| 提交全错 | 格式/通道 | 裸/带壳对照实验，查 flag_formats.py |
| runner 秒退零日志 | 内存耗尽被杀 | 腾内存；memguard 拒绝时看告警 |
| runner 秒退有日志 | 无赛可打/令牌 | 看 stderr 首行；agent/me 探测 |
| 容器 409 | 环境槽位未交还 | close_environment；确认退出交还逻辑生效 |
| solver 不动 | 假卡死误判 | 看 stderr 时间戳+CPU+容器，三者有一活跃即别杀 |
| 双会话互踩 | 无租约 | 一场一引擎；启动前查进程 |

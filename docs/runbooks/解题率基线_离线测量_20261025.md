# 解题率基线 · 离线测量锚点（2026-10-25 听风试水）

> 目的：把「真实解题数」这个唯一核心指标在**当前离线数据**上的可复现真值钉死，
> 防止后续出现 RDD 式「我把 presolve 调到 XX%」的虚假战报。任何「提升」必须对照本锚点重测。
> 测量方法：worktree@4640aa0（含并行 a135327）+ 拷入 gitignored 的 data/，跑既有权威回归测试。

## 一、三份基准的真实覆盖率（纯 Go 确定性 presolve，离线、零 token）

| 基准 | 题数 | 模式 | 覆盖率 | 备注 |
|---|---|---|---|---|
| `data/ctf_benchmark/real_benchmark.json` | 55 | 仅 description | **20/55 = 36.4%** | 门禁 `TestRealBenchmark_*` 要求 ≥14，已通过 |
| `data/questions_real_bench/cross_bench.json` | 88 | 仅 description | **0/88 = 0%** | 设计如此：76/88 附件已缺失，文本口径本就无解 |
| 同上 · 有数据子集（12 题附件仍在磁盘） | 12 | description + 真实附件 | **5/12 = 41.7%** | 5 命中全是 crypto；7 miss 见下 |

- 注册表路径 `PresolveWithRegistry` 在 55 题集上 **= 生产路径 20/55**（注册表缺 0 / 多 0），
  即没有「写好却没接进生产路径」的求解器可补 → 无接线缺口。
- 88 题集注册表路径同样 0/88。

## 二、miss 归因（为什么到顶了）

- **55 题集 35 道 miss：35/35 全部「描述里无实例数据」**。抽样确认均为「技法描述题」，
  描述只写技法名（"RSA共模攻击：n1和n2共享素数p"、"git log查看提交历史找到flag"、
  "tshark提取HTTP POST body中的flag"），**无任何可算参数/密文/附件引用**。
  → 确定性层连数据都没有，加求解器也无从下手。0 道「有候选但错」、0 道「已解无候选」
  （即无正则近失，无「找到但格式判错」）。
- **12 子集 7 道 miss**：`real_crypto_specialcurve2`（附件 `SpecialCurve2.py` 注释自证
  「n/HINT/C 每次运行随机生成、未留存」，仅恢复脚本模板，无本实例真值）、
  `real_reverse_js`（JS 反混淆，需 node）、`real_reverse_sheng`/`real_reverse_upx`
  （二进制/UPX，需 angr/UPX）。→ 结构性不可离线解。
- **88 题集 0%**：76/88 附件缺失，文本口径毫无数据。

## 三、结论：离线零 token 杠杆已耗尽（实测，非没找到）

1. 确定性 presolve 层在现有离线数据上**已到硬顶**：36.4% / 41.7% / 0%，剩余 miss 全部
   因「无数据」或「需二进制/符号执行工具（本地未装）」。无可修靶点。
2. `FilterFlagCandidates` 识别闸门用 `flagRegex=(?i)(?:flag|ctf|dasctf)\{[^}]{3,}\}`，
   仅认三种前缀。**存在真实但不可离线验证的缺口**：真实赛题 flag 前缀多样
   （`SecAutoMind{`/`ByteCTF{`/`0CTF{`…），Layer 3 解出但前缀不在白名单会被漏提。
   **但不得凭臆测拓宽**：该闸门输出直投平台，提交机会是全队共享稀缺池，误提假 flag
   直接浪费次数；且 LLM 层冻结无法离线测召回/误报权衡。→ 列为「待平台放闸后专测」项。
3. `infer_skill_require`（zip→skill 路由）**不在本仓代码**（仅存于 `CTF-Agent_融合/
   ctf_agent/core/prompts.py`，属另一套 ctf-agent 引擎）。本仓 skill 路由是注册表式
   presolve 探测器，已验证生产==注册表，无未接线函数。

## 四、试水下一刀的方向（待平台放闸 / 用户拍板）

唯一能抬核心指标「真实解题数」的杠杆是 **Layer 3（LLM 推理层）**——它才负责 35 道
「技法描述题」类 miss。平台冻结（全端点 40403 无赛道）前无法实测。建议放闸后：

1. 建**本地 LLM 层 eval harness**（gate 在模型端点）：对 88 题集（含已恢复附件）+ 55 题集
   跑完整 pipeline（presolve→skill→LLM），逐类报解题率，作为 Layer 3 改进的对照基线。
2. 在 harness 上测 `flagRegex` 前缀覆盖缺口，按「召回 vs 误投」权衡决定是否拓宽 + 加回归测试。
3. 12 子集 7 miss 中二进制/UPX/JS 类，待本地装齐 angr/node/UPX 后由 skill-bridge 攻。

> **用途**：① 部署后验收（别让"服务 200 但能力为零"溜过去）② 决赛/评审现场演示的取用清单 ③ 新人上手第一份操作文档。
> **数字口径**：本文所有计数以 `python scripts/count_stats.py --json` 为唯一真值源，**禁止手写**。
> **最后更新**：2026-10-04

## 一、部署完整性对账（🔴 最高优先级，先做这步）

**血泪教训（2026-10-04）**：线上服务一直是 `active` / 面板 200，但 `roles/`、`skills/` 两个目录**从未部署**，
导致 13 个角色、23 个技能包**全部静默失效**——服务照常运行，只是不干正事。**只看"服务起得来"永远发现不了。**

| # | 目录 | 对应配置键 | 缺失时的症状 | 验收方法（实证判据） |
|---|---|---|---|---|
| 1 | `roles/` | `roles_dir` | 机器人回「暂无可用角色」；日志里任务 `"role":""` 全空 | `journalctl -u secautomind \| grep "警告: 加载角色配置文件"` 应**无输出**（该警告走 stdout，不进 zap 日志） |
| 2 | `skills/` | `skills_dir` | Agent 每轮都被告知「技能包在 skills/ 目录」却读不到任何 SKILL.md | 重启后 journal 应**无** `eino_skills: skills_dir empty, skip`（该 Warn 必现于未生效状态） |
| 3 | `tools/` | `security.tools_dir` | 诊断显示「工具 YAML 声明 0/0」 | 见 §三 口径说明；`诊断` 命令的输出即判据 |
| 4 | `knowledge_base/` | `knowledge.base_path` + `knowledge.enabled` | 知识检索无召回 | 诊断「知识库」行 + 实际检索命中 |
| 5 | `web/` | 无（`go:embed` 编译进二进制） | 前端 404 / 空白页 | 本地 `scripts/check_web_asset_parity.py`，CI 亦跑 |
| 6 | `agents/` | `agents_dir` | 多代理编排提示词缺失 | 目录存在即可（文件小） |

**对账命令**（一眼看出漏了什么）：

```bash
# 仓库侧
ls -d */
# 服务器侧
ssh root@<host> 'ls -d /opt/secautomind/*/'
```

### 🔴 三处独立缺口，缺一即全盘失效，且**都不报错只降级**
一个能力要生效，需要**同时**满足：① 目录存在 ② 配置键有值 ③ 开关打开。
任何一处缺失都是**静默降级**（服务正常、能力为零）。判据不是"看代码里有这个字段"，
而是**找到代码里 skip 分支的 Warn 文案，反推"若仍无效必现哪句话"，再去日志里确认它没出现**。

### 配置文件的 CRLF 陷阱
服务器 `config.yaml` 是 **CRLF** 行尾。`sed` 锚定 `^key: value$` 会**因尾随 `\r` 失配**：

```bash
# ❌ 失配（$ 对不上 CRLF 的 \r）
sed -i 's/^skills_dir: skills$/xxx/' config.yaml
# ✅ 容忍 CR
sed -i 's/^skills_dir: skills\r*$/xxx/' config.yaml
```

插入顶层键时务必保持 CRLF 一致，否则下一次 `sed` 又会失配（这个坑已踩两次）。

## 二、口径分层：两类工具**同名不同义**（🔴 2026-10-04 修正）

这是评审最容易误解、进而判定"材料夸大"的一处。

| 名称 | 含义 | 数量来源 | 是否依赖部署 |
|---|---|---|---|
| **Go 内置 MCP 工具** | 编译进二进制的 Go 工具（资产 / 漏洞 / webshell / C2 / 批量任务 / HTTP 测试…） | `internal/mcp/builtin/constants.go` 的 `GetAllBuiltinTools()` | ❌ 不依赖，开箱可用 |
| **工具 YAML 声明** | `tools/` 目录下的安全工具**声明**（nmap / sqlmap / metasploit / ffuf…） | `tools/*.yaml`，经 `security.tools_dir` 加载 | ✅ 依赖目录部署 |
| 运行时工具合计 | 前两者之和，**不重叠** | `count_stats.py` 的 `runtime_tools` | — |

**历史缺陷**：`诊断` 命令曾把 YAML 工具数标成「内置 MCP 工具」，与材料的「内置 MCP 工具 52」
**同名不同义** → 未部署 `tools/` 时输出 `0/0`，评审看到会直接对撞材料的 52。
现已改为两层分列，措辞与 `count_stats.py` 字段严格对齐，并由测试锁死（`robot_doctor_caliber_test.go`）。

> 材料口径「工具 YAML 91 / 内置 MCP 工具 52 / 合计 143」是**声明数 + 内置数**的诚实拆分，
> 不是"91 个工具都能执行"的可用性承诺。**不要把它读成可用数。**

### YAML 工具的真实可用性取决于服务器装了对应二进制
`tools/*.yaml` 只是**声明**；实际执行需要服务器上有 `nmap` / `sqlmap` / `hydra` / `nuclei` 等二进制。
**只开配置不装二进制 = 制造"工具全坏"的假象，比不部署更糟**（Agent 会反复调用失败工具、烧 token、演示尴尬）。
部署前务必先查 `command -v <bin>`。

## 三、机器人演示取用清单（按性价比分层）

命令全表见 `help` 输出（分 General / Conversation / Role / Mode / 漏洞提醒 / Diagnostics 六组）。

### 🟢 第一层 · 零成本秒回（不消耗 LLM token，证明工程完备）
| 命令 | 演示什么 |
|---|---|
| `角色` | 13 个角色清单（渗透测试 / CTF / 二进制分析 / 后渗透 / 数字取证 / 云安全审计…）— **部署修复后应有的样子** |
| `诊断` | 配置健康度：主模型 / Go 内置工具数 / 工具 YAML 数 / 知识库 / 项目功能 |
| `模式` | 四种对话模式（Eino 单代理 / Deep / Plan-Execute / Supervisor）+ 当前选择 |
| `权限` | RBAC 权限矩阵（执行 Agent / 读写删对话 / 资源范围） |
| `身份` | 平台发送者、鉴权模式、当前实际 RBAC 身份 |
| `状态` / `版本` / `任务` / `列表` | 会话与运行态摘要 |
| `漏洞提醒` | 漏洞订阅状态（可现场开/关/调级别） |

### 🔵 第二层 · 能力自证（成本低、证明力强）
- **「列出你可用的技能包名称」** → 直接验证 23 个技能包是否真加载
- **「用 skill 工具加载 `attack-surface-recon`，按它的方法论给我一份攻击面自检清单」**
  → 证明技能包**可执行**，而不只是可列出

### 🟣 第三层 · 角色对比（演示冲击力强）
`角色 CTF` 问一道 pwn 题 → 再 `角色 二进制分析` 问同一题。
同一问题、不同角色给出不同视角，直接体现「角色 = 系统提示词编排」。

### 🟠 第四层 · 服务端强制拦截（评审最吃这个）
让 Agent 创建绑公网的反弹 shell 监听器 → 被 `internal/c2/listener_policy.go` 拦掉并回「安全策略拒绝」。
这是**服务端硬拦**（create / start+重启恢复 / MCP update / HTTP update 四入口全覆盖），
不是前端弹窗提示；配合起服日志里的「恢复 C2 listener 失败 … 安全策略拒绝」构成完整闭环证据。

### 🔴 第五层 · 一次性重活（贵，只留给决赛现场）
完整渗透报告。用户 2026-10-03 实测：对本平台发一次渗透测试，约 20 分钟出报告，
代价是**几十万 token**。

### ⛔ 明确不要做
- **别反复跑全量渗透**。免费额度是**每模型各 1M tokens**，用到即停；
  一次全量渗透就能烧掉一个模型的全部额度，其余请求会以 403 `Free quota exhausted` 失败。
- 换模型能续命（每个模型是独立池子），但别拿它当日常压测。

## 5. 已知陷阱（具体事故形态）

| 陷阱 | 具体形态（什么时候会咬人） | 规避动作 |
|---|---|---|
| Go `Sscanf("%x")` 不吃 `0x` 前缀 | 解析 objdump/immediate 的 "0xc0" 形态 → 静默返回 0（const-compare 三槽全零，真题回归才暴露） | 用 `strconv.ParseUint(s,16,64)`；signed int 还会溢出 64 位 movabs 立即数 |
| 共享工作区索引竞争 | 并行会话与本会话同仓并发 commit：我方 commit 被吞（索引被对方冲洗）、ref lock 冲突、对方的暂存文件混入我方 commit | 显式路径 add；commit 后 `git log --oneline -1` 复验；被吞就重提（工作内容在盘零丢失） |
| venv python.exe 双层结构 | workbuddy venv 的 python.exe 是启动器+真解释器，一个逻辑进程显示 2 个 → 按"进程名计数"判活必误判双开 | 按命令行匹配计数（≥2 层=1 个逻辑 runner）；race_preflight.py 已实现 |
| 共享 venv 依赖漂移 | workbuddy 默认 venv 被任何项目的 pip 操作改写（opentelemetry 1.32→1.45 曾崩掉赛时引擎；numpy 曾消失） | 赛前 `race_preflight.py` 必跑；赛时引擎用专用 venv；CTF_PYTHON_PATH 已 setx 钉死 |
| bin_* 求解器撞名 | 并行会话 forensics 引擎已占 tryZipChain/solveZipChain 等名（关键词提示检测器） | 新求解器先 grep 重名；真实现与提示检测器互补共存，注册名区分 |
| data/ctf_benchmark 为 gitignored 区 | xhlj_legacy 账本/资产不入 git（随区留盘）——删除该区 = 账本消失 | 账本要点同步进 docs/（已做）；勿"清理"该区 |
| TestCTF2LiveTargetChain 常红 | CTF² 平台 403 WAF 冷却（打赛+探针惹热），0.2s 即失败 | 环境项非回归；全包回归以"新增 FAIL 数==0"为准，不看绝对数 |

## 3. 最快实现路径（可直接执行）

1. **占位**（跑批前必做，否则实例可能被别的会话杀）：
   `python3 ~/SecAutoMind/scripts/session_registry.py claim --id S2-crypto14-26 --slice crypto14-26 --port 18091`
2. **建队列**（仅在尚无队列时；已有则跳过到 3）：
   `cd ~/sam_s1 && python3 scripts/stepfun_s2_server_batch.py --phase create --base http://127.0.0.1:18091 --pw-file ~/sam_s1ms/data/admin_initial_password.txt`
3. **先冒烟 1 题验证解析**（可选但推荐）：
   `... --phase smoke --base http://127.0.0.1:18091 --pw-file ~/sam_s1ms/data/admin_initial_password.txt`
4. **启动全量**：
   `... --phase start  --base http://127.0.0.1:18091 --pw-file ~/sam_s1ms/data/admin_initial_password.txt`
5. **轮询出账**（完成自动写 ledger 到 `~/sam_s1/data/ctf_benchmark/stepfun_sessions/`）：
   `... --phase poll  --base http://127.0.0.1:18091 --pw-file ~/sam_s1ms/data/admin_initial_password.txt --max-wait 3600`
6. **释放占位**：
   `python3 ~/SecAutoMind/scripts/session_registry.py release --id S2-crypto14-26`
7. **拉账回本地**：
   `scp user@172.16.222.99:~/sam_s1/data/ctf_benchmark/stepfun_sessions/s2_server_crypto14_26_*.json /e/Program/SecAutoMind/data/ctf_benchmark/stepfun_sessions/`

> 注：S2 脚本无 `--queue-id` 时从 `~/sam_s1/data/ctf_benchmark/stepfun_sessions/s2_queue_meta.json` 读上次 create 的 queueId，故 create 与后续 start/smoke/poll 不必重复传 queue-id。

## 5. 已知陷阱（具体事故形态）

| 陷阱 | 具体形态（什么时候会咬人） | 规避动作 |
|---|---|---|
| **证据门禁 `missing_execution_evidence`** | 批次执行器硬编码 `RequireExecutionEvidence=true`（`internal/handler/batch_queue_executor.go:299/302`）。模型只文本作答、未产生 completed tool execution → 整任务判 `failed`，与答案对错无关。S1 首跑整批 failed 根因。 | `task_text` 强制"你必须使用 execute 工具实际运行代码…禁止心算猜测"。S2 已打此补丁并冒烟验证门禁放行。 |
| **SamClient 口令硬编码路径** | `SamClient._read_initial_password()` 读 `~/sam_s1/data/admin_initial_password.txt`（对应 18086 实例）。若 `--base` 指向 18091，口令对不上 → 登录失败 `RuntimeError`。 | 加 `--pw-file` 显式传 `~/sam_s1ms/data/admin_initial_password.txt`。S2 已加。 |
| **YAML 缩进导致通道被丢弃** | `ai.channels` 子键若缩进错（与 `ai:` 同级而非其下 4 空格子级）→ 整段通道被丢弃，静默回退 `zhipu/glm-4-flash`（无 CTF 能力）。S1 `config.tokenhub.yaml` 实锤：`ai.channels=None`，即使写 `default_channel: tokenhub` 也回退。 | 改配置后必跑 `python3 -c "import yaml; c=yaml.safe_load(open('config.yaml')); print(list(c['ai']['channels'].keys()))"` 确认通道非空。 |
| **MD5 还原类环境不可解** | 题面"还原 MD5：<hash>"依赖字典/彩虹表爆破，但服务器沙箱无 rockyou/hashcat 词表；18091 的专用 `ctf_hash_crack` 内置词表也未覆盖。S1 `hash_md5`、S2 idx14（`03d9fdd9db520fbbb59cce27128b92e7`）均解不出。模型在 MD5 题上还会声称"工具集里没有 execute"（疑为解不出时的合理化说辞；S1 `xor_ff` 真用 execute 命中过，间接证明 execute 已挂载）。 | 出账时单列"环境不可解"，**不计入模型能力缺口**；不要据此判模型弱。 |
| **免费额度中途 402** | TokenHub `deepseek/deepseek-flash` 免费额度中途耗尽 → `402 Payment Required` → 任务 failed（非模型失败）。S1 `hash_md5`/`xor_ff` 实锤。 | 换 ModelScope 2000/天 免费池（18091）。若 18091 也耗尽，新建实例切 TokenHub 或 AMD Token Factory。 |
| **stepfun 付费通道限流** | 18086 默认 `default_channel: stepfun`（阶跃星辰 step-5-preview），已被限流，不符合"换免费 key"要求。 | S2 一律改打 18091（免费 ModelScope），不依赖 18086 默认。 |
| **占位超时互杀** | `session_registry` 心跳超 45 分钟失效；不 claim 会被别的会话按同 (host,port) 互斥杀实例（真实事故：S5 实例 3 分钟被杀）。 | 跑批前 `claim`，跑完 `release`；同一 (host,port) 活跃 ≤5。 |

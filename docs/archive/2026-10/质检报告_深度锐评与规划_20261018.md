## 2. 真诚的优点（先说清楚：这些确实做得好）

1. **「证据优先」的罕见文化**。`AGENTS.md` 是一份**事件驱动的协作宪章**（8 条），每条几乎都能追溯到一次真实事故。例如：第 3 条「Edit 会假成功（已 3 次）」、第 5 条「已知环境坑照抄即可」、第 8 条「定义齐全 ≠ 接线」。这种「把踩过的坑固化成规则」的做法，在参赛级项目里极罕见。
2. **门禁有牙齿，且自证**。门禁不是摆设：**关键门禁有变异验证**（注入错误必须变红）、**自测脚本成对存在**（`*_test.py`）、**取不到真值时 fail-closed 而非静默放行**。本次随机抽验 `secret_guard.py` 确认：指纹库为空 → 默认 BLOCK（`return 1`），仅显式 `--allow-no-fingerprint` 才降级为「形态匹配 + 人工复核」——**「锁装了且锁死了」**。
3. **三把尺的诚实基准学**。项目明确区分：自产集（开卷、**明令不得作能力证据**）、真题集（对外的唯一有效尺，真求解器 16/55=29.1%）、外部对照尺（Google CTF 0/40，**只作对照、不得并入 KPI**）。并有 `quant_effect.md` 机验声明表 + `check_quant_effect.py` 逐条复跑。**「自产 97.2% 不得当战果」写成了机器闸门**——这是多数团队做不到的自我克制。
4. **交付面数字本轮确实收口**。磁盘实测：`installer/secautomind-ai.exe` = 89,518,080 B ≈ **89.5 MB**、`SecAutoMind-Setup-1.7.28-x64.exe` = 20,326,591 B ≈ **20.3 MB**，与 MEMORY 记录的 `exe_mb/setup_mb`「实测 20.3/89.5」**逐位吻合**；官网「142 运行时工具」出现 5 次、陈旧值「140」出现 0 次。→ **数字同步纪律当前是成立的**。
5. **前一轮 QA 的 P1/P2 项确已闭环**（本次独立复验）：`default_config.yaml` 的 `default_mode` 已是 `approval`；`flagWrapperRe` 已与真源逐字对齐；`codeIsSuccess` 只认字符串 `"00000"`；HITL 处理器 `_, _ =`（吞错）计数 = 0。
6. **架构对齐赛题维度**。规划/执行/审计/复盘四个 Agent + 事实黑板 + HITL 审批 + 全链路审计，直接回应赛题「决策逻辑与可解释性」评分维；单二进制、离线可跑，部署门槛低。

## 4. 锐评（不客气的那部分）

1. **「护城河」放错了位置。**
   项目的投入产出极不均衡：**约 100 个脚本、8 条宪章、24 job CI、六道交付红线**，换来的是**可复现、可追溯、口径诚实**——这当然珍贵。但**决赛 60% 按解题得分**，而硬实力指标是 **外部真题 0/40、cross-bench 1.1%、求解器 7 个**。把 90% 的工程火力花在「证明自己是诚实的」，而把「真的能解题」留作短板，是**用过程可信替代了能力领先**。评委可能被材料说服，但**靶机不会被材料说服**。

2. **存在明显的「元工程 / 过程剧场」倾向。**
   「门禁的门禁」「门禁的变异测试」「修复器必须与判红门禁共用判据」「豁免数字 ≠ 豁免状态」……这些表述精确，但数量已到**自我循环**的程度。项目自己也承认反复被同族问题咬（空洞绿四形态、Edit 假成功 ×3、冻结哈希 CI 失败）。**当维护『证明链条』的成本开始逼近被证明的价值时，边际收益已经转负。** 近几轮把精力放在官网数字/PPT 重产/包体瘦身，是这种倾向的延续——**越是临近截止，越容易陷入『雕琢交付物外观』而非『提升交付物实质』**。

3. **「自产 97.2%」这类数字对项目是负资产。**
   项目已经非常诚实地承认它「是开卷考试、不得作能力证据」。既然如此，**保留它对内作回归集可以，但任何对外叙事里出现它都只会稀释可信度**。真正的能力叙事应只有一把尺：**真题 16/55=29.1%**，以及**主动公开的对照尺 0/40**。诚实到「自曝其短」是加分项，但**别让弱能力被一堆漂亮的过程指标淹没**。

4. **最大的风险点，恰恰是唯一「不归自己管」的事。**
   P0 资格项（仿真平台联调）100% 卡在外部 Agent Key；生产机还漂移了两个版本；HITL 人类档实证未跑。**当前项目把可控的做到了天花板，却把不可控的留成了悬崖。** 一旦赛场权限当天未就绪，所有工程纪律都救不了现场。**必须把「外部阻塞」当成一等公民来规划（见 §5 P0），而不是写个 runbook 就冻结。**

5. **代码层面最该警惕的不是「大」，而是「耦合」。**
   `agent.go` 2708 行/72 函数、`config.go` 2249/95——函数不算巨型，但**单文件承载的职责过多**，改动风险与认知负担都在积累。决赛冻结期（<14 天不动架构）这是**对的**；但**冻结结束后必须优先级最高地拆**，否则下一轮只能继续堆。

6. **安全上没有「已经安全」，只有「还没被利用」。**
   公开仓历史里躺过两把真 key，清理 ticket 还没审完，依赖里还挂着「无补丁」的 `imaging`。这些都属于**「知道但没关」**——工程纪律再强，**未闭环的风险照旧会兑现**。

## 5. 规划（优先级路线图）

> 原则：**先保资格与安全，再补能力，后清工程债；冻结期内不动架构；一切承诺可机验。**

### P0 — 决赛资格与不可逆风险（本周内）
1. **仿真平台：从「runbook」升级为「可运行的降级链」**
   - 建 **mock 平台 harness**：本地/CI 起一个返回 `code=="00000"` 的桩，**把 `Presolve → 平台 API → 提交 flag` 全链跑通并进 CI**，证明「拿到 Key 即通」。
   - 固化 **错误码谱系**（`40403/无权限`、鉴权失效、题目列表展平、靶机地址格式），做出「异常 → 人话提示」映射。
   - **明确外部动作 owner 与 deadline**：确认 Agent Key 归属与开通时点（人）。
   - **验收**：`verify_live_contract.py`（解除时间锁后）在 mock 上级 rc=0；真机拿到权限后 5 分钟内一键复验通过。
2. **泄露凭证收口（不可逆）**
   - **验收**：对 PUBLIC 全量对象流式 grep 三处旧指纹 = 0 命中。
3. **生产机对齐**
   - 拍板重部署策略（含 bot 长连接重连窗口），令生产构建 == HEAD。
   - **验收**：`go version -m` 读生产二进制内嵌 commit == HEAD 且无 `+dirty`。

### P1 — 能力（决赛 60% 的胜负手）
4. **求解器扩容（选择性、按类别加权）**
   - 以 `external_bench` / `cross_bench` 的**失败归因分类**为抓手，优先补 crypto（RSA 变体 / LFSR / GF(2) 高斯消元 / 格）、常见 web/pwn 静态解析。
   - **不追求数量对齐 58，只求「决赛高频类别」覆盖**；每个新求解器必须带 sha256 机验样例。
   - **验收**：外部对照尺从 0/40 有可见抬升（如实报告，不得设「通过阈值」）。
5. **单题止损（低成本高回报）**
   - 引入**单题时间预算 + 提前放弃/降级**；对慢工具（URL 渗透链）设类别门控与硬超时。
   - **验收**：构造「会超时的题」，断言在预算内止损并继续下一题。
6. **HITL 人类档实证（副 RQ-B）**
   - 按招募方案跑 ≥8 名导师 blinded 评测；阈值先定后看数；无论好坏如实报告。
   - **验收**：`hitl_failure_boundary.md` 出可复现实验脚本 + 数字。

### P2 — 工程债与安全卫生（冻结期后）
7. **依赖治理**：替换 `imaging` 或显式接受并留痕；升级 `ecdsa`。
8. **God-file 拆分**：`agent.go` / `config.go` / `robot.go` / `mcp/server.go` 按职责拆分，**先补测试再拆**。
9. **分发物纳入 CI 可见**：installer/PPT/dist 的构建与校验进入流水线，终结「untracked → 静默累积」。
10. **包体与公开仓策略**：评估 `dist/*.tar.gz`(179MB)/`ai.exe`(89.5MB) 是否应留在源仓（可移 Release/对象存储）。

### P3 — 治理与叙事收敛
11. **文档合并去重**：把 2 份质检、多份规划/清单**合并为单一「现状 + 路线」活文档**，历史报告归档。
12. **补人类向文档**：`CONTRIBUTING.md` / `ARCHITECTURE.md`（英文摘要 + 中文详版）。
13. **KPI 换轨**：从「门禁数 / 接线数」转向「能力指标 + 安全闭环率 + 单题止损命中率」；**停止新增门禁**，改为维护现有门禁的**健康度**。
14. **叙事重排**：对外只用「真题 29.1% + 对照 0/40 + 反注水机制」三件套，弱化「工具堆叠」和工程黑话。

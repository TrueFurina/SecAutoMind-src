## 一、改动前：一条命令收不了口

`python scripts/fix_material_numbers.py --apply --check`（`check_material_numbers.py:748`
明确推荐的修复命令）在干净检出里：

- 落盘 **12 个文件 / 31 处数字**，但复跑 `check_material_numbers.py` → **exit 1**；
- 残留红项两类：① `[FAIL] 已知漂移登记有问题 3 处` —— 官网 3 条登记项
  「已不再复现」（被同步器刷成了真值，台账过期）；② `[FAIL] 口径修复清单状态` 1 处；
- **`官网/index.html` 5 行被刷** ⇒ 直接违反用户 2026-11-08「官网不用动」裁定；
- 把官网手工 `git checkout --` 恢复后：门禁 **RC=0 PASS**、自测 **13/13 PASS**
  ⇒ 证明「刷完再手工恢复官网」是**必需但完全隐含**的一步，没有任何工具保证。

**根因**：`fix_material_numbers.py` 复用了门禁的 `ANCHORS` / `FROZEN_MATERIALS` /
`EXEMPT_FILES` / `SNAPSHOT_MARK`（其设计原则即「不允许两套判定并存」），
却**漏了 `data/ctf_benchmark/material_known_drift.json`** ⇒ 门禁认「已裁定不修」，
修复器不认。同一份裁定在两套工具里不一致。

## 二、改动：让同步器认同一份登记

| 位置 | 改动 |
|---|---|
| `scripts/fix_material_numbers.py` | 新增 `_num()` / `_drift_skip_keys()`：复用 `cmn.load_known_drift()`，按 `file + label + 去千分位数值` 生成跳过集合；台账自身有问题（过期 / 超限 / 字段缺）⇒ **返回空并告警，不据此跳过**（fail-closed，坏台账不能变成静默放水） |
| 同上 `fix_line()` | 新增可选 `skip=frozenset()`，在 HTML 分支与通用 `_repl` 分支都判断；命中即保持原文、不计入 `changes`（默认空 ⇒ 直接调用方行为不变） |
| 同上 `collect()` | 载入跳过集合并按 `rpath` 精确传入（`cmn.rel()` 已归一正斜杠，与登记 `file` 可比） |
| `scripts/fix_material_numbers_test.py` | 新增 T14~T18 五条变异：登记项保持原文 / 数值不匹配仍改写 / HTML 分支同样跳过 / 坏台账 fail-closed / 真实登记可解析（官网 3 条） |

跳过粒度是 **`(file, label, 数值)` 三元组**，不是整文件豁免：
官网同文件里若出现未登记的新漂移，照常会被刷。

## 四、发布节点 SOP（两步，顺序不可颠倒）

1. `python scripts/fix_material_numbers.py --apply --check` → 刷规模数字，门禁与自测转绿；
2. `python scripts/build_championship_evidence.py` 再 `--check` → 证据包转绿。

🔴 **第 2 步必须在 clean / Linux 环境**（CI 或干净 worktree）：本机存在
`installer/secautomind-ai.exe`，直接重生成会把 `present=false → true` 并写入
Windows 专属 md5/size，在 CI（ubuntu 无 exe）反而**新增**漂移。这是
2026-11-08 已实测过的污染路径，本轮在 worktree 里复核了 canonical 状态。

⚠️ **主工作树 `fix_material_numbers_test.py` 当前仍 RC=1**（T10：26 处未刷），
属既有状态、非本改动引入；`ci.yml:625` 会跑它 ⇒ **推上去之前必须完成第 1 步**。
本改动的价值不是让这个红消失，而是让第 1 步「一条命令即可正确收口」。

# xfyun 实际模型确证：generalv3，不是 lite（2026-10-26）

## 问题

上一轮 xfyun 跑批（30 次调用 / 0% 坏 JSON）时，配置快照打印 `light = lite`，
但日志不记录 `payload.model`，无法确认实际请求的是哪个模型。

## 解法：用能力差异反推（零代码改动）

模型自述不可用——问「你是什么模型」，两个都回套话（「讯飞星火认知大模型」）。
改用**长上下文定位能力**做指纹：塞 ~6000 字填充文本，问「最开头第一个词是什么」。

## 结果（可复现）

```
不设 CTF_AGENT_XFYUN_MODEL（→ 默认 lite）: '无'          ← 答错
设   CTF_AGENT_XFYUN_MODEL=generalv3      : '无关文本。'  ← 答对
```

| 请求 | 响应 | 判定 |
|---|---|---|
| `model='lite'` | `无` | lite 上下文不足，定位失败 |
| `model='generalv3'` | `无关文本。` | 定位成功 |
| **不传 model（跑批路径）** | `无关文本。` | **= generalv3** |

## 结论

✅ **上一轮 xfyun 跑批用的是 `generalv3`，不是 `lite`。**

原因：`llm/client.py:751` 在 `attempt < upgrade_after` 时读 `CTF_AGENT_{PROVIDER}_MODEL`，
该路径**不经过** `AppConfig.from_env()`（后者只读全局 `CTF_AGENT_LIGHT_MODEL`），
所以配置快照显示 lite 是**快照偏差**，不代表实际请求。

## 对上一轮对比结论的影响

| 项 | 原表述 | 修正后 |
|---|---|---|
| xfyun 模型 | 不明（快照显示 lite） | **generalv3** |
| 坏 JSON 对比 | glm-flash 28% vs xfyun 0% | **成立**，且是 generalv3 对 glm-4-flash |

⚠️ 仍需注意：xfyun 侧依然只有 **单题单轮（n=1, 30 次调用）**，
「换模型能提升解出率」仍然**不能**下结论（xfyun 该轮 0/1）。

## 顺带记录的观测缺陷

`AppConfig.from_env()` 与 `_resolve_settings()` **读模型的路径不一致**：
前者只认全局 `CTF_AGENT_LIGHT/HEAVY_MODEL`，后者优先认 `CTF_AGENT_{PROVIDER}_MODEL`。
⇒ **配置快照会骗人**。看模型必须看实际请求，不能看快照。

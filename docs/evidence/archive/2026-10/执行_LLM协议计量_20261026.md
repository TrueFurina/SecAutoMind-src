# 执行：LLM 输出协议计量打通（2026-10-26）

## 目标

把「模型输出不合协议」从 `tool_failure` 桶里独立出来 —— 今天已证明二者性质不同：
`tool_failure` 会让人去修工具模块，而真因是模型不吐 JSON（glm-4-flash 28.1%）。

## 改动（5 处，全部只增字段/只计数，不改任何判定）

| 文件 | 改动 |
|---|---|
| `llm/client.py` | `ai_chat_json_with_usage` 在「有内容但非 JSON」处置 `_LAST_LLM_UNPARSABLE`，新增 `consume_last_unparsable()` |
| `core/phases.py` | `plan_step` 返回后立即消费标记，计入 `protocol_fail` |
| `core/main_agent.py` | `__init__` 初始化 `_llm_parse_metrics` |
| `eval/benchmark.py` | `BenchmarkResult` 收字段 + `summary.llm_output_health` 汇总 |
| `run.py` | 把 agent 的计量挂到单题 output |

## 踩的两个坑（都值得记）

### 坑 1：改错了函数

`llm/client.py` 有**三个** JSON 入口，`run.py` 实际走的是 `ai_chat_json_with_usage`（带 token 记账那个），
我先后改在 `ai_chat_json` 和异步版上，都不生效。
**判据：改埋点前先 `grep` 调用链确认真正入口，不要凭函数名猜。**

### 坑 2：标记打在了 return 之后

第一版把置位写在兜底 `return recovered` **之后**，而实测 **7/7 次坏 JSON 全部被兜底成功恢复**，
于是标记永远置不上，`protocol_fail` 恒 0。

**判据：兜底成功 ≠ 模型守住协议，只是框架替它擦了屁股。计量必须放在兜底之前。**

## 追加：P4 模型名可观测（同日完成）

成功路径原本**不记模型名**（只有失败行 `payload.model=` 有）。
起因是「配置快照显示 lite、实际发 generalv3」无法从产物证伪。

已在 `llm/client.py` 成功返回处补 debug 级日志：

```
DEBUG llm.client: LLM 调用成功 provider=glm model=glm-4-flash
```

用 debug 级而非 info：真实跑批日志量大，默认不刷屏；需要核查时把日志级别调到 DEBUG 即可。

# 未命中归因：把 `cand=0` 拆成三种相反含义（2026-11-01）

> 一句话：报告里一个 `cand=0` 此前同时代表「模型没答」「模型编了个假答案」
> 「模型给了候选但我们没接住」。这三件事要修的东西完全不同，却长得一模一样。
>
> 提交：`7b77434`（能力）、`927541f`（去重与措辞）。

## 1. 问题：一个数字，三种含义

2026-11-01 的复盘里发现 Primes 在第 10 轮自造了 `CTF{YkDOLI...}`
（sha256 `b92b5b9b…` ≠ 真值 `df18e59d…`），而报告里它与「模型一句话没说」
完全同形 —— 都是 `cand=0`。这两个结论的处置方向正好相反：

| 报告显示 | 真实情况 | 该修什么 |
|---|---|---|
| `cand=0` | 模型没产出任何 flag 形态 | 补能力：提示、工具、预算 |
| `cand=0` | 模型产出了候选但被扣下 | 补幻觉抑制 / 收口策略 |
| `cand=0` | 通道挂了，根本没跑 | 修基础设施（已由 `ErrLLMUnavailable` 处理） |

## 2. 顺带查明的第二件事：模型自己写的 flag 从不参与判分

监督的候选扫描块整体位于 `if len(resp.ToolCalls) > 0` 内，扫的是
`roundObs` —— **只含工具输出**。所以：

- 模型在带工具调用的轮次里，**正文**中写的 flag → 从不提取；
- 模型把 flag 塞进**工具参数**（"拿这个去验一下"）→ 从不提取。

Primes 的假 flag 正属于这一类，因此 `candSeen` 一直是 0，报告写 `cand=0`。
本轮只做**可见化**（计入 `dropped`），**不改变提交语义**。

## 3. 修法

新增 `internal/runnerl3/outcome.go`：

- `classifyMiss` 是唯一判据（纯函数，无 IO），五种取值：

| 取值 | 含义 | 该修什么 |
|---|---|---|
| `no_candidate` | 全程零候选 | 能力/提示 |
| `candidates_suppressed` | 产出过候选但一个没交出 | 幻觉抑制 / 收口（含预算内未收口） |
| `answered`（报告层细化为 `answer_wrong`） | 交出了候选，判分另算 | 答案错，非管理问题 |
| `llm_unavailable` | 通道全不可用 | 基础设施（非能力） |
| `disabled` | 未启用 | 配置 |

- 用**单个 `defer`** 记录：`Solve` 有 8 个以上 return 点，逐点手写必漏，
  将来新增 return 还会继续漏；
- 反幻觉闸门打回、以及非终局轮的模型正文/工具参数，全部计入 `dropped`
  （**去重**，与 `bestCandSeen` 同口径）；
- 日志级从 `Debug` 提到 `Info`：此前唯一能区分两种 `cand=0` 的那条
  `"没找到 flag 格式"` 是 `Debug`，而跑批默认 `Info` ⇒ 最需要时恰好不可见。
- `llmbench` 报告新增 `miss_reason` 与 `dropped`，只在未命中时写。

## 4. 真机验证（DashScope / deepseek-v4-pro / `NO_FALLBACK=1` / `CTF_AIRGAP=1`）

三题连跑（`/tmp/fv4`，HEAD 干净构建）：

| 题 | 耗时 | cand | hit | `miss_reason` | `dropped` |
|---|---|---|---|---|---|
| Enigma | 132.2s | 0 | false | `no_candidate` | — |
| Primes | 300.0s | 0 | false | `candidates_suppressed` | 8（按次计，旧口径） |
| ZIP | 104.6s | 0 | false | `no_candidate` | — |

单题复跑 Primes（去重版）：

```
Primes  54.3s  cand=1  hit=false  reason=answer_wrong  dropped=1
```

被扣下的那个候选经 sha256 核对 **≠ 真值** —— 也就是说本轮**没有**发生
「算对了却被丢掉」，`dropped` 记录的确是幻觉，不是被误扣的正确答案。

> 核查方式：只取日志里的候选串算 sha256 与 `flag_sha256` 比对，
> 明文不落盘、不入库。

## 5. 变异验证（4 次，全部精确变红）

测试绿不等于测试有效，所以逐条破坏：

| 变异 | 预期 | 实际报错 |
|---|---|---|
| 删 `suppressed` 分支 | 红 | `= no_candidate，期望 candidates_suppressed` |
| 删 `defer` | 红 | 三条 Solve 归因测试同时报 `实际 ""` |
| 删闸门记账 | 红 | `闸门打回必须记 candidates_suppressed，实际 no_candidate` |
| `dropped` 退化为按次计 | 红 | `同一候选出现 2 次应记 1，实际 2` |

**第一版接线测试是假绿**：它测的是 `disabled` 分支的显式 `set`，
把 `defer` 整段删掉依然通过。是变异验证把这层假绿暴露出来的，
随后换成三条真实退出路径（no_candidate / 闸门打回 / 正常交出）。

## 6. 未解释的部分（不在本次声称范围内）

同一题、同一模型、同一配置，两次跑差异极大：

```
第一次：300.0s（正好吃满整题预算）  cand=0  candidates_suppressed
第二次：  54.3s                    cand=1  answer_wrong
```

两次都没有命中，但「没命中的方式」不同：一次是预算内没收口，一次是收口了但答错。
这说明 `candidates_suppressed` 里还混着「收口速度」这一层方差，本轮**没有**
拆分它，也没有解释原因。任何基于单次跑批的结论都必须带上这个前提。

## 2. 不可归因的部分（本次新增结论）

14 行未解**全部**缺 `llm_rounds` / `truncated_rounds` / `api_error_rounds` /
`timeout_rounds` 四个字段。这些字段由 `scripts/ctf_stepfun_orchestrator.py`
的 `solve_one()` 写出，而结果文件生成于 2026-11-07 02:46，早于该埋点。

后果：那 10 次空答**分不清**是

- `finish_reason=length`（输出预算被推理吃光 → 工程上限，抬预算可救），还是
- 模型自己收尾说「不会」（能力边界），还是
- 第一轮就只回了 reasoning、`content` 为空（同族但成因不同）。

三者修法相反，故**不得**把这 10 次任一归到「能力」或「病理」。此前流传的
「空答是解码病理不是能力边界」是**推断**，不是测量结果。

## 3. 已就位的观测（重跑即可归因）

`solve_one()` 现在（agentic 与 pure 两个分支都）落：

| 字段 | 作用 |
|---|---|
| `llm_rounds[]` | 每轮 `finish_reason` / `reasoning_chars` / `content_chars` / `tool_calls` |
| `truncated_rounds` | `finish_reason=="length"` 的轮数 |
| `api_error_rounds` / `api_error_first` | HTTP 4xx/5xx、连接失败——**分母污染**，必须剔除 |
| `timeout_rounds` | 服务端长尾 / 墙钟耗尽 |
| `inline_chars` / `artifact_files` | 附件到底喂了多少字符进 prompt |

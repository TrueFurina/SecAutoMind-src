# CI 收集集被可选依赖静默缩小 · 2026-11-09

> 结论先行：上一轮把两端全量门禁的数字差异（本机 2153 / 服务器 2169）解释成
> 「Python 3.14 / 3.12 与 deselect 记账表的既有差异」——**这句话没量过，而且全错**。
> 实测差异 100% 来自本机与 CI 都漏装了 `python-flint`：
> `tests/test_crypto_knapsack_mhk.py` 模块级 `pytest.importorskip("flint")`
> 让 **11 条格基 LLL 背包密码能力用例在 collect 阶段整块消失**，
> pytest 报告连一行 skip 都没有，门禁照绿。
> 补齐依赖后端收集数逐项一致（2203/2293，90 deselected）；
> 另加一道从 AST 自动守「可选依赖不许缩小收集集」的门禁，防下次重演。

### 2.3 根因

`tests/test_crypto_knapsack_mhk.py:53`：

```python
flint = pytest.importorskip("flint", reason="格后端 python-flint 未安装")
```

模块级 `importorskip` ⇒ 整个模块在 collect 阶段静默消失。依赖链：

| 位置 | 状态 |
|---|---|
| `CTF-Agent_融合/ctf_agent/requirements.txt:32` | ✅ 声明 `python-flint==0.9.0` |
| `ci.yml` pytest job 的 `pip install` 显式清单（15 个包） | ❌ 漏 `python-flint` |
| 同 job「装完立刻自检」的 `need` 列表（15 个模块） | ❌ 漏 `flint` |
| 服务器 `~/sam` 环境 | ✅ `flint 0.9.0` 已装 |

⇒ 这 11 条**从未在 CI 跑过**；本机也从未跑过；只有服务器（唯一跑题机）跑过。
而 CI job 名与历史文档里写的「2212 cases」之类数字，把静默缩小的覆盖面盖住了。

### 2.4 反证：补装后逐项对齐

本机 `python-flint 0.9.0` 有 `cp314-cp314-win_amd64` wheel（腾讯云镜像），
`pip install --no-deps` 后：

- `import flint` → `0.9.0`；
- collect 变成 **`2203/2293 (90 deselected)`**，与服务器逐项一致；
- 单跑这 11 条：`11 passed, 1 deselected in 7.31s`。

⇒ 与 Python 版本、deselect 表**都无关**，就是这一个包。上一轮的解释作废。

## 3. 修法（两层）

### 3.1 补这一次的洞

- `ci.yml` pip 清单加 `"python-flint>=0.9,<0.10"`；
- 「装完立刻自检」的 `need` 加 `flint`；
- 本机补装，使两端与 CI 的收集集合一致。

### 3.2 堵这一类洞

只补一个包名，下次谁再加 `importorskip`（或某个包在 CI 装失败），同样静默。
新增 `CTF-Agent_融合/ctf_agent/scripts/check_ci_optional_deps.py`：

- **AST** 扫 `tests/**/*.py` 的 `pytest.importorskip("X")` 字面量，
  取顶层模块名（`PIL.Image` → `PIL`，`Crypto.Cipher.AES` → `Crypto`），
  逐个 `importlib.util.find_spec` 验证；缺一个就点名文件/行/模块并 RC=1。
- 用 AST 不用正则：注释与字符串里的 `importorskip` 不误判
  （同族前科：`_registry_threaded_proven` 被注释骗成假阳性）。
- 非字面量参数 / 语法解析失败 ⇒ **RC=2 fail-closed**，判不了就不许报绿。
- 实扫结果：17 处 `importorskip`、**9 个完整模块路径 / 7 个顶层包**
  `Crypto / PIL / brotli / cryptography / flint / gmpy2 / zstandard`，两端均齐全。
- `--selftest` 第一版 7/7；§7.1 补完整路径判据后 **9/9**：原件绿、缺包必红、
  注释/字符串诱饵不误判、非字面量 fail-closed、完整路径齐全绿、
  父包在但子模块缺必红、顶层缺失的带点路径必红、反向回绿、语法坏文件 fail-closed。

接线（AGENTS.md 第四条：门禁必须进 CI 且自身有回归测试）：

| 位置 | 内容 |
|---|---|
| `ci.yml` | 两个新 step：`--selftest` 与本体，位于依赖安装完成后、全量 pytest 之前 |
| `scripts/verify_capability_evidence.py` | `EXTERNAL_GATES` 第 **14** 条（两端五段门禁都会跑） |
| `scripts/capability_caliber_test.py` | 头部与第 4 段标签 13 → 14 |

## 6. 方法论

这是同一天内第三次撞到同一个形状：**用一句听起来合理的解释，替代一次可以做的测量**。

1. 上一轮：「改判分口径会让历史 verdict 失效」→ 实测 349 格 / 19 批次零分歧 ⇒ 假的。
2. 本轮：「两端差异是 Python 版本与 deselect 表的既有差异」→ 实测是漏装一个包 ⇒ 假的。
3. 更早：「按既有口径整批剔除」→ 验证发现口径根本不剔除 ⇒ 假的。

三者的共同点不是「不小心」，而是**解释越顺口越没人去量**。
「不要把它读成少跑」这类劝告式结论，尤其要当成待验证主张看待。

## 7. 补测：13 条 pass/skip 分配差（19:03 续）

§4.1 第一稿写「分配差 13 条是平台相关 skip，未逐一归因」——又是第四句顺口的
解释。两端各跑一次 `-rs` 导出 skip 原因清单，归一化路径分隔符后按原因对比：

| 来源 | SKIPPED 行数 | 报告 skipped |
|---|---|---|
| 本机 | 19 | 21 |
| 服务器 | 30 | 34 |

行数净差 11，与报告差 13 相差 2/4 条，来自 `-rs` 未列出的模块级 skip，
**这两条未逐一归因**（不补理由）。按原因拆开：

| 服务器多 skip 的原因 | 条数 | 性质 |
|---|---|---|
| 真实附件缺失（.gitignore 排除）/ 题库为空 | 4 | 数据缺失，公开仓有意设计 |
| 缺 tesseract / 字体 / OCR 读回花括号 | 5 | **测试内有意的能力探测跳过**（见 §7.2 勘误） |
| WABT 未安装 | 1 | 服务器确缺 WABT 系统二进制 |
| 无探测快照 | 1 | 本地产物未入库 |
| Job Object 级联收割是 Windows 语义 | 1 | **唯一真正的平台语义差异** |
| 未配置 deepseek key | 1 | 配置差异 |

本机另有 2 条（真实 LLM smoke 未开启、题库缺失原因文本带本机路径）与之抵消。

🔴 结论修正：**「平台相关」只对了 1/13**。绝大多数是数据缺失 / 测试内
有意的能力探测 / 配置差异，不是平台语义。本机缺 `python-flint`（§2），
服务器缺的是 WABT —— **两端覆盖互补，没有任何一端是完整的**。

- 工具探测：`wat2wasm` / `wasm2wat` 在服务器上确为 `MISSING`；
  `test_wasm_probe.py:136` 靠 `wp._wabt_available()`，需要系统二进制。
- `sudo -n true` ⇒ `sudo: 需要密码`，WABT 那 1 条本会话无法 apt 补齐，挂账给管理员。
- 🔴 **tesseract 那 5 条的解释后来被推翻**，见 §7.2：服务器其实装了用户态
  tesseract 5.5.3，skip 是测试内的 `_ocr_reads_braces()` 能力探测主动跳过。
- 🔴 **收集集一致 ≠ 实际执行集一致**：`importorskip` 在 collect 阶段整块消失
  （静默、连 skip 都不报），`pytest.skip()` 在运行时跳过（报 skipped 但数量
  变化没人盯）。`check_ci_optional_deps.py` 守的是前者；后者目前只有这份
  快照文档，**没有门禁**。要堵须引入按环境分基线的 skip 清单比对，本轮不做
  （硬编码环境差异会很脆，容易变成天天红的门禁）。

### 7.1 同轮补：`check_ci_optional_deps.py` 只验顶层模块的半截判据

写完 §3 的门禁后自查发现：第一版对 `pytest.importorskip("PIL.Image")`
只 `find_spec("PIL")` 就放行 —— 可 `importorskip` 真正要的是**子模块**，
`PIL` 在而 `PIL.Image` 挂了照样整块跳过。自测第 ⑤ 条甚至把这个缺陷
写成「点号模块名只验顶层 ⇒ 绿」，等于把半截判据固化成期望。

实测 `find_spec` 两种「找不到」形态不同，都必须算缺失：

| 路径 | 行为 |
|---|---|
| `PIL.DefinitelyMissing` | 返回 `None` |
| `definitely_missing_pkg_xyz.Sub` | 抛 `ModuleNotFoundError` |

修法：改为对**完整模块路径**逐个 `_resolvable()`；`ImportError` 家族算缺失，
其它异常 RC=2 fail-closed。自测 **7 → 9/9**（新增「父包在但子模块缺 ⇒ 红」、
「顶层缺失的带点路径 ⇒ 红」两条变异）。本体从
「17 处 / 7 个顶层包」细化为 **「17 处 / 9 个完整模块路径 / 7 个顶层包」**，
两端 PASS。

### 7.2 勘误：服务器「缺 tesseract」是错的（19:24 复核）

§7 第一稿由 `command -v tesseract` = `MISSING` 推出「服务器缺系统工具、
5 条 OCR 用例结构性不可覆盖」。逐层复核后**这个推断不成立**：

| 测量 | 结果 |
|---|---|
| `~/.local/bin/tesseract --version` | **5.5.3**（leptonica-1.87.0），用户态已装 |
| `~/.local/share/tessdata/eng.traineddata` | 存在（软链到 `~/ocr_env/share/tessdata`） |
| `command -v tesseract` | MISSING —— 只因 `~/.local/bin` 不在 ssh 非交互 shell 的 PATH |
| `skills.jpeg_png_embedded._locate_tesseract()` | 找到 `~/.local/bin/tesseract` + tessdata |
| `test_jpeg_png_ocr.py::TestJpegPngOcr::test_tesseract_locatable` 单跑 | 两端均 **1 passed** |
| 补 `TESSERACT_BIN` + PATH 后跑 `test_svg_path_text.py` | `14 passed / 5 skipped`，耗时 0.14s → **4.42s**（OCR 真被调用） |

`skills/svg_path_text.py::_find_tesseract()` 只查 `TESSERACT_BIN` /
`shutil.which` / 硬编码候选（不含 `~/.local/bin`），所以默认路径下找不到。
但显式给 `TESSERACT_BIN` 后三条件实测：

```
_HAS_TESS = True   _HAS_FONT = True (DejaVuSans.ttf)   _ocr_reads_braces() = False
```

⇒ 那 5 条 skip 是 `test_svg_path_text.py:121` **有意的能力探测**：
tesseract 在 DejaVuSans 下无法稳定读回 `flag{...}` 的花括号，测试主动跳过
端到端用例（源码注释写明是为避免 CI 红 + CheckSuite 刷屏），
**不是环境缺工具，也不是被掩盖的 bug**。skip 原因文案把三个条件揉成一句，
是这次误判的直接来源。

顺带修正 `ci.yml` 里 2026-10-31 的过时注释：原文说
「`test_tesseract_locatable` 是硬断言，不装 tesseract 必红」，但该用例
11-08 已改成**按 vision extra 声明判定**（`pytesseract` 未装 ⇒ skip；
装了却找不到本体 ⇒ fail）。装系统 tesseract 的动作保留，理由改写。

**结论**：三端里真正缺工具导致跳过的只有 **WABT 那 1 条**；
「6 条结构性不可覆盖」缩减为 1 条，且 `sudo` 需密码仍无法在本会话补。

### 7.3 CI runner 的 `python-flint` 可装性（挂账降级）

§5 原写「未验证 GitHub Actions runner 能否装上」。查
`https://pypi.org/pypi/python-flint/0.9.0/json`（31 个发布文件）：

- `python_flint-0.9.0-cp313-cp313-manylinux2014_x86_64.manylinux_2_17_x86_64.whl` **存在**；
- 另有 `cp310-abi3` 的 manylinux wheel 兜底，以及 cp314 / PyPy311 版本；
- `ci.yml` 的 `ctf-agent-pytest-gate` 是 `runs-on: ubuntu-latest` +
  `actions/setup-python@v5` `python-version: "3.13"`，本机装的约束
  `"python-flint>=0.9,<0.10"` 会解析到 0.9.0（PyPI 上 0.9.0 即最新）。

⇒ 「CI 装不上 / 退回源码编译」的风险已由 wheel 清单排除。
仍**未实跑 Actions**，故只从「未验证」降级为「wheel 已确认，runner 未实跑」。
另注意该 job 有 `Install system tools (tesseract OCR)` step 但**没有 WABT**
⇒ WABT 那 1 条在 CI 上同样跳过。

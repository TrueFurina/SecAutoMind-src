# LLM 解题链路的「围栏 / 附件」闭环取证（2026-11-01）

## 结论先行

1. 修好了一条**活的伪造分数通道**：纯文本题的 python 会话 cwd 曾落在仓库根，路径围栏据此把**整个仓库**当白名单，模型可直接读题集真值文件。实测现在被拒。
2. 修好了围栏的**自伤**：`read_attachment` 落盘在 `/tmp` 根、围栏不放行，附件题会变成"模型不会用工具"的假结论。现在附件落进**按进程 + 按题目工作目录分桶**的收件箱，围栏只放行这一个桶。
3. 上述两条都在**真 Linux 二进制**上做了正反双向验证（放行要放行、拦截要拦截），不是只跑单测。
4. 本文件不含任何**能力**结论。修复只改变"模型能看到什么"，不改变"模型会不会做"——解出率仍须用真 token 重跑才可报。

## 事故链一：围栏把仓库根当白名单（伪造分数）

成因链：`cmd/llmbench` 旧实现对**无附件题直接 return，不做 chdir** → 进程 cwd = 启动目录（仓库根）→ `fenceWorkdir()` 取 cwd 建白名单 → 整个仓库放行。

实测（旧 binary + 假端点，读题集真值文件）：

```
拒绝执行：代码引用了本题工作区之外的路径 [...]；
允许范围是 /home/user/SecAutoMind | /tmp/secautomind_att_1377865_18061b69 | /tmp/secautomind_sess_205305494 | ...
                ^^^^^^^^^^^^^^^^^^^^^^^ 整个仓库在白名单里
```

修好 `prepareWorkdir`（无论有无附件都 `RemoveAll`+`MkdirAll` 一个**新空目录**再 chdir）后，同一路径被拒：

```
拒绝执行：代码引用了本题工作区之外的路径 [/home/user/SecAutoMind/data/ctf_benchmark/real_benchmark.json]；
允许范围是 /tmp/llmbench_work_truth/base64_triple_real | /tmp/secautomind_att_1378475_a2e5ed10 | /tmp/secautomind_sess_...
```

白名单从"整个仓库"收缩到"本题工作目录 + 本进程收件箱 + 会话目录"。

另有第二道闸（`denyFragments`）：即使路径落在白名单内，命中 `/data/answers/`、`/answers/`、`/.git/`、`/.ssh/`、`ycb2026_truth`、`benchmark_truth`、`*.pem`、`*.key`、`id_rsa` 也一律拒。

## 事故链二：围栏挡住工具自己给的附件路径（附件题不可解）

原状态：`read_attachment` → `/tmp/secautomind_att_<name>`；围栏白名单不含 `/tmp` 根 → 模型拿工具刚给它的路径来读，被自己的围栏拒。

修法（`internal/runnerl3/attachment_inbox.go`）：收件箱 = `os.TempDir()/secautomind_att_<pid>_<cwd哈希前8位>`。

- 按进程 + 按工作目录分桶 ⇒ 别的进程/别的题下载的附件读不到，也**不会跨题串味**（上一题的 `flag.txt` 不会漏给下一题）；
- 围栏只放行**这一个桶**，不是整个 `/tmp`——`/tmp` 里有并行会话的其他题目残留、别的基准 `app.log`、甚至别人的私钥（2026-11-01 取证）。

## 验证矩阵

| 断言 | 手段 | 结果 |

| **附件闭环**：下载 → 用回执路径打开 | 假端点 `--scenario inbox` + 真 binary | `b'MZfa'`（31 字节附件读前 4 字节） |

服务器：`go test ./internal/runnerl3/ ./cmd/llmbench/ -race` 全绿（Linux，Go 1.25.4）。

## 口径提醒

- 围栏在 `pySessionMgr.Exec`（`python_session` 唯一入口）与 `toolExecutePython`（`execute_python`）两处生效；后者走 skill 子进程，靠 `paramPathViolations` 把 params 里的绝对路径过同一条 `pathFence`（2026-11-01 二轮补，见事故链三）。
- 逃逸阀 `RUNNER_PY_FENCE=0` 会整体关掉围栏，**默认必须开**；报 KPI 前请确认它没被关。
- 本次改动全部是 harness/护栏，**不含任何解题能力提升**；「LLM 真实解出数」仍以真 token 跑批为准。

# 二轮补丁（同日 05:00-08:50）：三条仍活着的通道

## 结论先行

上午闭掉的是「harness 没 chdir 导致仓库根进白名单」；这一轮实测发现**同一类病还有三处**，
其中两处是**新增入口**（`execute_python`）、一处是**正则盲区**（中文路径）。三条都已修 + 变异验证。

## 事故链三：`execute_python` 是围栏的正门

上午的围栏只装在一处：`pySessionMgr.Exec`。而 `execute_python` 走的是另一条路 ——
`skill_name` 被 `fmt.Sprintf` 拼进 `import %s as s`（代码注入面），`params` 被 skill 直接
`open()`（读文件面）。源码取证：

```
CTF-Agent_融合/ctf_agent/skills/mbr_sse_verify.py:233
        raw = open(params["path"], "rb").read()
```

也就是说模型只要 `execute_python(skill_name="mbr_sse_verify", params={"path": "<任意绝对路径>"})`
就能绕开 `python_session` 的全部围栏把文件读出来（86 个 skill 模块里 12+ 个吃 `path` 参数）。

修法（两层，都在 `internal/runnerl3`）：

| 面 | 修法 | 位置 |
|---|---|---|
| 代码注入 | `validateSkillName`：必须匹配 `^[A-Za-z_][A-Za-z0-9_]*$` | `llm_hardconstraint.go` |
| 越权读文件 | `paramPathViolations`：递归收集 params 的字符串值（含 key），过**同一条** `pathFence` | 同上 |

**为什么是结构校验而不是 skill 白名单枚举**：工具 schema 里给模型的名字与 `skills/*.py`
的文件名并非一一对应，硬枚举会误杀文档承诺可用的别名（那是功能回归）。结构校验只砍
"根本不是标识符"的输入，拼错的模块名让 `ModuleNotFoundError` 自然失败即可。

**纵深防御**：`cmd/runner/pyskill_bridge.go::execSkillSubprocess` 是**真正拼源码**的地方，
那里也加了同一守卫（将来新增调用方不会漏）。

## 事故链四：仓库根被当工作区 —— 生产路径仍在漏

上午的修法只覆盖 `cmd/llmbench`（每题 chdir 到干净空目录）。生产入口没有这道 chdir：
runbook 的启动方式是 `cd ~/SecAutoMind_verify && ./runner`，**进程 cwd = 仓库根** ⇒
`fenceWorkdir()`（= `os.Getwd()`）把整个仓库塞进白名单。

`denyFragments` 只挡已知文件名模式（`/data/answers/`、`*truth*.json`、`*.pem`…），
挡不住归档 writeup。本轮实点：

```
docs/evidence/西湖论剑归档_20260821/solutions/  71 个文件，其中 22 个含 flag 形态明文
```

读到即"命中"（判分只认 `flag_sha256`）—— 性质与被 deny 表挡掉的那批完全相同。

修法：`fenceWorkdir()` 增加**目录身份**判定 —— `isProjectSourceTree(dir)` 命中 ≥2 个标记
（`go.mod` / `AGENTS.md` / `cmd/runner/main.go`）即认定"这是代码仓库，不是题目工作区"，返回空串
（`newPathFence` 会忽略空串 ⇒ 白名单只剩会话目录 + 附件收件箱）。显式降级阀：
`RUNNER_PY_FENCE_ALLOW_REPO=1`。

**为什么是"≥2 个标记"而不是"命中任意一个"**：逆向/源码题的附件里完全可能带 `go.mod`
（那就是题面输入）。按单标记判定，这道题的工作区会被自身围栏锁死 —— 模型连自己刚下载的
附件都读不到，比越权更糟。这条误伤防护由 `TestFenceWorkdirRefusesProjectSourceTree` 的
第二档断言锁住（只含 `go.mod` 的目录必须仍是工作区）。

## 事故链五：非 ASCII 路径对围栏完全不可见

`absPathRe` 原本用 `[A-Za-z0-9_.\-+*]` 作路径段基类 —— 遇到中文目录，**整条路径都抽不出来**，
`violations` 返回空 ⇒ 围栏静默放行。而要保护的那批文件恰好就叫
`docs/evidence/西湖论剑归档_20260821/solutions/`。

这不是"顺手优化"，是本轮写测试时被自己的断言打出来的（先红后改）。修法：基类改成
「非空白、非引号、非括号、非尖括号、非逗号/分号/竖线、非花括号」的排除式字符类；
排除 `{}` 是因为 `f"/home/{x}/y"` 这类格式串不是真实路径，抽出来只会制造误报。

## 变异矩阵（每条守卫都做了"摘掉必须变红"）

| # | 变异 | 期望 | 实测 |

| M1 | `execute_python` 两处守卫调用改成 `if error(nil)` / `[]string(nil)` | 两条拒绝用例红，其余绿 | `TestExecutePythonRejectsInjectedSkillName` / `...RejectsOutOfWorkspacePathParam` FAIL，RC=1 ✅ |

# 三轮补丁（同日 09:00-09:40）：环境变量外泄 —— 真机当场撞出来的

## 结论先行

用真实通道跑 12 题时，模型在第 6 轮执行 `print(os.environ)`，
**`RUNNER_LLM_API_KEY` 的明文被当作"工具输出"回给了模型**，也就发给了模型提供商。
路径围栏管不到这条出口（`os.environ` 不碰任何路径）。比赛日同一条路会吐出
`CTF2_AGENT_TOKEN`（平台令牌）与 `SSH_AUTH_SOCK`（等于把 ssh-agent 借出去）。

## 事故链六：模型可写的子进程继承了整份进程环境

三处 `exec` Python 都没有设 `cmd.Env` ⇒ 默认继承父进程全量环境：

| 位置 | 用途 |
|---|---|
| `internal/runnerl3/py_session.go:131` | `python_session` 常驻 REPL（模型逐轮写代码） |
| `cmd/runner/pyskill_bridge.go`（exec 上） | `execute_python` → skill 子进程（params 来自模型） |
| `cmd/runner/pyskill_bridge.go`（checkDep） | 依赖探测（无模型输入，但同样没必要给全量） |

修法一：新增 `internal/procenv`，**白名单**下发 `PATH/HOME/LANG/LC_*/PYTHON*/TMPDIR/…`。
不用黑名单（名字含 KEY/TOKEN 就丢）的理由：漏掉一个不带这些词的机密就前功尽弃；
白名单的失败模式是"忘了加某个变量"，可复现、可修、不会静默泄露。

修法二：`path_fence` deny 表加 `"/environ"` —— `/proc/<pid>/environ` 是**同一个出口的文件形态**，
而且它是内核保存的**初始**环境快照，`os.Unsetenv` 清不掉，只能靠围栏挡读。

修法三：`internal/procenv.Harden()` —— `prctl(PR_SET_DUMPABLE, 0)`，让**同 uid** 的进程
读不到本进程的 `/proc/<pid>/environ`。这条挡的是 `ps eww`（它就是读这个文件）：
围栏只能拦"文件路径"出现在 Python 代码里，拦不住"模型起一个 ps 子进程"。
三个入口（`cmd/runner`、`cmd/llmbench`、`cmd/evalharness`）启动即调用。

## 真机行为验证（不是查源码）

| 断言 | 证据 |
|---|---|
| 子进程读不到密钥 | `TestPythonSessionEnvIsScrubbed`：真起会话跑 `os.environ.get(...)` → `APIKEY=ABSENT`、`TOKEN=ABSENT`、`PATHOK=yes` |
| 修好后重跑 12 题 | 日志里 `grep -c "sk_tr_"` = **0**（修复前同一条路径命中 1 次） |
| prctl 真的生效（Linux） | `TestHardenBlocksParentEnviron`：起 `sh -c "cat /proc/<本进程pid>/environ"` 必须失败，且 `/proc/<pid>/status` 仍可读（证明只挡敏感文件） |

## 处置与残留

- 事故日志已 `shred -u` 销毁；服务器 `/tmp/*.log` 全量扫过无 `sk_tr_` 残留。
- 🔴 **该 key 必须轮换**：它已经出现在模型提供商侧的请求/响应链路里。
- 残留风险：`/proc/<pid>/environ` 之外的同类出口（如 `/proc/<pid>/cmdline` 泄露命令行参数）
  未逐个封堵；本项目密钥走 env 不走 argv，故暂不处理。

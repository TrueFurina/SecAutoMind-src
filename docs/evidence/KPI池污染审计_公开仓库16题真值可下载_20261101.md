# KPI 池污染审计：40 道外池题里 16 道的真值可从公开仓库直接下载（2026-11-01）

## 一句话结论

`data/questions_external_bench` 的 **40 道题中，16 道（40%）** 的官方源仓库里，
`challenge/flag.txt`（或 `challenge/flag`）的 sha256 **与题集登记的 `flag_sha256` 逐位相等**。
也就是说：**只要被测子进程能联网，一条 `curl` 就能拿到答案。**

在这批题上产出的任何"解出率"，只有在**执行期断网**成立时才配叫能力数字。
审计题源、剔除题目都解决不了这个问题——剔完池子基本清空（16/40 一删，只剩 24 道，
其中多数还是必须联网的服务端题）。

## 判据（可复核）

- 只比 `sha256(文件内容 raw 与 strip 两种形态)` 与题集 `flag_sha256`，**全程不打印、不落盘明文**。
- 取仓库整树（`git/trees?recursive=1`），在**每个题目目录的全部层级**里找文件名匹配
  `^(flag|flags|flag.txt|flag.bin|flag.out)$` 的 blob，再逐个下载比对。
- 工具：`scripts/audit_public_flag_leak.py`（可重复执行，输出清单与百分比）。

## 关键教训：审计粒度决定结论

同一件事，两种审计写法得出两个完全相反的答案：

| 审计写法 | 结果 |
|---|---|
| 只查题目目录**根层**的 `flag*` 文件（26 道 crypto） | **0 / 26 命中** |
| 递归查**全部层级**（40 道全池） | **16 / 40 命中** |

差别只有一个 `challenge/` 子目录——flag 全部躺在 `<题>/challenge/flag.txt` 里。
这正是本项目反复踩过的同型陷阱：**范围差一层，"干净"就是假的。**

## 修法：执行期断网（syscall 级，非 root 可用）

选题判断：不换池、不删题、不加题源审计，而是在**执行期**把出口关掉。

| 方案 | 为什么不行 / 行 |
|---|---|
| 只信 `RUNNER_LLM_AIRGAP` | 它只作用于 `read_attachment` 的 HTTP 客户端；模型走 `python_session` 自己写的 `requests/urllib` 直连，绕得干干净净（真机事故） |
| `unshare -n` 网络命名空间 | 服务器上 uid_map 写入失败、无 sudo，不可用 |
| 题源审计 / 剔除题目 | 剔完池子几乎清空；且新题源还会复发 |
| **seccomp（已实现）** | 非 root 可装；拦的是 `socket(AF_INET/AF_INET6)` 本身，与上层用哪个库无关；`AF_UNIX` 放行 |

实现：`internal/airgap`（`ca793f5`）

- 自 re-exec 包装：父进程把 `cmd` 改写成「自身 + `--airgap-child` + 原命令」，
  子进程装 `PR_SET_NO_NEW_PRIVS` + `PR_SET_SECCOMP` 后 `exec` 目标；信号与退出码原样透传。
- 装不上就 `exit 97`（**fail-closed**）：绝不能"装作装好了"继续跑，否则数字被污染且毫无提示。
- 未调用 `RegisterMain()` 的二进制，`Wrap` 静默不改写——防止包装参数被当成自身参数解析。
- 默认**关**（赛时要连靶机/远程服务，断网等于自废武功）；`CTF_AIRGAP=1` 仅用于离线评测。
- 接线在四处「模型可驱动」的子进程：`python_session` / skill 子进程 / 流式 shell / 壳命令。

## 验证：同一台机器上的双条件（不是两台机器的两个绿）

| 用例 | 结果 |
|---|---|
| `internal/airgap` 单测 4 项 | PASS：AF_INET 被拒(EPERM)、AF_UNIX 放行、不开闸能建 socket、未开闸不改写命令 |
| 端到端金丝雀 `TestAirgapBlocksOutboundFetchFromSkill` | 不开闸 → `FETCHED` 且 sha256 与靶子一致（**阳性对照**）；开闸 → `BLOCKED:PermissionError`（内核 EPERM） |
| 不误伤 | `CTF_AIRGAP=1` 下 mhk2 仍 **105.0s / L2-HIT**（sha256 一致） |

金丝雀为什么不用 GitHub 当靶子：**服务器对外网本来就不通**（实测 `URLError`）。
用它当靶子时，"开闸后被拦"与"环境本来没网"结果完全一样——就是假绿。
改用 `httptest` 起在 `127.0.0.1` 的临时监听：网络栈本身通，唯一变量是 seccomp；
并把异常类型区分为 `PermissionError`（闸门）与 `URLError`（环境），不给"绿得含糊"留空间。

两点值得记下：

1. 命中的 `electric-mayhem-cls` **恰好在上面的泄露清单里**，但断网下仍解出——
   模型读 `firmware.tgz` 解出 AES 变体、自己算出明文。这条在这次之前**无法证明**：
   同样的行为在联网时，你分不清它是算出来的还是下载来的。
2. 断网没有把 L3 打死（每轮工具调用都正常，纯计算类题目照常推进），说明闸门只关出口、不伤能力。

**未带 `CTF_AIRGAP`**）。那些结果按本文判据**不可用于对外**，也不能与本节数字并列。

## 后续口径（写进结论前的硬约束）

1. 这个题池的定位是**工程回归池**，不是"能力 KPI 池"。想用它谈能力，必须附 `CTF_AIRGAP=1` 与本节审计结论。
2. 任何不带宽网执行证据的"解出率"，一律视为不可归因——包括本轮之前的纯 LLM 数字（需重跑复核）。
3. 赛时**不得**开 `CTF_AIRGAP`（要连靶机）；断网只属于离线评测，两者口径不能混。

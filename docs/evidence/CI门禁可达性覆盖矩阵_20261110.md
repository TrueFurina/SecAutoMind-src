# CI 门禁可达性覆盖矩阵：「约 20 个未接 CI」证伪（2026-11-10）

**一句话结论**：长期记忆里「约 20 个门禁脚本仍未接 CI」是**度量口径错误**，不是
真实缺口。按「CI 根入口 + Python import/字符串常量引用」的传递闭包重算：
**55 个门禁类脚本里 44 个可达、11 个有具名豁免、0 个漏接**。本轮没有去「把 20 个
都接上」，而是把可达性本身固化成自动判据——新增门禁不接 CI 就判红。

## 1. 旧口径为什么错

旧结论来自「`ci.yml` 里有没有 `scripts/xxx.py` 字符串」，得到 20 个未命中。三个
系统性漏判：

| 漏判形态 | 实例 |
|---|---|
| **间接 import 覆盖** | `capability_caliber_test.py`（`ci.yml:1148`）import 并断言 `verify_verdict_chain.check()` / `verify_capability_evidence.selftest()` / `check()` 等，全部 `all(rc == 0)` 才返回 0 ⇒ 这些脚本的判据**确实在 CI 里跑**，只是没有作为 CLI 出现在 YAML 里 |
| **其它 workflow 文件** | `check_workflows_yaml.py` 在 `ci_lint.yml`；只看 `ci.yml` 自然 0 命中 |
| **路径写法不同** | `check_question_truth_test.py` 在 ci.yml 里被引用，但路径不带 `scripts/` 前缀，被窄正则漏掉 |

此外多数 `audit_*` 的 docstring 明写「盘点工具，不是门禁」「一次性归类器」，本来
就不该接 CI。把「没被 YAML 字符串点到」直接等价于「没接 CI」，是典型的
**度量工具没校准就下结论**。

## 2. 新口径：可达图

```
根入口 R0 = 所有 .github/workflows/*.y*ml 的 run/python/entry 命令行
          + .pre-commit-config.yaml 的 entry
          + scripts/_ci_local.sh 的命令行
          （整行注释与行内 # 之后的内容一律不算）

依赖边 E  = 每个 scripts/*.py 经 ast.parse 得到的
            ① 同目录 import（Import / ImportFrom）
            ② 非 docstring 的 ast.Constant 字符串里的 scripts/xxx.py
            （注释不会进 AST；docstring 里的「用法：python scripts/x.py」是说明文字，排除）

可达集 R  = R0 沿 E 的传递闭包
扫描集 S  = scripts/*.py 中 check_/verify_/audit_ 开头且非 _test.py
```

实测：`ci_roots = 127`、`S = 55`、`|S ∩ R| = 44`、具名豁免 11、
**不可达且未登记 = 0**。

结论：**没有一个是「该接却漏接」的门禁**。三个稳定判红/超时的若强行接进 CI，
只会造出天天红、最后被整段注释掉的闸门（项目已有此教训）。

> ⚠️ **插曲（又一次度量纪律实证）**：第一轮试跑用「手打的文件名清单」，其中
> `verify_demo_readiness.py` 被漏了一个字符（真实 24 字符 / 手打 23 字符），
> 导致按手打名字拼路径报 `FileNotFoundError`，差点被误记成「脚本会红」。改用
> `Path.glob` 枚举的真实文件名重跑，才拿到 RC=1 / 0/2 通过。长期记忆里
> 「关键词禁手打须从文件名复制」这条纪律本轮又踩了一次；新门禁的 R4
> 「豁免键必须真实存在于扫描集」正是把这个坑变成自动判据。

## 4. 新判据 `scripts/check_ci_gate_reachability.py`

| 判据 | 守什么 |
|---|---|
| R1 | 根入口只从 `run`/`python`/`entry` 命令提取；注释行与行内 `#` 之后不算 |
| R2 | 依赖边只认 AST 的 import 与非 docstring 字符串常量；注释/docstring 示例不构成边 |
| R3 | 扫描集内脚本必须可达，或登记在豁免表 |
| R4 | 豁免键必须真实存在（防拼错/悬空）、理由 ≥20 字且不含 TODO/待定、数量 ≤ 15 |
| R5 | 防缩水：根入口 ≥ 100、可达门禁 ≥ 40 |

`--selftest` **15 项变异全 PASS**：B0 合成基线 / B1 数量达标 / B2 真实仓库基线；
M1 豁免键拼错、M2 理由空洞、M3 豁免超限、M4 新增门禁不接 CI、M5 整行注释伪造
接线、M6 行内注释伪造接线、M7 真实 run 行可提取、M8 docstring 不构成边、
M9 注释不构成边、M10 真实常量构成边、M11 根入口塌陷、M12 可达门禁塌陷。

**判据自证**：接线**之前**跑该脚本，它把自己（`check_ci_gate_reachability.py`）
判成 `R3 门禁类脚本不在 CI 可达图且未登记豁免`，`unreachable_not_exempt=1`、
selftest 14/15；把两步命令接进 `ci.yml` 的 `test` job 之后，同一脚本
**15/15 + 本体 RC=0**，`55 / 44 / 11 / 0`。即「判据确实能变红」不是合成变体，
而是真实接线前后对照。

## 6. 作用域边界与未做的事

- 判据作用域 = 仓库根 `scripts/` 下 `check_/verify_/audit_` 开头的脚本；
  `CTF-Agent_融合/ctf_agent/scripts/` 那套脚本只作为 CI 根入口参与计算，
  不纳入本判据的扫描集。
- 可达图是**静态近似**：`subprocess` 动态拼接路径、`importlib.import_module`
  变量模块名不在 R2 覆盖内，本门禁不对这两类声称覆盖。
- 11 条豁免是**记账不是删除**：R4 把「键悬空 / 理由空洞 / 数量膨胀」都锁住，
  想豁免必须写清为什么不能在干净检出上跑。
- ⚪ 未改任何判分口径、分母、verdict、材料数字、交付包；未推远程（远程仍
  `fa2fb6c`，本轮两个提交后本地领先 **48**）；**真实 Linux Actions CI 仍未跑过**；
  23 个 WIP 未触碰；Go `-race` 未跑；临时 worktree 已清理。

## 7. 复用纪律

1. **先校准度量工具再下结论**：「YAML 里有没有字符串」≠「CI 有没有跑」。
   本轮连续三次校准：窄正则→多 workflow + 间接 import 可达图、手打文件名→
   glob 真实名、`is_gate` 只看 docstring 前两行→逐个实跑定性。
2. **不要把「接 CI」当成目的**：11 个不可达里有 3 个当前稳定判红、2 个超时，
   全接进去只会制造永久红门禁。豁免要具名、要有实测依据、要有上限。
3. **新判据先把自己判红再接线**：这是最便宜的「能变红」证明，比合成变异更可信。
4. **改 CI 步骤数必须同步 `docs/GATES.md`**：本轮 20 → 21，C6 复跑 PASS。

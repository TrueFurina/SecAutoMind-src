## 1. 第七个偏差：明文门禁的命名绕过（结构性空洞绿）

`check_benchmark_plaintext_answer.py` 的扫描集是

```
GLOB = data/ctf_benchmark/*benchmark*.json
```

**只按文件名匹配**。本机实证：`data/ctf_benchmark/purellm_full188.json`
（176 题池，顶层含 `problems` 字典）名字里没有 `benchmark`，两个明文判据
（花括号 token、自然语言自曝）一次都没有扫到它。

由此推出：第 8 次收紧宣称的「新池零容忍」只在**被扫到**的前提下成立；把
一个新题池命名成 `pool_v3.json` 就能完全绕过门禁，门禁照样绿。这是与前面
六个假绿同形的空洞绿，且是结构洞而非数据问题。

补充两点事实：

- 第一次排查我用了整条路径做 `*benchmark*.json` 匹配，目录名
  `ctf_benchmark` 本身就含 `benchmark`，于是误判「零漏扫」。改用 basename
  后查出 17 个顶层 json 不在 GLOB 内。与项目既有教训「关键词必须从文件名
  复制，禁手打」同源，此处是同一类假阴性的变体。
- 对 **git 已入库**的顶层非 benchmark 命名文件逐个做形状检查，含
  `flag_sha256` 题项的文件数为 **0**（其余为 coverage report、manifest、
  registry、单题素材、运行时记录）。即当前没有已入库题池被实际漏判，
  但洞在未来任何新增文件上都成立。`purellm_full188.json` 本身未入库，
  评测入口的前置守卫也已拒绝它，不属于 CI 可见范围。

## 2. 第八个偏差：verdict 存盘后无人复核（证据可事后篡改）

- `scripts/verify_evidence.py` 全文 **0 处**引用 `verdict` / `claim_scope` /
  `capability_rate`。
- `capability_caliber_test.py`（当时）只跑两段**合成数据**自测；
  `audit_private_proof.py --verify` 只比私有性锚点证据的 7 个结论字段。
- 4 份 verdict 的 `claim_scope` 由代码重算写入，`generated_by` 也标明自动
  生成，但**没有任何环节复核存盘值**。

后果：手工把某份 verdict 的 `claim_scope` 改成
`capability_rate_candidate`，或把 `capability_rate` 写成 0.9，全门禁仍绿，
而评审引用的正是这些 JSON。「证据自动生成」堵住了填写时的造假，没堵住
**事后篡改** —— 与第六个偏差「题面自证」一样，缺的是外部锚点。

## 3. 修复（全部在门禁侧，不碰判分/跑批代码）

1. `scripts/check_benchmark_plaintext_answer.py` 新增
   `looks_like_pool()` / `tracked_top_level_json()` /
   `coverage_violations()`；`--check` 对 **git 已入库的顶层 json** 做覆盖
   断言：形状像题集（`problems` 非空 dict 且至少一题带 `flag_sha256`）却
   没出现在 `analyze()` 结果里 ⇒ 判红，强制改名或显式登记。git 清单取不到
   ⇒ `None` ⇒ fail-closed 判红。**不改 GLOB、不改 31 集/557 题口径、不动
   两条判据基线**。
2. 新增 `scripts/verify_verdict_chain.py`：复用同一生产判据
   `claim_scope_for_pool()` 逐键重算比对，另校验
   `result_pool_sha256 == pool_sha256`（防换池洗白）、
   `capability_rate == LLM_SOLVED / claimable_denominator`（算术自洽）、
   `claimable=False ⇒ rate=null`、非 candidate 不得声明可发布；
   `MIN_VERDICTS=4` 防「删掉一份 verdict 让不一致消失」。`--selftest`
   内含 6 类篡改变异 + 1 个原件通过的正例（证明不是永远红灯）。
3. `scripts/capability_caliber_test.py` 增加第三段转发上述自测与
   `--check`。CI job `capability-caliber-gate` 本来就跑这个入口，故
   `ci.yml` / `docs/GATES.md` 无需改动（`answer-leak-gate` 有
   `actions/checkout@v4`，浅克隆下 `git ls-files` 仍可用）。
4. `scripts/check_benchmark_plaintext_answer_test.py` 新增 6 个用例：
   真实仓库覆盖绿、改名题池确实不在 GLOB 内（洞存在）、改名题池被抓、
   报告类 json 不误伤、空清单不恒红、git 清单不可得 fail-closed。

新增门禁的前提：运行环境须有 git 且处于 git 仓库。CI checkout 满足；
非 git 环境一律 fail-closed 判红，不猜绿。

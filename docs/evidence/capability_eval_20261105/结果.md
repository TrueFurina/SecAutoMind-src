## 1. 本轮修正的三个「假绿 / 错配」

| # | 问题 | 实锤 | 修法 |
|---|---|---|---|
| A | 把 Go runner 的开关无差别套到 Python pure_llm 路径 | `CTF_AIRGAP` 全树消费者只在 `cmd/llmbench` / `cmd/runner` / `internal/airgap` / `py_session.go` 等 Go 侧；`ctf_stepfun_orchestrator.py` **0 命中**。`RUNNER_LLM_NO_FALLBACK`、`CTF_AGENT_INTERNAL_PRESOLVE` 同样无消费者 | 判据改为**路径感知**：`pure_llm` 要求路径内生证据，`agentic` 才要求 seccomp + IP 直连；未声明路径按最严契约判 |
| B | 旧脏池批次靠「换干净池重新归因」被洗白 | 改造后一度把 1/176 判成 `claimable=true / rate=0.0`；它用的是被 gitignore 的 `purellm_full188.json`（含题面明文伪解） | 新增 `result_pool_matches_proven`：**由 `judge_run` 内部按 sha256 重算**，人工在证据里填 True 无效；`--run` 时入口从 `--benchmark` 实取指纹绑定 |
| C | 题池没入库却宣布「可引用能力率」 | smoke 1 题时 `claimable=true / rate=0.0`，而 `tracked=false` 只是个 WARN | `pool_tracked_and_clean` 改由代码按三子键重算（指纹一致 + 门禁零违规 + **git 历史可查**）；`git add` 后未 commit 也不算，避免第三个假绿 |

另修一处口径：能力率**分母只含可归因题**（`LLM_SOLVED + CLEAN_FAIL`），`NOT_ATTRIBUTABLE` 的题明确剔除并计数，不再混入分母。

## 2. 两条路径的证据契约

`pure_llm`（本次采用）：`solve_one()` 非 agentic 分支写死 `tool_calls: 0 / audit: []`，
模型**没有代码执行或网络出口**，威胁是「模型记忆 / 题面明文答案 / 通道归属伪造」，不是「联网抄官方 flag」。

| 契约键 | pure_llm | agentic |
|---|---|---|
| `airgap_active` / `airgap_zero_egress_proven` | N/A（无解题子进程） | 必需（seccomp + IP 直连 proof） |
| `no_model_egress_proven` | **必需**：结果（`agentic=false`、`tool_calls_total=0`、每题 `tool_calls=0`、`audit=[]`）+ 源码 AST（`run_python_tool` 仅在 `call_llm_agentic` 内可达）双证 | — |
| `single_channel_proven` / `channel_attribution_proven` | 源码单一 `load_key` 调用点、无 `Resolve()` 降级链、summary.provider 与命令一致 | 同左 + `RUNNER_LLM_NO_FALLBACK=1` |
| `no_presolve_proven` / `presolve_off_proven` | `verify_flag()` 源码不含 presolve、结果无 presolve 命中 | env 显式关闭 |
| `temperature_fixed` | 请求体两处硬编码 `0.2`（代码级） | 同左 |
| `pool_tracked_and_clean` / `result_pool_matches_proven` | 两条路径都必需，均由代码重算 | 同左 |

`prove_pure_llm_path()` 从结果文件 + orchestrator AST 自动生成上述证据，**不接受人工填写的布尔**。
详见 `path_proof.json`。

## 6. 唯一剩余阻断与闭环动作

```bash
git add -f data/ctf_benchmark/purellm_clean_benchmark.json \
           data/ctf_benchmark/purellm_clean_benchmark.manifest.json
git diff --cached --stat
git commit -m "eval: 纳入干净题池与逐题处置清单（160 题）"
```

**本轮没有替用户执行 `git add` / `git commit`**：工作树存在他人在途 WIP
（`scripts/ctf_stepfun_orchestrator.py` 等），提交会移动 HEAD，属交付决策，留给持有跑批权/提交权的会话。
仅 `git add` 而不 commit **不算闭环**——判据查的是 `git log -- <path>`，staged 仍判 false。
入库后重跑一次 `--run`（或对该批次重新判分）即可产出第一条经代码仲裁的数字；
**即使结果是 0/N，也必须带 `CTF_AIRGAP` 语境说明**（见下）。

## 7. 取证边界（不得外推）

- **纯 LLM 路径排除不了模型记忆与公开 writeup**：无工具出口 ≠ 无先验知识。
  本题池大量为公开赛题，任何命中都只能说「本路径内未抄题面 / 未用工具抄官方仓库」，
  不能等同于「模型推理能力」。要谈能力仍需私有题或 `CTF_AIRGAP=1` 的 agentic 路径。
- 本次 **3 题 smoke 是链路验证**，分母极小，不得对外引用为能力率。
- 未跑 `agentic` 路径（本机无 go/seccomp，服务器未占位）；未跑全量 160 题。
- `channel_attribution` 是**代码级单通道证明**，非网络层抓包，不覆盖 DNS/代理劫持。
- `temperature` 显式固定 ≠ 逐位可复现（provider 采样与版本仍带来方差）。
- 未修改 `ctf_stepfun_orchestrator.py`（他人在途 WIP，diff 保持 7+/5-）。

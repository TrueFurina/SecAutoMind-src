1. **题源**：`pool_prior_audit.json` 实扫 160/160 全公开、零私有题，
   `heldout` 11 题也是 NYU CTF Bench 公开基准 ⇒ 先验无法排除。
2. **题面信息量**：`description` 长度 min **1**（内容就是一个 emoji `🤬`）、
   中位数 78、max 1453；`<20` 字符 11 题、`<60` 59 题、`<120` 107 题、
   `<300` 149 题。正则扫出 23 题含附件/交互线索
   （`source.py` / `.pcap` / `nc` / `server.py` …），本批 **未传 `--artifact-dir`**
   ⇒ 附件不可用、交互题无靶机。**大量题在 pure_llm 路径上根本不可解。**
3. 因此 verdict 已由代码标注 `claim_scope = engineering_regression_only`。

## 4. 🔴 跑完复核时才炸出的更大问题：干净池并不干净

### 4.1 起因
归档日志出现 167 处花括号 flag token。按项目红线先做「候选 vs 真值 sha256」反查，
发现有 5 个形态与**某题真值**命中。定位后不是跨题巧合，而是
`real_misc_sheng2022_traffic_*` 这 5 题的题面都写着
「…**writeup 明确给出 `<X>`**。`<flag 外壳>{次数/端口/密码}`」——
**题面自己承认答案来自公开题解，并把答案写在题面里**。
具体值按 R10 不落明文，只给可复核指纹（与 `writeup_answer_audit.json` 一致）：

| 题 id | 真值形态 | 长度 | 命中形态 sha8 |
|---|---|---|---|
| `real_misc_sheng2022_traffic_ftp_dataconn_count` | 裸内容 | 1 | `6b86b273` |
| `real_misc_sheng2022_traffic_ftp_port` | 裸内容 | 2 | `48449a14` |
| `real_misc_sheng2022_traffic_bruteforce_count` | 裸内容 | 3 | `be47addb` |
| `real_misc_sheng2022_traffic_telnet_pwd` | 裸内容 | 5 | `cc0f6b52` |
| `real_misc_sheng2022_traffic_enable_pwd` | 裸内容 | 8 | `0fc5ec3e` |

模型把这 5 题照抄成花括号 flag token（`got` 长度 7/8/9/11/14 一一对应），
但 `solved=False`。

### 4.2 两个根因（同源）

- **判分不去壳**：`ctf_stepfun_orchestrator.py::verify_flag()` 走
  `experiments/flag_util.py::candidate_variants()`，实测
  `candidate_variants(花括号 flag token)` **只返回它自己**（无裸内容变体）。
  而这 5 题真值登记的是 `sha256(<裸内容>)` 哈希
  ⇒ 模型按题面要求输出花括号 flag token 永远判不中。
  实测：把裸内容 X 包进花括号 flag token 后，用 `sha256(X)` 作真值调用
  `verify_flag()` 仍返回 `solved=False`。
- **门禁同一处漏**：`check_benchmark_plaintext_answer.py::answer_is_in_statement()`
  只把花括号 token 过 `candidate_variants` 对撞 `flag_sha256`。
  `analyze(ROOT)` 对干净池的实际输出是
  `{"plaintext_answer": 0, "baseline": 0, "offenders": []}` ⇒
  **`--check` 的 RC=0 是空洞绿**，不是「池里没有题面答案」。

### 4.3 可复跑审计与结果
新增 `scripts/audit_writeup_answer.py`：不依赖明文答案字段，**纯 sha256 反查**
（题面 token 的裸内容 / 常见赛事外壳 / 题面出现过的 `word{}` 形态），
`--selftest` 7/7、`--verify` PASS，证据**不含明文答案**（只写长度与 sha8）。

```
扫描 29 集 / 390 题 → 题面即答案 6 题（含自然语言自曝措辞 5 题）
全部位于 purellm_clean_benchmark.json，全为 pool=real
```

第 6 题是 `real_crypto_dnui_keyboard`（带壳形态命中，无自曝措辞）。
**这 6 题全部在分母 137 内、判分均为 CLEAN_FAIL，且都不在 23 道泄漏集里**
——既没被判分算成分，也没被防污染锁剔除。

⇒ 工程闭环：`run_capability_eval.py::claim_scope_for_pool()` 现在重算这份清单，
verdict 自带 `claim_scope.statement_tainted_count = 6` 与逐题 id，
`--selftest` C 段 6/6，`report()` 打印警示。**不是再写一份外围文档提醒。**

## 6. 结论（总结论第 7 次收紧）

这份 `0/137` **只证明**四件事：链路能在 160 题规模跑通、防洗白锁正确剔除 23 题、
通道归属单一、判据能产出格式可引用的结论。

它**不证明任何解题能力**，而且本轮顺带证伪了两条此前被当成绿的：
「题池已剔除题面伪解」与「明文答案门禁零违规」。现在连
「池是干净的」都不成立，`engineering_regression_only` 还要再打一次折。

# v2 干净池与门禁收紧（2026-11-06）

> 结论先行：本轮修的是**判据可信度**，不是「能力证据」。
> 能力证据仍为空，且本轮又量化出一个新的系统性偏差（判分假阴性）。
> 任何分母的跑批读数仍只能称「工程回归读数」。

## 0. 本轮为什么必须做

上一轮全量 160 题（`verdict_full160.json`）暴露第四个假绿：明文答案门禁对
干净池实报 `plaintext_answer=0 / offenders=[]`，但池里 6 道题的**题面自己
写着答案**。根因同源：

- `check_benchmark_plaintext_answer.py::answer_is_in_statement()` 只扫
  花括号 token；
- `scripts/experiments/flag_util.py::candidate_variants()`（L67–84）只生成
  原文 / 小写 / 前缀归一，**不产生裸内容变体**；
- 真值登记为 `sha256(裸内容)` 时，题面「writeup 直接给出 X」这类自然语言
  自曝永远扫不到 ⇒ `--check RC=0` 只说明「没超登记基线」，不说明「池里没答案」。

按「不能只写文档」的教训，本轮把这条判据做成**代码会拒绝**的三层锁：
门禁层、题池层、评测入口层。

## 1. 三层锁（均可复跑）

| 层 | 工程件 | 判据 | 实测 |
|---|---|---|---|
| 门禁（CI 已挂 `--check`） | `check_benchmark_plaintext_answer.py` 新增 `self_disclosure_in_statement()` | 题面 token 的裸/带壳形态 sha256 == 该题 `flag_sha256` | 31 集 / 557 题扫出 6 题，全在 v1；v2 与任何新池零容忍 |
| 题池 | `build_clean_benchmark_v2.py` → `purellm_clean_benchmark_v2.json` | 从 v1 派生、剔 6 题、父池指纹钉死 | 160→154，两个判据内建计数均 0，selftest 7/7 / verify 9/9 |
| 评测入口 | `run_capability_eval.py` 两条新前置守卫 | ① 本批次池自曝题=0（代码逐题重算）② 命令 `--benchmark` 与 `--pool` 同指纹 | 见 §3 |

**单一真值源**：`self_disclosure_in_statement()` 同时被门禁与
`audit_writeup_answer.py` 复用（后者不再自备一套判据），杜绝「门禁一套、
审计一套」的口径漂移。`--verify` 复核证据与题库集合一致 = PASS。

单测 `check_benchmark_plaintext_answer_test.py` 由 12 → **17/17**，新增 5 个
变异用例：裸内容真值命中（旧判据漏）、证据无明文、同形词防误伤、无指纹不裁定、
未登记能力池带自曝即报红。`plaintext_answer` / `offenders` 语义与历史基线
（15/4 登记契约、`real_solver_caliber`）**未改**，避免口径漂移。

### v1 为什么不一起改
v1 的 sha256 `0835c1f2…` 已绑定三份已提交 verdict 的 `result_pool_sha256`：
`verdict_smoke3.json` / `verdict_smoke3_closed.json` / `verdict_full160.json`。
改一字节三份历史证据立刻失去可归因性 ⇒ **v1 永久只读**，v2 用新文件名。
v1 的 6 题在门禁里按 `SELF_DISCLOSURE_BASELINE` 登记 6 只是避免 CI 常红，
输出明确标注「已知历史池，禁止用于新跑批」；真正拒绝它的是入口守卫 ①。

## 2. v2 池

```
父池  purellm_clean_benchmark.json        sha256 0835c1f274c79ba07…  (只读)
v2    purellm_clean_benchmark_v2.json    sha256 3bfb3a3922c9886c6…

保留  requires_airgap 23 题；不回流任何 flag 明文字段
```

剔除的 6 题：5 题 `real_misc_sheng2022_traffic_*`（裸内容真值 + 自曝措辞），
1 题 `real_crypto_dnui_keyboard`（带壳形态自曝，措辞不显著）。
manifest 记录每题的 `answer_form` / 长度 / sha8 / `self_disclosing_wording`，
**不含任何明文答案**（项目红线）。

题源先验 `pool_prior_audit_v2.json`：**154/154 全公开或来源不明，
private_proven=0，capability_rate_publishable=False**。
⇒ 结论作用域恒为 `engineering_regression_only`，与分母无关。

## 3. 防洗白守卫实测（不是文档承诺）

| 场景 | 结果 |
|---|---|
| 默认池（v1）起新跑批 | `FAIL 本批次题池无题面自曝答案 tainted=6` → `RC=2` 拒绝 |
| 用 v2 过前置、命令却把 `--benchmark` 指向 v1 | `FAIL 跑批命令题池与 --pool 同指纹` → `RC=2` 拒绝 |
| v2 池 + 命令同池 | 前置通过 `RC=0`，`in_history=True` |

`run_capability_eval.py` 已参数化 `--pool` / `--manifest` / `--prior-audit`，
整条链（preflight → adjudicate → `claim_scope_for_pool`）都用选定池，
换池不换题源证据会直接判 `unverified`。

## 4. 第五个偏差：判分不去壳造成的假阴性（本轮量化，未修）

`audit_scoring_variant_gap.py` 在**审计层**把模型候选做去壳/带壳变体后与
本题 `expected_sha256` 重比（selftest 7/7，证据无明文）。对 v1 全量结果：

```
160 题，原判命中 0，去壳后新增命中 5 题
scoring_variant_gap_v1.json：5 个 id 全部是 real_misc_sheng2022_traffic_*
```

原始跑批结果含模型候选，按 R10 **不入库**；证据里只留 `result_sha256`、
题号与形态指纹（长度 / sha8）供复核，不含任何明文答案。

即：**v1 的 `0/160` 里有 5 题是「模型答对、判分判错」**，不是模型不会。
v2 已把这 6 题剔除 ⇒ 已知假阴性来源被消除；但判分函数本身**仍未修**：
`verify_flag()` 位于他人在途 WIP 的 `ctf_stepfun_orchestrator.py`，
`candidate_variants()` 位于共享 `scripts/experiments/flag_util.py`，
两者本轮均未碰（红线：不单方改他人 WIP，且改判分口径会让三份历史 verdict 失效）。

⇒ **v2 的 `0 命中` 依然不能读成「模型一道都没解出」**；只能读成
「按现行判分口径的命中数为 0，且该口径已知存在不去壳偏差」。
v2 跑批结束后会用同一审计脚本复算，确认已知假阴性归零（见
`全量154题_v2_20261106.md`）。

1. **零私有题**：154/154 公开，模型记忆与公开 writeup 无法排除。
2. **判分不去壳**：他人 WIP 未修，`0 命中` 含已知口径偏差。
3. **题面结构性不可解**：v1 全量实测题面中位数 78 字符、最短 1 字符，
   23 题需附件却未传 `--artifact-dir`（本轮仍为 pure_llm 路径）。
4. **agentic 路径未跑**：`CTF_AIRGAP=1` + IP 直连证明 + 单通道 +
   判据接进 `solve_one()` 均未做。
5. **发布链未刷**：`count_stats` 数字、安装包、push 一律不动。

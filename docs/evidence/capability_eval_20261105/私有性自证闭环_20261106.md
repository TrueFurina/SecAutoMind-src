# 第六个偏差：私有性「题面自证」闭环（2026-11-06）

> 状态：**已取证 + 已内生修复 + 已接 CI**。本文不含任何明文答案；所有数字可用
> 文末命令重跑。结论作用域仅限 `SecAutoMind` 的纯 LLM 评测判据链，
> 不涉及赛时提交链路，也不改变任何历史跑批的命中数。

## 1. 发现：判据链最上层是「自己声明自己可信」

`audit_pool_prior.classify()` 判定一道题 `private_proven` 的四条依据全部取自
**题面字段**：`source` 含私有标记、`created_at` 晚于训练截止、id/描述/pool 不含
公开赛事标识、有来源字段。而 `run_capability_eval.claim_scope_for_pool()` 的
旧逻辑是：

```
if 全池 private_proven:
    claim_scope = "capability_rate_candidate"   # 于是数值可以叫「能力率」
```

也就是说，**出题方在题面里写一句「我是私有的、我是 2026 年写的」，判据就信了**。
这与前面五个偏差同源：声明被当成证据。

### 可复现攻击（实跑，非推演）

取 `data/ctf_benchmark/purellm_clean_benchmark_v2.json` 的 154 道题，
**只改** `id` / `name` / `description` / `pool` / `source` / `created_at`，
`flag_sha256` 一字不动（题目真值完全没变）：

| 步骤 | 结果 |
|---|---|
| 原题 `ext_cybench_hackthebox_...` | `classify()` → `public_named` |
| 单题改元数据 | `classify()` → `private_proven` |
| 整池 154 题改元数据 | `private_proven = 154/154`，`capability_rate_publishable = True` |
| 旧 `claim_scope_for_pool()` | 会返回 `capability_rate_candidate` |

⚠️ 第一次尝试伪造时**没有成功**：用 `dict(v, ...)` 继承了原题的 `name` 等
公开标记字段，被 `PUBLIC_RE` 命中。严格丢弃原字段后才成立。
这个「失败—重取证」过程本身说明：不是随便加个字段就能洗白，但**只要愿意改
元数据就一定能洗白**，且判据对此毫无防御。

⇒ 一句话：**同一批公开题，换一层元数据就能从「工程回归读数」变成「能力率候选」。**

## 2. 修复：私有性必须有外部锚点（R0–R6）

新增 `scripts/audit_private_proof.py`，定义 fail-closed 契约。注册表
`data/ctf_benchmark/private_pool_registry.json`（逐题记录）必须满足：

| 编号 | 判据 | 堵的是 |
|---|---|---|
| R0 | 注册表 `pool_sha256` == 当前池文件 sha256 | 换池套用 |
| R1 | 注册表存在、可解析、**已在 git 历史中** | 本地草稿冒充证据 |
| R2 | 池内每题都有条目，无多余条目 | 挑几题做样子 |
| R3 | `problem_fingerprint` == `sha256(description + "\n" + flag_sha256)` 重算值 | 注册表与池内题目不一致 |
| R4 | `flag_sha256` 不与任何已知公开池真值重合 | **公开题套私有壳洗白**（第 1 节攻击） |
| R5 | `first_commit` 是真实 commit，提交日期从 `git show` 读、`> 2025-01-01`、且等于登记值 | 自填创建时间 |
| R6 | `declared_unreleased == true` | 必要条件，非充分条件 |

公开池清单只列**已入库**的 4 份（`purellm_clean_benchmark.json`、
`_v2.json`、`real_benchmark.json`、`external_bench.json`）。
`purellm_full188.json` 被 `.gitignore` 忽略、CI 拿不到，挂进去只会制造一条
假缺失，故不列入。当前实扫得 **214 个去重公开真值**，缺失清单 0。

任一条件不满足 ⇒ `anchored=False`。注册表缺失/解析失败/公开池全不可读 ⇒
整体 fail-closed，绝不猜一个绿。

### 内生化到 verdict，不靠外围文档提醒

`run_capability_eval.claim_scope_for_pool()` 现在由代码重算
`private_proof_anchored`，且**只有它为 True 才允许 `capability_rate_candidate`**：

- 题面自证全私有 + 无外部锚点 → 强制 `engineering_regression_only`，
  reason 写明「题面自证全私有但缺外部锚点 ⇒ 不采信」；
- verdict 新增 `private_proof_anchored` / `private_proof_anchored_count` /
  `private_proof_reason` / `private_proof_contract` / `private_proof_registry_path`；
- `--run` / `--adjudicate` 的控制台输出增加一条对应告警。

**4 份历史 verdict 已补字段**，逐键校验：`claim_scope` 与
`scoring_variant_gap` 之外所有字段与 HEAD 版本完全一致（判分数字一个没动），
作用域全部仍为 `engineering_regression_only`、`anchored=False`。

### 不是「永远红灯」

`scope_selftest()` 新增反证：局部打桩注入一份合规锚点结论 ⇒
`capability_rate_candidate`（证明该分支可达）；无锚点 ⇒ 强制降级。
生产调用路径**没有任何注入参数**，打桩只存在于自测内部。
`audit_private_proof.py --selftest` 12/12，含：

- 合规合成注册表放行（用真实 HEAD commit 与 git 读出的日期）
- 注册表未入库、伪造 commit sha、自填日期与 git 不符、内容指纹漂移、
  缺未公开声明、注册表缺题、契约头不符、换池套用、注册表缺失 → 全部拒绝
- 公开题真值套私有壳（R4 洗白攻击）→ 拒绝
- 同一攻击在旧判据里确实得到 `private_proven` → 证明洞真实存在

## 3. 顺带修掉的两个接线缺陷

**(a) 评测链路自测此前根本没接 CI。** `grep` 确认 `ci.yml` 里
`run_capability_eval.py --selftest` 出现 0 次 —— 又一次「写了判据没锁」。

**(b) 自测不可移植，直接接 CI 会必红。** 缺件模拟（临时移走
`.workbuddy/tmp/rev_leak.out`）实测 `--selftest` **RC=1**：
B 段正向链路依赖这份未入库的本机产物，而 `load_leak_ids()` 缺文件时应
`available=False`，`judge_run()` 正确地判全批 `NOT_ATTRIBUTABLE`。
修法不是把它入库，而是让 **B 段自测自包含**：合成数据时改用「可用但为空」
的合成泄漏集并打印提示；生产判分 `adjudicate()` 仍读真实泄漏集，
其 fail-closed 由 A 段变异用例「泄漏集不可用 ⇒ 不可归因」守住。
复跑验证：有/无 `rev_leak.out` 两种环境都 `19/19 + 12/12、链路自测 PASS`。

新增 CI job `capability-caliber-gate`（`fetch-depth: 0`，因为锚点要查
首次入库 commit 的时间戳）：

```
python scripts/capability_caliber_test.py       # 两个 selftest 的 CI 入口
python scripts/audit_private_proof.py --verify # 证据与当前池一致
```

按项目 `*_test.py` 约定建入口，**没有去改他人维护的 `gen_gates_map.py`
识别规则**。门禁地图重生成后：38 个 job / 31 个带自测，新 job 标「有」；
`gen_gates_map --check`、C5/C6、docs lint 全 PASS。

> 历史漂移留痕：`docs/GATES.md` 手写盲区段仍写「标『无』的 12 个 job」，
> 在本次新增前就已过时（实际 7 个）。属发布节点的数字校准项，
> 本轮不单方改他人材料，仅记录。

## 4. 刻意不做：对外「能力率叙事」门禁

全仓 100+ 份 `.md` 含解出率/成功率字样，但按「结论作用域 = 断言作用域」
收窄到**纯 LLM 能力率**后，窄口径仅命中 1 行，且是引用外部论文数字
（ChatGPT Agent 76.1% vs 纯 LLM 17.6%），不是本项目自称。
现存 `16/55=29.1%` / `6/6=100%` / `19/55=34.5%` 等是**静态求解器 / 靶场对照 /
编排召回**读数，多数自带免责（「不作能力证据」「只作回归」「待验证」）。

⇒ 结论：口头纪律「对外不许出现解出率」实际被遵守，只是从未机验。
给一个当前恒绿、只能靠合成用例变红的门禁加进 CI，制造的是新的空洞绿，
**本轮不建**。若将来出现真正的纯 LLM 能力率宣称，应由
`claim_scope=capability_rate_candidate` 的 verdict 支撑，而该值至今为 0 份。

4 份 verdict 的 `claim_scope` 分布（本轮复核）：

| verdict | claim_scope | capability_rate | claimable | anchored |
|---|---|---|---|---|
| `verdict_smoke3.json` | engineering_regression_only | null | False | False |
| `verdict_smoke3_closed.json` | engineering_regression_only | 0.0 | True | False |
| `verdict_full160.json` | engineering_regression_only | 0.0 | True | False |
| `verdict_full154_v2.json` | engineering_regression_only | 0.0 | True | False |

# 第十二个偏差：agentic 前置「首次全绿」是跨层假绿（勘误）

日期：2026-11-06　提交：见 `git log`　范围：能力评测前置守卫，**不产出任何能力分数**

## 0. 勘误声明（最高优先级）

`IP直连证据与结果出口_20261106.md` 与当轮结论里写的
「`--preflight --mode agentic` 带 proof → 11 项全 OK / RC=0，agentic 前置守卫首次全绿」
**作废**。那份全绿证明的只是「Go 探测二进制上的 seccomp 闸门有效」，
与 agentic 跑批实际使用的解题子进程不是同一条路径。本轮把它撤回为 **RC=2**。
`airgap_ip_direct_proof_20261106.json` 本身仍有效（机制层证据），但其作用域声明
被消费者忽略，不得再用于放行 agentic 跑批。

## 1. 实证：前置全绿 + IP 直连 proof，解题子进程依然能出网

条件与上一轮完全一致（三项开关全开，且带那份 proof）：

```
CTF_AIRGAP=1 RUNNER_LLM_NO_FALLBACK=1 CTF_AGENT_INTERNAL_PRESOLVE=off
```

只读导入他人 WIP `ctf_stepfun_orchestrator.py`，调用其 **agentic 唯一工具出口**
`run_python_tool(code)`（即 `call_llm_agentic` L593 的实际执行路径），
代码用 `importlib.import_module('so' + 'cket')` 拼装模块名以避开 `_audit_code`
的关键词正则，然后对**已知可达 IP** 做直连：

```
_audit_code      = allowed=True reasons=[]          # 正则守卫被绕过
run_python_tool  = CONNECTED 172.16.222.99 22 ('172.16.222.99', 22)
                   FAILED 127.0.0.1 22 ConnectionRefusedError 10061
```

`CONNECTED` 而非 `PermissionError errno=1` ⇒ syscall 层没有任何拦截。
第一次用 `1.1.1.1:443` 得到 `TimeoutError`，也**不是** EPERM（socket 创建本身成功）；
按项目铁律改用可达 IP 后才拿到可判定结果。

## 2. 根因：证据的作用域声明被消费者忽略

| 层 | 实际对象 | 隔离 |
|---|---|---|
| proof 探测对象 | Go 二进制 `cmd/airgaptest` 自 re-exec 装 seccomp | 有效（TCP/UDP EPERM、AF_UNIX 放行） |
| agentic 跑批解题子进程 | `subprocess.run([python, '-I', '-c', code])` | **无**；只靠源码正则 `_audit_code` |

证据文件自己已经写明局限，前置守卫却只读了两个布尔值：

- `airgap_scope` = 「解题子进程 python_session/skill/流式 shell」（**Go 侧**）
- `caveats[0]` = 「只证明 seccomp 闸门在该服务器该二进制上生效，
  **不证明任何一次跑批真的开了闸**」
- 旧 `preflight()`：`proof_ok = ip_direct_blocked is True and af_unix_ok is True`
  —— 没有读取 `airgap_scope` / `caveats`，也没有与 `--` 之后的跑批命令做任何绑定。

⇒ 「机制存在」被当成「本次执行已隔离」；判据层 `airgap_zero_egress_proven` 也跟着写 True，
未隔离子进程里的命中会被 `judge_one` 归因成解出。这是**证据作用域错配**，
比「证据被篡改」更隐蔽：证据是真的、门禁也是绿的，只是答非所问。

## 3. 修法（只改 `run_capability_eval.py`，不改 WIP、不改证据文件、不改 `ci.yml`）

1. 新增纯函数 `agentic_run_binding(proof, command)`：放行需**双条件**
   - 机制层：`ip_direct_blocked && af_unix_ok`；
   - 绑定层：`proof["run_binding"]["command_sha256"]` == 本次跑批命令指纹，
     且 `subprocess_ip_direct_blocked is True`（本次解题子进程内实跑 IP 直连 A/B）。
   - 无命令 / 缺 `run_binding` / 指纹不符 / 子进程未证明 ⇒ 一律 False，理由逐条可打印。
2. `preflight()` agentic 分支新增检查项「本次跑批解题子进程隔离绑定」，
   并把 `ev["airgap_zero_egress_proven"]` 改成 `proof_ok and bound_ok`
   （判据层不再拿到跨层假信号），另记 `airgap_scope_binding`。
3. `airgap_scope_selftest()` F 段 **7 例**变异验证，接进 `pipeline_selftest()`
   —— CI 第二段本来就跑该入口，故 `ci.yml` / `GATES.md` 未改。
4. docstring §18 写清「机制证据 ≠ 本次执行隔离」。

**当前状态：agentic 路径 fail-closed、不可跑批。** 现有 proof 无 `run_binding`，
无论 `--preflight` 还是 `--run` 都返回 RC=2；Go runner 路径同样不豁免，
因为它也需要「本次跑批子进程」的证据，而不是探测二进制的证据。

## 5. 边界（不夸大）

- 本轮**撤回一个自己上一轮制造的假绿**，不是能力进展；`--run` 真实评测一次没跑，
  题源仍全公开、`anchored=False (0/154)`、4 份 verdict 作用域与 rate 一个没动。
- `run_python_tool` 的正则可绕过属他人 WIP（7+/5-），**未修改**。
  本文只做记录；真正修复需给该子进程接 syscall 隔离或改由 Go runner 执行。
- Go 侧 seccomp 机制本身仍有效，`airgap_ip_direct_proof_20261106.json`
  保留为机制层证据，但**不得单独用于放行任何 agentic 成绩**。
- 要让 agentic 真正可用，需补齐：① 本次跑批解题子进程内的 IP 直连 A/B 证据；
  ② 该证据与跑批命令指纹绑定；③ 私有题池 + 外部锚点注册表。

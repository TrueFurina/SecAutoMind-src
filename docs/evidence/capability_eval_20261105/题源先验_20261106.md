# 题源先验审计：为什么 160 题跑完也不能叫「能力率」

日期：2026-11-06　｜　工具：`scripts/audit_pool_prior.py`　｜　证据：`pool_prior_audit.json`
关联：评审 §13.7「唯一剩余动作」中的「私有题 / 模型先验前提」这半条。

## 1. 结论（先说结果）

```
pool_sha256        = 0835c1f274c79ba0…
total              = 160
private_proven     = 0      ← 可证明私有的题，一道都没有
public_named       = 160
unknown            = 0
requires_airgap    = 23
capability_rate_publishable = False
```

**干净池 160/160 题全部是公开竞赛题或公开基准题。** 因此无论全量跑批命中几道，
该数值只能作为**工程回归读数**（验证链路、判据、通道、耗时），**不得对外称为能力率**。

分布（`public_by_pool`）：`real` 76、`external` 39、`ext88` 23、`cybench` 11、
`heldout` 11。逐项看不是靠标签猜的：

| 组 | 实际 id 形态 | 公开性来源 |
|---|---|---|
| `external` 39 | `ext_gctf2021_abc-arm-and-amd` … | Google CTF 2021 公开题，官方仓库有 `challenge/flag*.txt` |
| `real` 76 | `real_anxun2020_BeCare4`、`real_crypto_anxun2020_coolboy` … | 安洵杯 2020 等公开赛事，公开 writeup 存在 |
| `heldout` 11 | `ext_nyu_ctf_bench_2017q_cry_lowe` … `2023q_for_1black0white` | NYU CTF Bench 2017–2023 公开基准数据集 |
| `ext88` / `cybench` | `ext_*` / cybench 公开基准 | 公开题库 |

🔴 **`heldout` 不等于私有**：它只是本系统内部的「留出集」划分，题目本身来自
NYU CTF Bench 公开数据集，模型训练时完全可能见过原题与公开题解。
把 heldout 当私有题是本项目最容易再犯的一次口径错误。

## 2. 判据（fail-closed，四条全满足才算私有）

`audit_pool_prior.py::classify()` 对每题要求同时满足：

1. 题面自带显式来源字段（`source` / `origin` / `provenance` / `source_url`）；
2. 来源值含私有标记（`private` / `internal` / `unreleased` / `self-authored` / `自产` …）；
3. 题面自证创建时间（`created_at` 等）晚于保守截止线 `2025-01-01`；
4. `id` / `name` / `description` / `pool` 均不含公开赛事或公开基准标识
   （`ext_` / `real_` / `gctf` / `nyu_ctf_bench` / `cybench` / `anxun` / `github` / `writeup` …）。

**任一条不满足即判「公开或来源不明」，绝不靠猜测给题目开绿。** 干净池所有题的
字段并集只有 `category / description / flag_sha256 / id / name / pool / requires_airgap`
——连来源字段都不存在，所以第 1 条就全数不满足；`missing_criteria_histogram`
里 `no_source_field=160`、`public_identifier_present=160` 是同一事实的两面。

这四条是**必要不充分**条件：即使集齐，仍需逐题证明「无外网访问、无题面明文、
无训练白名单命中、通道归属单一」，`pure_llm` 也排除不了模型记忆。

`--selftest` 9/9：公开基准题、公开赛题、无来源自产题、自称私有但无时间戳、
时间戳早于截止线、四项齐备、四项齐备但带公开赛名、空来源串、带 URL 无来源，
分类全部符合预期。`--verify` 重算池指纹与证据比对，防证据漂移。

## 3. 工程闭环：把作用域搬进 verdict，而不是写在文档里

§13 三个假绿的共同根因是「证据由人填或外围声明」。只写一份提醒文档，
下一个读 `verdict.json` 的人依然会看到 `capability_rate: 0.0` 而误当成能力率。
因此本轮把这一维接进判据链：

- `run_capability_eval.py::claim_scope_for_pool()`：**代码重算**题源审计结果，
  只拿已存证据的指纹/计数做一致性校验，绝不采信证据文件里的结论字段。
- verdict 新增 `claim_scope`，三值：
  - `capability_rate_candidate` —— 全池题目可证明私有且审计证据一致（仍须其余判据）；
  - `engineering_regression_only` —— 存在公开/来源不明题，数值只能作工程回归读数；
  - `unverified` —— 题池/审计证据缺失、漂移，或**结果绑定池指纹与审计池不一致**（防洗白）。
- `--run` 判分与 `report()` 打印 `[!] 本批次数值仅为工程回归读数，不得对外称为能力率`。
- `--annotate <verdict.json>` 给已有 verdict **只追加**作用域字段，不重判、不改原有字段
  （写回前逐键比对 `before == after`，不一致直接拒绝），用于本轮已启动的跑批。
- `--selftest` 新增 C 段 5/5：公开池→回归读数、绑定指纹不一致→unverified、
  全私有池→candidate、审计证据漂移→unverified、证据缺失→unverified。

**`claimable=True` 的语义没有变**：它仍表示「链路合规、格式可引用」，
从来不表示「这个数可以叫能力率」。两者现在由 `claim_scope` 显式分开。

## 4. 对已有结论的影响（不藏）

| 结论 | 之前 | 现在 |
|---|---|---|
| `0/3` 闭环（11-06） | `claimable=True / rate=0.0`，文档里靠人提醒「不是能力率」 | verdict 追加 `claim_scope=engineering_regression_only`，代码自己说明 |
| `1/176` | 证伪：题面抄写 | 不变（且池未入库，早已不可归因） |
| `14/14`、`13/13` | 项目自行作废 | 不变 |
| 全量 160 题 | 「唯一剩余动作」 | 跑完是**工程回归读数**，不是能力率；能力证据仍为空 |

⚠️ 数据文件 `purellm_clean_benchmark.json` 的 `provenance.note` 仍写着
「本池仍为本地草稿…对外引用前须入库」——这是 11-05 草稿期文案，
该池已于 `9a4be25` 显式入库。**故意不改**：改一个字节就会让池指纹漂移，
使所有已绑定该指纹的 verdict 失去可归因性。此处仅作勘误留痕。

## 5. 要拿到可引用的能力率，还缺什么

1. **私有题池**：题目自带 `source=private self-authored` 与 `created_at` > 训练截止线，
   且 id/题面不含公开赛事标识；由 `audit_pool_prior.py` 判成 `private_proven`。
2. **agentic 路径 + `CTF_AIRGAP=1`**：有解题子进程，需 seccomp 隔离与 **IP 直连证明**
   （`ip_direct_blocked` + `af_unix_ok`）；pure_llm 路径该维 N/A，不冒充。
3. **单通道归属**：`RUNNER_LLM_NO_FALLBACK=1`（Go 侧）/ 固定 `--provider`（Python 侧）。
4. **逐题三条件**：sha256 命中 + 该题零外网 + 无题面明文 / 训练白名单命中。
5. 判据接进 `solve_one()`（目前仍是外层包装），发布节点才刷 `count_stats` 数字。

> 评委问「`0/3` 和 `0/160`，哪个更能证明系统能解题」——**都不能**。
> 分母不是核心；题是不是私有、模型有没有先验、判分时能不能证明这两点，才是。
> 现在项目不止有文档这么说，代码会在 verdict 里直接写出这个作用域。

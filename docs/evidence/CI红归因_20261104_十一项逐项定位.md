## 0. 一句话结论

11 项红不是「历史遗留」四个字能盖住的：**5 个根因里，4 个是防御性动作自己把判据切断**——

## 2. G1 —— `trithemius` 的「包装分支」把可读性门禁做成了恒真条件

**机制**（`internal/ctfplatform/presolve_trithemius.go:42-55`）：
对题面全文做 ±1 位置移位，若 `trithemiusPlausible()` 通过，就直接拼 `"HTB{" + dec + "}"` 当候选答案。

`trithemiusPlausible()`（:76-90）的判据是：**可打印率 ≥0.9 且空格/下划线 ≥2**。
而输入的英文题面本来就是"可打印、多空格"——移位只改字母，不改可打印性和空格数。
**所以这个门禁对英文题面恒真**：任何英文题面都会得到一个 `HTB{<乱码句子>}` 候选。

**实证 5 例**（本机 48.81s 复现，`engine=trithemius`）：
`ext_gctf2021_david-and-the-tree`、`ext_gctf2022_segfault-labyrinth`、`ext_gctf2023_papapapa`、`ext_gctf2025_bpfbox`、`ext_gctf2025_numerology`。
其中两例候选极短（`HZM{ovls}`/`IAN{pwmt}`），说明拼出来的不只是"长乱码句"，短串也照样过闸。

**为什么比 CI 红更严重**：该 solver `Priority 22`。`presolve` 一旦把它判成 best，上层会按"已解出"短路，Agent 不再真解——**拿一段伪造的 `HTB{...}` 当战果**。这条分支历史上已有一次回归：2026-11-02 `wolvctf2024_xor` 的 base64 密文被硬包垃圾串，priority 22 抢过 `xor_known_plaintext(37)`。

**为什么测试红了**：`externalbench_false_positive_test.go` 的规矩是"未登记的非占位符假阳性一律红，且不许直接把题号加进台账了事"（:120 的断言文案就是这么写的）。5 例未登记 → 红。

**可选的修法（三档，均未执行，等拍板）**
- A（治本，推荐）：给包装分支加**语义判据**——解码结果必须满足"词表命中率 ≥X"或"整串不含空格"（真 flag 不含空格）。
- B（收敛）：只在 `text` 不像自然语言（字母频率异常/无空格）时才启用包装分支；对英文题面直接跳过。
- C（最省事、最危险）：把 5 题登记进 `externalBenchKnownFalsePositives`。**测试自己的注释明令禁止**这种做法，且等于承认生产路径会给错答案。

## 3. G2 —— 脱敏改了基准语料，判据没跟着改（4 个 job 连坐）

### G2a `benchmark.json` 15 题题面被改成 `flag{REDACTED_*}`，`arena_manifest.json` 仍拿原 flag 判分

- 提交：`fe62edc`（"fix(build): 收口前一阶段未提交的 WIP"），该文件 `91 +/ 103 -`，其中 45 行含 `REDACTED`。
- 事实：`data/ctf_benchmark/benchmark.json` 15 题 description 含 `REDACTED`：
  `log_forensics, net_forensics, html_comment, json_leak, cookie_leak, web_sqli, web_xss, web_lfi, web_rce, web_idor, web_csrf, web_ssrf, forensic_1, forensic_2, forensic_3`。
- 而 `scripts/arena_solvers.py` 的设计是"从 `benchmark.json` 的 description 取密文 → 解出明文"，`arena_manifest.json` 里存的是**原 flag**。脱敏后解码结果必然对不上 → 15 题必判 `regressed`。
- 本机逐题比对（`$env:TEMP\probe_arena.py`，只打印布尔+哈希前缀、不打印明文）：**一致 0 / 不一致 15**。
- 结论：这不是"能力退化"，是**判据与语料版本不一致**。要么同步 `arena_manifest.json`（并对"已脱敏不可解"的题做标记或从清单剔除），要么把脱敏只做在展示层、不动语料。

### G2b `real_benchmark.json` 4 题被标 `prompt_answer_redacted`，但「基线地板 20」没重锁

- 提交：`1dafb8e`（2026-10-31 12:38，作者 Dream），该文件 `30 +/ 13 -`，新增字段 `prompt_answer_redacted: true` + `prompt_answer_redacted_fields`，把 4 题的题面答案改成 `flag{REDACTED_flag_in_html}` 等。
- 这 4 题：`flag_in_html, flag_in_json_api, flag_in_cookie_set, flag_in_log_data`——正是"题面即答案"的伪解题，脱敏是**正确的**。
- 后果：`static` 命中 20/55 → 16/55，正好 −4。而 `check_benchmark_parity.py` 与 `check_suite_parity.py` 的地板仍是 20。
- 门禁自己写了处置办法：「确属测量口径变更 → `--update-baseline` 重新上锁并在 commit message 写明」——**这一步没做**。于是 evidence / parity / quant 三个 job 同时红，`benchmark-validity` 的 C 层从 39 变 43（71.0% → 78.2%）。
- 结论：**四门同根**。语义是对的，上锁动作缺失。

## 8. 锐评（不留情面版）

1. **「防御动作把功能砍了」不是第一次，也不是最有创意的一次，而是最没记账的一次。** 脱敏语料换来了 `secret_guard` 好看，代价是 4 个 job 恒红 + 15 题判"退化"，而这两件事没有任何一处写在同一个地方——直到今天才被并到一起。
2. **基线是判据，不是纪念品。** 语义变更（`prompt_answer_redacted`）已经写进 commit message，却没人执行门禁自己给的 `--update-baseline`。结果红的是"校验器"，坏的是"记账纪律"。
3. **`trithemius` 那条门禁等于没门禁。** `可打印率 ≥0.9 且 ≥2 空格`——这两个条件在英文题面上恒成立。用恒真条件当防线，和"code freeze 只写在指令里"是同一类错误：把约束写成了请求。
4. **它已经真的骗过人一次**（11-02 `wolvctf2024_xor`）。当时按"个案回归"修了门禁参数，没有回头问一句"这个门禁能拦住别的题吗"。今天 5 例就是答案。
5. **`truth-source-gate` 红得体面，但没有校验力。** 一个解析 0 题就 fail-closed 的门禁，等于一个永远举红牌的裁判——红牌是真的，但它已经不看比赛了。
6. **口径清单替门禁宣布 PASS**，这是本仓最该 outlaw 的动作。文档可以滞后，不能替门禁下结论。
7. 唯一值得肯定的：`docs-lint` / `agent-docs-gate` / `CTF-Agent pytest` 三项是本轮真修的，修完在**干净检出**里验过（`git worktree` 仿真，不是"我本地绿"）。

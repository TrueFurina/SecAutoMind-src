# 门禁「空扫描集假绿」审计与行为级防线（2026-11-10）

> 一句话结论：遍历型门禁的通用形态是「收集文件 → 逐文件检查 → 汇总 errors → 空则
> rc 0」。扫描范围一旦被缩小、路径常量写错、目录被移走，就变成「扫 0 个文件 = 0 条
> 违规 = 全绿」。本轮实测确认 **2 个门禁已处于该状态并修复**，另有 **7 个同类门禁
> 仍处于该状态**（如实登记为可见挂账），并新增一道**行为级**判据防止新增门禁再犯。

## 1. 缺陷与四象限红测

判据口径：在进程内把 `os.walk` / `glob.glob` / `glob.iglob` / `os.listdir` /
`pathlib.Path.rglob|glob|iterdir` 全部替换为空，再调用门禁的 `main()`，看返回码。

| 门禁 | 修复前 正常 | 修复前 空集 | 修复后 正常 | 修复后 空集 |
|---|---|---|---|---|
| `scripts/check_flag_eval_regex.py` | rc=0 | **rc=0（假绿）** | rc=0 | **rc=1 且点名「扫描集覆盖不足」** |
| `scripts/check_docs_lint.py` | rc=0 | **rc=0（假绿）** | rc=0 | **rc=1 且点名「扫描集覆盖不足」** |

红测方法：用 `git show HEAD:<path>` 取出修复前源码，`exec` 到以真实路径为
`__file__` 的命名空间（保证 `ROOT` 解析正确），再施加空集 patch。四象限结果如上，
所以「修复前确实假绿、修复后确实判红」不是推断，是同一份判据对两个版本各跑一次。

### 1.1 `check_flag_eval_regex.py`（危害最高：它保护判分红线）

`os.walk(SCRIPTS)` 是唯一扫描入口，`violations` 由循环内累积。扫描集为空时
`violations == []`，`main()` 直接返回 0 并打印「无未挂账违规 / PASS」。也就是说：
一个专门防「小写-only 正则 / 裸 sha 比较」造成**模型答对却判不中**的门禁，在路径
常量写错时会对全仓静默放行。

修法：`scan_all(stats)` 统计被遍历的 `.py` 数；新增纯函数 `coverage_errors(scanned)`；
`main()` 在 `scanned < MIN_SCANNED_PY(100，实测 215)` 时 fail-closed 并把错误计入
返回码。`--self-test` 增加第 11 条变异（空集必红、达标不误报），现 11/11。

注意作用域：下限只加在 `main()` 门禁入口，不加在 `scan_all()`。因为 `--self-test`
在临时小目录里直接调 `scan_all()` 做 10 条变异，若加在函数内部会把变异用例全判红。

### 1.2 `check_docs_lint.py`

`run(root)` 遍历 `iter_docs(root)`（`docs/` 递归 + 仓库根 `*.md`）。空集时
`findings == []`，打印「未发现不闭合代码块 / 断裂本地链接 / 不存在的脚本引用 /
缺失的中文对应」并 PASS——它把「没有文档可查」说成了「文档全部通过」。

修法：`MIN_SCANNED_DOCS = 150`（实测 300）；`main()` 计算 `n_docs` 并追加覆盖错误
到 `findings`；`--no-coverage-check` 仅供回归夹具显式使用（CI 默认入口不带）；
`check_docs_lint_test.py` 新增 T20（真实仓库覆盖检查生效）与 T21（空集必须判红），
现 **22/22**。

## 2. 更大范围：21 个遍历型门禁里 9 个有防线、7 个仍在假绿

从 `ci.yml` 的 `run` 行提取「`python [scripts/]X.py`」并按 AST 判定是否含目录遍历
调用（排除 `ast.walk`），得到 21 个遍历型候选。逐个子进程跑「正常 / 空集」两态：

| 定性 | 数量 | 处置 |
|---|---|---|
| 空集判红（有防线） | **9** | 纳入判据强制项 |
| 空集仍报绿、已确认但本轮未修 | **7** | 具名挂账，只减不增，发布节点前必须清零 |
| 不适用 / 环境依赖 | **5** | 具名豁免（需外部池日志、Go 二进制、量化重算、材料门禁既有挂账、本机 CRLF 假红） |

7 条挂账的实测证据（空集态输出）：

- `audit_benchmark_validity.py`：真求解器 0 题 / 命中率 0.0%，仍「PASS（3 项断言全过）」。
- `check_agent_docs.py`：C3「docs 顶层文档全部登记」与 C5「文档数 ≤ 44」在空集下是
  vacuous truth，全过。
- `check_doc_port_consistency.py`：自己打印「扫描 docs（0 个文件，跳过材料线 0 个）」
  然后 PASS——已经看见了 0，却没有据此判红。
- `check_final_artifacts_freeze.py`：没有冻结产物可比，PASS。
- `check_flag_extract_contract.py`：「仓库内各拷贝与判分口径逐份相符」退化成 0 份空真。
- `check_mcp_servers.py`：仍按固定清单报 3 个 server 并 PASS，目录侧遍历未进结论
  （需修或定性为不适用）。
- `check_web_asset_parity.py`：源/目标各 0 文件，仍判「一致——无漂移」。

这 7 条没有在本轮一并修，理由是每个门禁都有各自的回归夹具（临时小目录），加下限
需要同步加显式跳过开关并补变异用例；仓促批量改的风险高于收益。它们被登记在
`KNOWN_FALSE_GREEN`，判据每次运行都会打印清单，且**修复后必须删键**（见 §3 R8）。

## 3. 新增判据：`scripts/check_gate_scan_coverage.py`

设计原则：**不靠「源码里有没有 MIN_ 常量」**。正则/字符串匹配会被注释、docstring、
改名骗过（本项目已实证三次：`temperature_fixed` 判据、`_registry_threaded_proven`
判据、本次 `ast.walk` 被误判为目录遍历）。判据在独立子进程里真的把目录遍历 patch
成空，按 `ci.yml` 的真实 argv 跑门禁，看返回码。

判据 R1~R8：

| 编号 | 内容 |
|---|---|
| R1 | 候选集必须存在，且 `ci.yml` 可提取门禁数与候选数达下限 |
| R2 | 每个探测目标正常态必须 rc=0（不掩盖门禁本身的红项） |
| R3 | 非挂账目标空集态必须 rc≠0（rc=0 即假绿） |
| R4 | 不适用者必须具名豁免：键必须在候选集内、理由具体、数量有上限 |
| R5 | 候选集中「未探测且未豁免」的判红（防新增遍历型门禁漏登记） |
| R6 | 三层防缩水：`ci.yml` 门禁数、目标数、空集判红数各有下限 |
| R7 | 探测子进程异常 / 超时 / 加载失败不得静默当绿 |
| R8 | 假绿挂账：理由具体、只减不增；修好后挂账过期立即判红，逼人删键 |

变异自测 **19/19**，含 B0（正常态不误报）、B1（7 条冻结挂账不误报）、M14（挂账
过期）、M17（挂账数超基线）等。接线前该判据把自己判红（新门禁未接 CI），接线后
转绿——与上一轮可达性判据同样的自证方式。

实测：`ci_gates=35 / candidates=21 / targets=16 / 空集判红 9 / 挂账 7 / 豁免 5`。

## 4. 三次「探测工具出错」的教训（都已纠正，不据此下结论）

这一节是本轮最有价值的方法论部分：**探测工具本身也会假绿/假红**。

| # | 错误 | 症状 | 纠正 |
|---|---|---|---|
| 1 | 调用签名错 | 对 8 个门禁一律传 `argv`，`main()` 无参 ⇒ 全部 `TypeError`，差点被记成「门禁崩了」 | 用 `inspect.signature` 判参数个数 |
| 2 | patch 打偏 | 只替换 `Path.rglob/glob/iterdir`，而 7 个门禁用 `os.walk` / `glob.glob` ⇒ NORMAL 与 EMPTY 输出**逐字相同**（都报「59 个语料文件」），得出「7 个假绿」的假阳性 | 补 `os.walk` / `glob.glob` / `glob.iglob` / `os.listdir` 后重测，7 个假阳性全部消失 |
| 3 | 自指假阳性 | 判据自身用 `ast.walk`，被自己的 AST 判定认成「目录遍历」⇒ 把自己列为候选并判红 | AST 判定排除 owner 为 `ast` 的 `walk` |

教训固化为两条纪律：① 空集探测必须**两态输出对比**，输出相同就说明 patch 没命中；
② 判据先跑一遍自己，能把自己判红/判绿都当证据。

## 6. 边界（如实）

- 本轮修复 2 个门禁，**未修 7 个**已确认的同类假绿；它们被登记为可见挂账，不是通过。
- 判据作用域：`ci.yml` 中直接调用、源码含目录遍历的门禁。间接 import、动态
  `subprocess` 拼接、模块加载期就缓存文件列表的门禁不声称覆盖。
- 未改判分口径、分母、verdict、材料数字、交付包；未推远程（远程仍 `fa2fb6c`）；
  **真实 Linux Actions CI 仍未跑过**；23 个 WIP 未触碰。
- 本机 CRLF 工作树与 git blob 纯 LF 的差异，按既有纪律只在纯 LF 提交态下判定结论。

### 1.1 五条修法（形态一致：默认生效 + 显式跳过 + 回归变异）

四条共同点：**下限只加在门禁入口（`main`），不加在被复用的扫描函数**。因为每个门禁的
回归夹具都用临时小目录（1–3 个文件）直接调扫描函数或走 `--dir/--source`，把下限塞进
`scan_*` 会把全部夹具判红。

- `check_doc_port_consistency.py`：`scan_dir()` 已返回 `scanned`，`main()` 里判
  `scanned < MIN_SCANNED`。新增 `--no-coverage-check`；回归 `run()` 统一带上，
  另加 `run_full()` 跑不带开关的两条变体：T8（真实仓库 exit 0）、T9（空目录 exit 1
  且输出「扫描集覆盖不足」）。现 **9/9**。
- `check_web_asset_parity.py`：`compare()` 已返回 `source_count/target_count`，
  `main()` 在 `env_error` 之后判两侧下限。空集时**拒绝 `--sync`**——否则会把空源
  同步成空目标，制造「同步成功」的假象。回归三处调用统一加开关，新增
  `t11_scan_coverage`（真实仓库 exit 0 + 空目录 exit 1）。现 **20/20**。
- `check_flag_extract_contract.py`：`scan_regex_copies(root, stats=None)` 加可选
  累加器（`do_selftest` 的 6 处临时目录调用不传），`do_check_copies(require_coverage)`
  汇总两个 root 的 scanned 后判下限。`--check` 默认生效。现 `--check` RC=0 并打印
  「418 个 .py 内各拷贝逐份相符」，空集 exit 1。
- `check_agent_docs.py`：新增 `check_scan_coverage()` 作为 **C7**，只从 `main()` 调，
  `self_test()` 的最小树完全不受影响（9 项自测仍全过）。空集下 C3「0 份全部登记」与
  C5「0 ≤ 44」都是 vacuous truth，C7 是唯一能戳破它的判据。
- `check_mcp_servers.py`：`list_services()` 之后判服务数；空集时 A 的「索引→目录存在」
  仍会检查（`os.path.isdir` 不受 patch 影响），但 B/C/D 三层全跳过，所以需要显式下限。
  回归新增 `run_full()` 与 T17/T18（用「只拷索引文件、无服务目录」的临时目录构造
  真空集，避免被「索引缺失 → exit 2」的 fail-closed 抢先）。现 **18/18**。

### 1.2 两条「不适用」的实测依据（不是凭感觉放行）

- `audit_benchmark_validity.py`：`load()` 读的是两个**固定 JSON**（`open` 读取），
  `os.listdir(ATTACH)` 只用于附件集合。实测把 `os.listdir` 置空后，`--check` 输出
  `16/55 = 29.1%` 与 `16/16 = 100.0%`，与正常态**逐字相同**、PASS 结论不变
  ⇒ 空集不影响任何断言，属语义不适用。它的 CI 入口还是不带 `--check` 的报数模式，
  rc=0 是契约。
- `check_final_artifacts_freeze.py`：`if not got:` 走 `[SKIP]` 是 2026-10-14 门禁审计
  后的**有意设计**（CI 检出没有 PPT/压缩包/视频，否则门禁恒红）；而「清单 artifacts
  为空」已有独立 `[BLOCK]` 防线（同一段注释里写明的空洞绿防线）。两条合起来已覆盖
  真实风险，再加产物数下限会与「CI 检出必然无产物」冲突。

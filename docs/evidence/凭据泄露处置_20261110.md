## 二、处置优先级（顺序不可颠倒）

### 1. 🔴 立即轮换 —— 唯一能撤销危害的动作

**删文件、清 git 历史都救不回已公开的凭据**：public 仓库的 fork、clone、搜索索引、
CI 缓存、第三方镜像都可能已经留存。让密码失效是第一步，其余都在它之后。

在目标机上（用现有会话，不要把新值写进聊天/仓库/日志）：

```bash
# ① SSH 登录口令
passwd
# ② Web 后台管理员口令（按该服务自身的改密流程；注意其请求体是 camelCase 字段名）
# ③ 若该密码在别处复用过，那些地方同样要换
```

随后检查是否存在异常登录（只读）：

```bash
last -n 50
journalctl -u ssh --since "7 days ago" --no-pager | grep -i "accepted" | tail -50
```

### 2. 改密钥登录并关掉口令认证

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
# 把本机公钥追加进 ~/.ssh/authorized_keys（公钥非机密），chmod 600
# 确认密钥能登录后，再改 /etc/ssh/sshd_config：
#   PasswordAuthentication no
#   PubkeyAuthentication yes
systemctl reload sshd
```

⚠️ 顺序：先验证密钥登录成功，再关口令认证，否则会把自己锁在外面。

### 3. 清仓库历史（减少未来暴露，不消除已发生的）

口径由附录五的全历史审计钉死：**只需清 1 个路径**，但必须覆盖
**20 个远程分支 + 1098 个历史提交**，不是只推 `main` 和开发分支。

```bash
# 在一份全新 clone 上做，且需与所有协作者协调（force push 会改写历史）
git filter-repo --path <该运维脚本路径> --invert-paths

git push --force --tags
```

`forkCount = 0` ⇒ 没有公开 fork 需要协调（唯一的好消息）；但匿名 clone、
搜索索引与 CI 缓存无法撤销，所以这一步**只能减少未来暴露**。
同时：补 `.gitignore`、检查 GitHub 搜索缓存、把该脚本从任何交付包与参赛材料中
排除。**本轮未执行**（需你授权动远程，且会改写他人已 clone 的历史）。

### 4. 本地工程侧防复发（本轮已落地）

## 五、附录：全历史 / 全分支暴露面实测（07:4x 补测，纯本地只读）

**为什么必须补这一节**：本文件初版第 3 步只写了 `--path <占位符>`。但清历史之前
得先知道清哪些路径、覆盖多少 ref —— 只清一个文件、只 force push 两个分支，
改完仍会有 18 个分支带着明文。

**方法**：`git rev-list --objects --all` 枚举全部对象，`cat-file --batch` 流式取 blob，
对文本扩展名做「凭据赋值 / 私钥头 / sshpass 明文」三类形态 + 占位符过滤；
全程**只输出路径、形态标签、命中数与值长度分布**，值一个字节都不打印。

| 量 | 实测 |
|---|---|
| 全历史提交 / 本地可见 refs | **1098** / **50** |
| 远程分支（含 `main`） | **20** 个当前快照都含该脚本 |
| 全历史唯一对象 / 扫描文本 blob | **11911** / **6783** |
| 有「非占位凭据形态」的路径 | **14** 个 |
| 逐行遮蔽定性后 | **13 个是误报**；真凭据只在 **1 个路径、5 处**（值长度 9 / 16 / 24） |
| `.gitignore` 的 3 个 NEVER commit 项 | HEAD / main / 远程快照均**未被跟踪**，忽略确实生效 |
| 被跟踪的 3 个 `.pem` | 全部 `-----BEGIN PUBLIC KEY-----` 赛题附件，非私钥 |
| `forkCount` / `stargazerCount` | **0 / 0**（没有公开 fork 需要协调，唯一的好消息） |

13 个误报的构成（均经脱敏行骨架核验）：4 份 i18n 文件的 `passwordLabel` /
`passwordPlaceholder` UI 文案（各 33 处左右）、SQL 注入教学语料、本地
`127.0.0.1` 授权靶场的实验报告、单测里的假 PEM 头与断言字符串。

`git log --all -G` 另证：全历史只有 **1 个提交**改动过含该形态的凭据行。
⇒ **清历史口径 = 单路径 × 全 20 ref × 全 1098 提交**；没有第二个 P0。

⚠️ 审计边界：它按「字面量形态」扫，不能证明不存在以其它形态（Base64、
拆分字符串、运行时注入）存在的凭据。结论是「在可机验的字面量形态里没有
第二个」，不是「仓库绝对干净」。轮换口令仍是第 1 步。

### 二次修正：判据自己的多行盲区（07:5x）

上一节的暴露面审计没有覆盖「新加的判据本身是否可靠」。补测发现：初版
`NETWORK_PASSWORD_RE` 用 `[^\n]{0,160}?` 要求连接调用与 `password=` 同行，
把同一个假值改写成多行函数调用后，门禁 **RC=0 直接放行**（同行写法 RC=1）。
⇒ 一个只靠「换行」就能绕过的门禁，比没有门禁更危险。

修法：正则改 `[\s\S]{0,300}?`，通道从「逐行 search」改为「按文件全文
finditer」，行号取匹配结束处（`password=` 所在行，供白名单哈希钉死真正含值那行）；
值仍不跨行、仍不进 `masked`。放宽前先量化：全仓提交态 4134 文件、新旧规则
均 0 命中 ⇒ 误报面为零，不是靠豁免压下去的。

四场景端到端变异：同行 RC=1 / 多行 RC=1 / 根级 `tests/` 降级 RC=0（留痕 1 条）/
删探针 RC=0；两个假值在四次输出中出现 **0 次**；多行场景报告行号精确落在
`password=` 那一行。全仓门禁 RC=0、三套既有自测 RC=0。

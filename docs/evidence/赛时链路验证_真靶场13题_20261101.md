# 赛时链路验证：常驻真靶场 13 题（2026-11-01）

> 结论先行：**13/13 全命中，链路后半段（题面 → 真执行 → HTTP 打靶机 → 提取 flag → 判分）在服务器上成立。**
> 但这个数字**不是能力率、不是 KPI、不能对外报解题水平** —— 它验证的是"链通不通"，不是"题难不难"。

## 1. 为什么做这件事

赛时链路分两段：

| 段 | 内容 | 当前可验证性 |
|---|---|---|
| 前半段 | 轮询平台 → 领题 → 拿附件 | ❌ 评测平台全端点 `40403 无权限`，无开放赛道，**真机无法验证** |
| 后半段 | 题面 → L3 执行 → flag → 提交 | ✅ 可用常驻真靶场验证（本文） |

此前所有解题数字（如 3/12）都来自 `cmd/llmbench` / `cmd/evalharness`（`pyBridge=nil`，纯 LLM 下界），
**生产形态 `cmd/runner`（有 86 skill）从未在真机上跑通过任何一道题**。
本文先把后半段钉死，把"未知"缩小到只剩前半段与 skill 增量。

## 2. 方法

- **靶场**：`liverange-s4`（PID 1172435，服务器 `172.16.222.99`，LISTEN `19000`–`19013`，已连续运行）。
  设计上 `GET /targets` **不含 flag**、`POST /verify` **只回 bool**，与真实赛题同构，静态读题面拿不到答案。
- **题集**：`/tmp/range_bench.json`，13 题（2001–2013），字段 `id/category/sub/title/description/flag_sha256`。
  题面 = `/targets` 的 desc + `靶机地址: http://127.0.0.1:190xx`（**题面自包含**，因此不需要平台轮询）。
- **明文纪律**：题集只写 `sha256(完整 flag)`，明文未写入。生成时断言 `description` 内无 `flag{` 字面量（自检通过）。
  明文仅存在于本机编排侧临时脚本与仓库内 `internal/ctfplatform/live_targets.go`（自造靶场题源）。
- **二进制**：`git archive HEAD`（`c581932`，含附件落盘修复 + 四条伪造分数通道封堵）→ 服务器 `/tmp/fv2` 干净构建。
  **不带**工作树里并行会话的 270 个未提交改动。
- **通道**：jiyuan `https://tokenrhythm.studio/v1`，模型 `deepseek-v4-pro-0813`，串行（并发 1）。
- **闸门**：`RUNNER_LLM_FALLBACK=true`（llmbench 拒绝隐式直连，未设则 `RC=2` 直接退出）。

## 4. 判定审计（三重）

1. **sha256 匹配**：13/13，判分只读 `flag_sha256`，不读明文。
2. **外连审计**：日志中所有 HTTP 目标均落在 `127.0.0.1:190xx` 靶机。
   唯一非靶机目标：
   - `https://tokenrhythm.studio` —— LLM 通道本身（1 次，预期内）；
   - `http://example.com`、`http://127.0.0.1:80`、`http://localhost:19007` —— **WEB-07 SSRF 题模型自造的探测 payload 列表**（`for u in ['http://example.com', ...]`），属 SSRF 题面要求的正常打法。
3. **无背书污染**：13 个 flag 由我方自造（`flag{live_*_ok}`），公网与训练语料中不存在。
   即使模型外连也拿不到答案 —— 与 40 道 Google CTF 公开题（writeup 里直接有 flag）性质完全不同。

**因此这 13 条是真解出，不是抄的。**

## 5. 能证明什么 / 不能证明什么

能证明：
- 题面自带靶机地址时，L3 有能力**自己发现"必须真发请求"并执行**：2001 第 0 轮读题面、第 1 轮直接 `requests.get`，两次工具调用解题。
- `python_session`（常驻 REPL 真执行）在服务器上可用且稳定，`requests` 就绪。
- 附件/围栏修复后的 HEAD 二进制无回归，能连续跑 13 题不崩、不超时、不误杀。
- 判分链路（提取 → sha256 → 记账）无误判。

不能证明：
- **不是能力率**。13 题全为 WEB，且难度是"教学级"（源码注释、单点注入）。无 crypto / misc / reverse / pwn 覆盖。
- **不是生产形态**。日志明确 `execute_python: false` —— `pyBridge=nil`，那 86 个 skill 一个都没参与。
- **不是 KPI**。题是我们自己造的，不能与真题池混算，不进 KPI 分母。
- 前半段（平台轮询领题、真提交）仍未验证。

## 6. 由此暴露的真问题（比 13/13 更重要）

**那 86 个 skill 在 WEB 类上是零增量 —— 没有它们也能 13/13。**

这反过来说明：skill 的唯一价值区在 crypto / misc（现成爆破、分解、解码脚本省掉模型现场写代码的轮次），
而这恰好是真题主力、也是 17% 解题率卡住的地方。**但"带 bridge 的生产形态在 crypto/misc 上表现如何"至今没有任何真机数据。**

完整缺口清单：

| 缺口 | 现状 | 能否现在验证 |
|---|---|---|
| 平台轮询领题 + 真提交 | 平台 40403 无权限 | ❌ 需等放闸 |
| `execute_python` / 86 skill 通路 | 从未在真机跑过 | ⚠️ 需 llmbench 接 bridge（改代码） |
| crypto/misc 真靶场 | 靶场 13 题全 WEB | ⚠️ 需补靶场题源或换题集 |
| 附件落盘修复的效果 | 修复前 40/40 静默无附件 | ✅ 可重跑外部池（但有背书污染） |

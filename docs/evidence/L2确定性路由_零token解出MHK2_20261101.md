## 2. 为什么前三次全是 0（三层断裂，逐层实证）

### 第一层：Desc 列的是幻觉 skill 名（已修 708593f）
`execute_python` 的工具描述手写了 16 个 skill 名，15 个在 catalog 里不存在
（`factor_integer` / `rsa_wiener_attack` / `angr_decompile` / `pwn_checksec` / `zip_crack` …）。
真机后果：B 臂唯一一次 `execute_python` 调的就是 `factor_integer`，import 必失败。
→ 修法：Desc 从 catalog 现取，加回归锁（Desc 里每个名字必须真实存在）。

### 第二层：参数契约不可见
Desc 换成真名后，C 臂确实改用真名 `crypto_knapsack_mhk`，但传的是
`{"a1": [], "a2": [], "b": [], "c": []}` —— 名字对了、参数全空。
模型没办法从名字猜到它要 `kind` / `pk` / `ct` / `path`。
→ 修法：启动时一个 python 子进程 ast 解析 79 个 skill 源码，抽 params 键与
`kind` 分派分支；Desc 渲染成 `crypto_knapsack_mhk(a,ct,kind,path,pk,s_bits,verbose)`。
真机数据：**79 个 skill 中 70 个抽到契约，15 个有 kind 分派**。

### 第三层：L2 拿不到本地附件路径
L2 只认 `ch.AttachmentURLs`（平台下发的下载 URL）。离线跑批的附件在本地磁盘，
于是 `params["path"]` 永远为空 —— 所有"吃文件"的 skill 在跑批里等于没接上
（与 40/40 附件静默阉割同型：**能力没接上却不报错**）。
→ 修法：`TryCategoryLocal(ctx, cat, ch, localFiles, budget)`，每个本地文件各算一个
基础参数；再按源码分派分支补 `kind` 逐个试。

### 补充：模型不会自己用 skill（这条推翻了 L2 可以省略的假设）
D 臂之前先跑了「契约可见 + with-skills」：模型 23 秒就收工，只用了
`read_attachment` 3 次 + `python_session` 5 次，**一次 execute_python 都没调**。
→ 结论：不能把"模型会不会用 skill"当作 skill 价值的判据，必须走确定性路由。

## 3. 本次修掉的三个自身缺陷（都是真机跑批打出来的，不是既有代码）

1. **`extra` 参数合并写在了子进程执行之后。**
   合并块被插在 `// 解析 JSON 返回值` 之前，而那行在 `execSkillSubprocess` **之后**，
   于是 L2 注入的 `path` / `kind` 从未送到 skill。
   现象：日志打印 `kind=mhk2_decrypt`，skill 实际收到空 `kind` 并返回 `unknown kind`。
   **看起来极像"skill 解决不了这道题"，实则参数没送到。**
2. **`RunSkill` 只认 `flag` / `flags` 字段。**
   `crypto_knapsack_mhk` 把明文放在 `plaintext` 键 ⇒ skill 已解出却被判未命中。
   修法：自报 `ok`/`solved` 时，从所有字符串值按形态挑 flag
   （`plaintext`/`text`/`decoded` 都可能装答案）；判分侧仍走 sha256 精确比对。
3. **`path` 只取排序第一个文件。**
   mhk2 的两个附件按字典序是 `MHK2.sage` 在前，于是 skill 拿到 sage 源码而非
   `output.txt`，`literal_eval` 必然 SyntaxError。

三条都属于"静默错误"：不崩溃、不报错、结果看起来就是"没解出来"。

## 6. 这个数字不能当作什么

- **不能当能力率**：6 道题全是 Google CTF 公开题，题本身就是这些 skill 的编写对象
  （`crypto_knapsack_mhk` 的模块注释直接写"Google CTF 2023「MHK2」的确定性求解器"）。
  它证明的是**通路已接通**，不是**泛化能力**。
- **不能当 KPI**：不进外部池 KPI 分母（分母=39），也不属于 heldout。
- **不能外推到未见题**：1/6 只说明"当题与某个 skill 的适用面重合时，可以零 token 拿下"。
- 反向也不能说"skill 没用"：同一题 pure LLM 224s/0 候选，skill 104s/命中。

## 7. 工程口径与配置

| 项 | 值 | 说明 |
|---|---|---|
| `--with-l2` | 默认关 | 关=口径不变（纯 L3）；开=先跑 L2 |
| `--l2-budget` | 300s | **整类**预算。crypto 有 28 个 skill，不限会拖到 14 分钟/题 |
| `CTF_SKILL_TIMEOUT` | 30s | L2 批量扫单次超时（要短） |
| `CTF_SKILL_TIMEOUT_RICH` | 180s | 模型单点调用超时（LLL 类单次可达 100s+） |
| 展开上限 | 3 文件 × 4 分派 ≤ 6 变体/skill | 不设界会变成小时级 |
| 报告 `layer` | `l2` / `l2-miss` / `l3` | 区分"这分是 skill 挣的还是模型挣的" |

`--with-l2` 时允许没有 LLM key：这条路径零 token，是回答"不花一分钱能解几道"的唯一入口。

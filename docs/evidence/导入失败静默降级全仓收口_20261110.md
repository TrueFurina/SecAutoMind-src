## 4. C3 判据：如何区分「静默放弃」与「能力替代」

C2 只对 `presolve.py` 生效且绑定具体函数名 `_warn_import_once`；C3 面向全仓，
必须放宽到「任何 warning 级调用」，同时不能把合理回退误报成缺陷。

```
C3 纳入条件（三者同时成立）
  ① try 体只有 skills.* / agents.* 导入（纯导入探测）
  ② handler 以 return None / return 放弃整条通道
  ③ handler 内除 return / pass / debug|info 日志外，没有别的语句

  满足 ⇒ 必须有 warning 级调用（函数名含 warn，或属性为 warning/warn）
         且第一个字符串参数精确点名被导入模块
  不满足 ⇒ 豁免，计入 c3_fallbacks_skipped，不计入 C3 分母
```

第 ③ 条是区分器：`crypto_toolkit` 的 handler 含 `Assign`（`_MORSE = {...}`），
直接豁免；`continue` 因不满足 ② 也自动排除；求解异常因不满足 ① 排除。

**防缩水**：C3 分支数不得低于 `MIN_C3_GUARDS = 4`（实测 5），C2 仍为 18（实测 22），
C1 守卫模块数下限 2（实测 2）。C3 扫描前先做字节预筛（900+ 文件不必全 parse），
但**判据本身全部走 AST**，预筛只用于加速。

**变异自测 21 项全 PASS**（`--selftest`）：原 11 项（B0-B2 / M1-M8）完整保留，
新增 B3-B5 基线、M9（换回 debug）、M10（注释伪造告警）、M12（告警不点名模块）、
M11 两例（合成源码证明「内联回退豁免」与「同一分支改成 `return None` 必须判红」）、
M13/M14（C3 覆盖数塌陷 / 达标）。M11 专门防「豁免逻辑被当成无条件放行」。

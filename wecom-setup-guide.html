结论：你只需要在企微后台点两下，不用改代码、不用动服务器

企业微信通道的代码和服务器配置早就齐了，我实测过两件事：

  • 服务器上的企微凭证 真的有效 —— 用它能成功换取 access_token（返回 errcode:0）。
  • 回调地址 公网真的能访问 —— http://120.48.36.201:18086/api/robot/wecom 返回 HTTP 400 invalid signature。
    这个 400 是好事：说明路径活着、验签逻辑在工作，只是我这条 curl 没带正确签名而已。

所以缺的只有一环：企微后台还不知道把你的消息推到哪里。下面就是填这一步。

先搞懂

企业微信和钉钉不一样，别套用钉钉的经验

钉钉： 服务器 ──主动连──▶ 钉钉 （不要公网，Stream 长连接） 企微： 企业微信 ──推消息──▶ 你的服务器地址 （必须有公网地址）

所以企微这步必须在后台登记一个公网地址，让企微知道消息往哪推。
好消息：你的服务器本来就有公网地址 —— 120.48.36.201:18086。

你要做的 · 3 步

在企微管理后台登记回调地址

第 1 步 · 打开企微管理后台并登录

  1. 浏览器打开 https://work.weixin.qq.com/
  2. 右上角点「企业登录」，用管理员的企业微信扫码登录。

第 2 步 · 找到那个应用

  1. 顶部菜单进「应用管理」。
  2. 在「应用」列表里，找到「自建」分组下、AgentId 是 1000002 的那个应用，点它的名字进去。
  3. 在应用详情页里找到「接收消息」这一块，点「设置 API 接收」按钮。

找不到？就用 1000002 这个 AgentId 去对号 —— 服务器上配的就是它，只有一个。

第 3 步 · 填三个值，然后点保存

URL http://120.48.36.201:18086/api/robot/wecom
Token <见下方「Token 从哪来」>
EncodingAESKey <同样从服务器取原值粘贴，不要点「随机获取」（见下方坑 2）>

🔴 URL 必须带结尾那段 /api/robot/wecom 路径，不能只填 http://120.48.36.201:18086，也不要在结尾多打一个 /。三种写法的实测对照：
· 只填到端口 → 返回的是 677 KB 的网页首页（答非所问）→ 企微报「请求不通过」；
· 结尾多一个 / → 服务器回 301 跳转，企微未必跟跳 → 同样报「请求不通过」；
· 完整、且无尾斜杠 → 返回 HTTP 400 invalid signature。这才是正常信号：说明请求准确落到了回调处理器上，只是我这次探测没带合法签名而已。

填完点「保存」。企微会立刻向这个 URL 发一条验证请求：

  • 验证通过 → 弹出保存成功，配置即刻生效 ✅
  • 验证失败 → 见下方「保存报错怎么办」

如果后台这块的 EncodingAESKey 现在是空的，说明要重新随机生成 —— 那请先别保存，把随机出来的 43 位发我，我同步改服务器配置后再保存。

Token / EncodingAESKey 从哪来？

本页刻意不写死真实凭证（本仓库是公开的，写死等于永久泄漏）。登录服务器后自己取这三个值：

ssh root@120.48.36.201 \ "sed -n 's/.*corp_id: *//p' /opt/secautomind/config.yaml | head -1; \ sed -n 's/.*token: *//p' /opt/secautomind/config.yaml | head -1; \ sed -n 's/.*aes_key: *//p' /opt/secautomind/config.yaml | head -1"

把 Token（26 位）与 EncodingAESKey（43 位）逐字符粘进后台那两个框，别手打。它们必须与服务器配置完全一致，否则企微验证必失败。若后台这两个框现在是空的、或已被点了「随机获取」，一律清掉，改粘服务器原值。

三个必踩坑

照做就行，但别在这三处翻车

#坑后果 / 正解
1 Token 抄错一个字符 保存必报「验证失败」。后台填的 Token 必须和服务器上完全一致： <服务器 config.yaml 里 robots.wecom.token>（26 位，注意大小写）
2 手贱点了「随机获取」 EncodingAESKey 一旦重新随机，就和服务器上那个对不上了，验证必失败。 正解：保持原值；若确实要换，把新值发我，我改服务器后再保存。
3 以为保存失败是代码问题 保存时企微会马上来敲门验证。服务器必须在跑 + 地址必须公网可达。 这两项我刚刚都实测过了 —— 现在是好的。若你操作时恰好变了，先找我。
⚠️ 拦路虎（先分清一件事）

规则取决于：你的企业微信是否已做「企业认证」

企微官方技术支持的原话是分两种的：

  • 未认证企业：可以直接用 IP 地址配置回调 URL，不校验域名主体 —— 即 http://120.48.36.201:18086/api/robot/wecom 这条路本来应走得通。
  • 已认证企业：必须用域名，且域名ICP 备案主体要与企微认证主体相同或有关联，否则报「域名主体校验未通过」。

所以你填 IP 被拒，按可能性排序有三种：① URL 没填对（漏了结尾的 /api/robot/wecom，或多打了尾斜杠 —— 最常见）；② 企微是已认证（IP 必被拒）；③ 未认证，但被端口/可达性卡住。先排掉 ①，再谈 ②③。

⚠️ 订正：本文档早前版本写过「接收消息 URL 一律不支持 IP」——那句话只对已认证企业成立，属错误口径，已删。

后台报错原文结论最短路径
「域名主体校验未通过，需配置备案主体与当前企业主体相同或有关联关系的域名」 已认证企业 必须上域名：买域名 → 解析到 120.48.36.201 → nginx 反代 → ICP 备案（福建约 6–9 工作日）。
「openapi 回调地址请求不通过 / URL 需要正确响应验证请求」 先查 URL 是否填错（漏路径 / 多尾斜杠）；两项都排除后，才轮到端口/可达性。 按本页第 3 步把 URL 原样（含 /api/robot/wecom、结尾无斜杠）重填一次；仍不过再改走标准端口 80/443。
兜底 企微先挂着，用已接通的钉钉做答辩演示；企微按上表对应路径再补。

服务器侧（nginx 反代、端口监听、证书）我可以全部代做；你只需在腾讯云控制台放行端口（如需域名则再买域名 + 备案）。

验证

怎么确认真的接上了

  1. 保存成功后，打开企业微信客户端（手机或桌面版）→ 找到这个自建应用。
  2. 给它发一句「帮助」。
  3. 应先在几秒内收到内置命令回复；稍后收到 AI 生成的回复。

AI 回复走的是「异步处理 + 主动推送」：因为企微只给 5 秒接话时间，AI 想得慢，所以先回你一个占位、算完了再用 API 推给你。所以两条回复之间有几秒间隔是正常的。

# 工具故障分诊模板（诊断分层）

> 对应 REA #145「诊断分层：注册 / 重启 / 缺 provider 各有解药」。
> 用途：MCP 工具"调不通"时，**先定位在哪一层**，再动手；不许上来就重启。
> 纪律：每一层都有**判据**。判据不成立就不能跳到下一层——否则会把"没注册"当成
> "provider 挂了"，重启十次也不会好。

---

## 0. 先记录（30 秒）

```yaml
工具名: <tool_name>
现象: <一句话：报错 / 无响应 / 返回空 / 结果不对>
时间: 2026-10-20 20:15 (UTC+8)
调用方: <agent / 前端 / curl / 测试>
原始返回: <整段贴进来，不要只说"报错了">
```

---

## 1. 六层分诊表

| 层 | 判据（怎么确认在这一层） | 解药 | 不要做什么 |
|---|---|---|---|
| **L1 注册** | 工具不在 `GetAllBuiltinTools()` 结果里；或 `count_stats.py --json` 的 `builtin_tools` 与预期不符 | 补注册 / 查 `Name:` 常量拼写；确认 `RegisterTool` 所在文件被编译进包 | 不要重启服务——重启不会让未注册的工具出现 |
| **L2 授权** | 工具在册但返回"无权限/unauthorized"；`mcp_authorization.go` 里该工具不在当前会话允许集 | 按最小面授予权限；确认是否 T2 需显式申请 | 不要改工具实现——实现没问题，是准入没开 |
| **L3 入参** | 返回"参数错误/缺少必填"；或模型传了 schema 里没有的字段 | 对照 `InputSchema` 修参数；schema 描述不清则改 description | 不要放宽校验"绕过"——那会把脏数据写进库 |
| **L4 provider/密钥** | 工具本身无错，但依赖的外部能力报鉴权失败（如 LLM 11200、API key 缺失） | 检查 provider 配置与余额；确认 preset 正确 | 不要反复重试同一个坏 key（会触发熔断） |
| **L5 数据/上游** | 工具执行了，返回"未找到/空"，且上游确实无数据 | 先确认数据是否存在；空结果按 `NOT_ENOUGH_INFO` 返回，不编造 | 不要把"没数据"当成"工具坏了" |
| **L6 运行时/资源** | 超时、OOM、文件锁、并发冲突 | 看 `logs/` 与执行时长；确认单写者约束；必要时串行化 | 不要盲目加并发/加重试放大压力 |

**分层判据的核心**：L1/L2 是"工具根本没进来"，L3-L6 是"进来了但跑不成"。
两者的解药完全不同——前者改注册，后者改配置/数据/资源。

---

## 2. 常见误判对照

| 看起来像 | 实际常常是 | 怎么区分 |
|---|---|---|
| "provider 挂了" | L2 授权没开（工具压根没被调用） | 看日志里有没有该工具的调用记录：没有 ⇒ L2 |
| "模型不会用这个工具" | L3 schema 描述太差（模型猜错参数名） | 看模型传的 args 与 schema 是否一致 |
| "工具返回空 = 工具坏了" | L5 上游确实无数据 | 直接查库/查上游确认 |
| "重启就好了" | L6 偶发资源竞争 | 重启后复现次数→若稳定复现，回 L1-L5 逐层查 |

## 3. 处置记录（填完才算闭环）

```yaml
定位层: L?
判据: <贴出证明在该层的那一行日志/输出>
处置: <改了什么，改在哪个文件>
验证: <复跑命令 + 结果；失败也要写>
残留风险: <同类工具是否也有此问题 / 是否需要加守卫>
```

## 4. 升级为守卫（防复发）

同一个故障出现第二次，就必须变成机器能判的东西：

| 故障类型 | 守卫形态 |
|---|---|
| 工具漏注册 | `count_stats.py --json` 断言 `builtin_tools=52`，进 CI |
| 权限漏配 | 授权矩阵单测：每个 T0 工具在当前会话必须 allow |
| schema 漂移 | `scripts/audit_tool_contracts.py --gate`（T0 缺 schema/required 即红） |
| 错误原文直出 | 静态守卫扫 `textResult("错误: "+err.Error()`，存量基线 + 只拦新增 |
| 空结果被当成功 | 统一 `NOT_ENOUGH_INFO` 标记 + agent 侧消费断言 |

> 反例：只写"已修复"，不写守卫——下次换个人改同一处，故障照旧。

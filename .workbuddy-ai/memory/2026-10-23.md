- **构造（权威源对齐，非记忆）**：Herrmann–May PKC 2010 §3 原文 + mimoo `boneh_durfee.sage`：
  `A=(N+1)//2`、`f(x,y)=1+x(A+y)`、根 `(2k, −(p+q)/2)`、模 e；`f̄=u+Ax`（`u=xy+1`）；
  x-shifts `x^i f̄^k e^(m−k)`（k=0..m, i=0..m−k）；y-shifts `y^j f̄^k e^(m−k)`（j=1..t, k=⌊m/t⌋j..m）；
  LLL 后两条短向量反缩放 + 代 `u=wz+1` + 结式消元求整数根，`d=(1+w0(A+z0))/e`。
- 🔴 **踩坑 1（构造级）**：y-shift 必须先在商环 `Z[u,x,y]/(xy+1−u)` 约化（`x^b y^c → x^{b−1}y^{c−1}(u−1)`），
  否则引入不在单子集里的 `x^b y^c` 项 → 格构造错、短向量在根处不为 0、攻击全灭。
  已加断言：约化后所有单子必须落在「x-shift 单子 ∪ {u^k y^j}」内。
- 🔴 **踩坑 2（界）**：`Y=⌊√N⌋` 对根 `y0=−(p+q)/2` **偏小**（AM-GM 下 (p+q)/2 ≥ √N，
  p,q 不等时可达 ~1.4√N）→ `|y0|>Y` 破坏启发式。改用 `Y=2·⌊√N⌋+1` 后 128/192-bit 均成功。
  论文的 `Y=N^0.5` 是渐近口径，工程实现必须按实际根界取。
- 🔴 **踩坑 3（自测）**：用例消息比 n 还长（28 字节 vs 128-bit n）→ `pow(m,e,n)` 先取模，
  解密只能还原 `m mod n`。改用 8–11 字节消息 + `assert m<n`。
- 🔴 **sympy `Matrix.lll()` 不可用**：本格（满秩、无零行）上必触发内部断言
  `assert all(mu_small(...))`，换 delta/转置均无效（2026-10-23 实测）。改回 `common.lll_reduce`
  （Fraction 精确算术）。性能实测（无 sage/fpylll）：128-bit m=3 ≈3s；192-bit m=3 ≈9s；
  m=4 ≈26–110s；256-bit m=3 失败（需 m=4）。
- **预算纪律**（对齐 t1）：成本模型 `dim²·bits²·3e-7`；首次尝试硬上限 `_FIRST_BUDGET=1e9`（≈300s），
  增量重试 `_RETRY_BUDGET=1e7`；1024-bit 实测 fail-fast「预估 696s 超上限，请用 sage/fpylll」。
- **能力边界（诚实标注）**：纯 Python 路径实用到 N ≈ 256-bit（m=4 数分钟）；更大 N 需 sage/fpylll。
  δ 的有限 m 失败概率：128-bit δ=0.26 m=3 可成可败；δ=0.24 m=3 实测 3/3 稳定。
